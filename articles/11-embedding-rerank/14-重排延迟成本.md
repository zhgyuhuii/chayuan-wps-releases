# 重排模型的延迟成本 是否值得每次都跑

chayuan-desktop 桌面单机版的重排有延迟成本。是否每次都跑值得讨论。这一篇讲。

## 重排的延迟

bce-reranker-base-onnx 在 CPU 上 50 候选 rerank 约 500-800ms。

GPU 上约 150-200ms。

每次检索加这一段时间。

## 用户体验影响

实时聊天场景。用户问 → 检索 → LLM 流式回答。

不开重排。检索 50ms，LLM 首字 500ms。总 TTFT 约 0.55 秒。

开重排。检索 50ms + 重排 500ms，LLM 首字 500ms。总 TTFT 约 1.05 秒。

差 0.5 秒。某些用户感知明显。

## 重排带来的精度提升

实测。固定查询集 100 题。

不开重排。top 5 准确率 78%。

开重排。top 5 准确率 92%。

差 14%。明显提升。

## 是否每次都跑

策略一：永远开（chayuan-desktop 默认）。

精度优先。延迟用户能接受 1 秒内。

策略二：永远关。

延迟优先。适合实时场景。

策略三：智能。

简单查询（关键词检索）不开重排（够用）。

复杂查询（自然语言问答）开重排。

策略四：用户开关。

让用户在 UI 上随时切换。

chayuan-desktop 默认策略一。设置里能切换。

## 自适应阈值

某些情况召回 score 已经很高（top 5 都 > 0.9 相似度）。说明召回已经准。重排意义不大。chayuan-desktop 跳过重排省时间。

某些情况召回 score 低（top 5 都 < 0.5）。说明召回不准。重排能救一下。开重排。

```python
if max(recall_scores) > 0.9:
    skip_rerank = True  # 召回已经准
elif max(recall_scores) < 0.4:
    skip_rerank = True  # 召回都不准重排也救不了
else:
    skip_rerank = False
```

## 重排候选数

候选越多重排越慢。

50 候选 → 500ms。

20 候选 → 200ms。

10 候选 → 100ms。

chayuan-desktop 默认 50。能在设置里调小（牺牲少量精度换速度）。

## GPU 加速时的差异

GPU 上重排 50 候选 150ms。比 CPU 快 3 倍。

带 GPU 的用户开重排几乎无感。chayuan-desktop 自动检测 GPU 时把重排默认开 永远开。

## 多 KB 时的重排

混合查询从 5 个 KB 各召回 20，共 100 候选。重排 100 候选 CPU 约 1 秒。

chayuan-desktop 的策略：先按召回 score 截到 top 50，再重排。避免对所有候选重排。

## 重排模型选择

不同重排模型延迟不同。

bce-reranker-base（轻量）。500ms。

bce-reranker-large（更准但更慢）。1500ms。

cross-encoder/ms-marco-MiniLM-L-6-v2（极轻）。150ms。

chayuan-desktop 默认 base。用户能在 large（更准）或 MiniLM（更快）切换。

## 用户感知的隐藏

某些 UI 设计能掩盖延迟。chayuan-desktop 的 流式开始 在重排完成前先发 token（基于召回 top 1）。用户看到字流出。重排完成后调整后续 token。

实际效果有限（重排和 LLM 串行依赖），但对感官有改善。

## 国产化场景

国产硬件（鲲鹏、飞腾）跑 bce-reranker（国产开源）速度跟 Intel 接近。chayuan-desktop 在国产硬件上重排同样可用。

## chayuan-server 的对应

chayuan-server 部署带 GPU 重排几乎免费。chayuan-desktop 单机以 CPU 为主，重排是可观成本。

## WPS 加载项

chayuan-wps 在 WPS 里检索走 chayuan-desktop。重排策略一致。

## 总结

重排模型的延迟成本是 chayuan-desktop 在精度 / 速度权衡上的工程选择。免费开源的AI软件 默认开重排（精度优先）+ 智能跳过 + 用户可关让 检索质量 在工程上有保障也有灵活性。
