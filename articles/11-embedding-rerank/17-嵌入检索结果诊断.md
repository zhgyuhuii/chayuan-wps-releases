# 嵌入与检索结果的诊断 为什么命中的不是这个

chayuan-desktop 桌面单机版的检索诊断面板让用户排查 为什么命中的不是想要的。这一篇讲。

## 用户的困惑

用户问 张三的合同。期望命中 张三 字样的合同 chunk。但实际命中 王五 的合同。

困惑。为什么？

需要诊断工具。

## chayuan-desktop 诊断面板

设置 - 调试 - 检索诊断。开启后每次检索都记录详细信息。

每次检索面板展示。

```
查询：张三的合同

候选 chunk（按召回 score 排）：
  #1: ... 王五的合同条款 ... (score: 0.87)
  #2: ... 张三与公司签订 ... (score: 0.82)
  #3: ... 张三的劳动合同 ... (score: 0.78)
  ...

重排后（按 reranker score 排）：
  #1: ... 张三的劳动合同 ... (score: 0.95)
  #2: ... 张三与公司签订 ... (score: 0.88)
  #3: ... 王五的合同条款 ... (score: 0.45)
```

让用户看到原始 score 和重排 score 的差异。

## 召回准但重排不准

某些场景召回 top 1 是想要的，重排把它排到第 2-3。说明重排模型在该 query 上不准。

诊断显示 召回 vs 重排 的差异。让用户判断是否关闭重排。

## 召回不准

某些场景 query 里关键词在 chunk 里完全没有相似词，但 chunk 因为其他词匹配而 score 高。

比如 query 是 张三，chunk 是 关于法人代表的内容。chunk 里 法人代表 跟 张三 的语义相关（张三是法人），bge-m3 嵌入接近，召回 score 高。但用户可能不是想要这个。

诊断让用户看到 哪些词导致命中。chayuan-desktop 用 attention rollout 高亮 chunk 里跟 query 最相关的部分。

## 词频导致的偏差

某些 chunk 提到 张三 10 次，某些 chunk 只提 1 次。词频高的 chunk 似乎应该 score 高，但 bge-m3 不直接基于词频，是语义嵌入。

诊断面板显示词频统计便于用户理解。

## 长度归一化的影响

chunk 长度差异。短 chunk（50 字）和长 chunk（500 字）相似度算法略有不同。

bge-m3 用 mean pooling。chunk 越长，每个 token 贡献越小。可能短 chunk 反而 score 高。

诊断面板提示 候选 chunk 长度差异。让用户知道这个因素。

## 多 KB 的诊断

跨 KB 检索时显示每个 KB 的召回情况。

```
office:zhangsan:contracts: top 3
  - chunk_a (0.92)
  - chunk_b (0.85)
  - chunk_c (0.81)
doc:legal_templates: top 3
  - chunk_x (0.78)
  - chunk_y (0.75)
  - chunk_z (0.72)
```

让用户看哪个 KB 命中。

## 路由诊断

某些 query 走结构化（text2sql）而非文档 RAG。诊断显示。

```
路由决策：structured_aggregate (置信 0.85)
理由：query 含 "几个"、"多少" 等聚合词
```

让用户判断路由是否正确。错了能手动走文档 RAG。

## chunk 详细信息

诊断面板能展开每个 chunk 详情。

完整文本。

embedding 向量预览（前 10 维）。

metadata（KB、tags、page、章节等）。

历史命中次数。

## 诊断的导出

诊断信息能导出 JSON。便于发给开发者排查。

某些 用户报 检索不准 的问题，开发者拿诊断 JSON 能精准复现。

## 国产化场景

党政军用户对 答非所问 敏感。chayuan-desktop 的诊断让用户能 自己排查 而不必每次找 IT。等保和审计场景下诊断信息也是合规材料。

## chayuan-server 的对应

chayuan-server 模式下诊断更详细（多用户聚合数据）。chayuan-desktop 单机版基础够用。

## WPS 加载项

chayuan-wps 在 WPS 里发起检索如果用户怀疑 检索不准，能在 WPS 侧栏点 诊断 看 chayuan-desktop 的详情。

## 总结

嵌入与检索结果的诊断是 chayuan-desktop 在 RAG 透明度上的工程支持。免费开源的AI软件 不让检索是黑盒。chayuan-desktop 的诊断面板 + 召回 vs 重排对比 + chunk 详情让 排查 检索问题 是看面板就能定位的事。
