# 嵌入计算的批处理 系统资源利用率

chayuan-desktop 桌面单机版的嵌入批处理优化系统资源利用率。这一篇讲。

## 单次嵌入的开销

每次嵌入有固定开销。

模型加载（已加载就 0）。

输入 tokenize。

模型 forward。

输出 pooling 和归一化。

固定开销约 10-20ms。

## 批处理的优势

8 个文本一起嵌入。固定开销摊薄。

```
单个嵌入：50ms × 8 = 400ms
批 8 嵌入：120ms（每个 15ms）
```

3 倍加速。

## 批大小的取舍

批太小（1-4）：开销摊不开。

批太大（128+）：吃内存可能 OOM。

中等（16-32）：性价比最高。

chayuan-desktop 默认批 32（建索引时）。

## 检索时的批大小

检索时一般单 query 嵌入。批 = 1。

某些场景多 query 同时（比如 query expansion 把 query 分成几个子 query）。批小（2-4）也行。

## 建索引时的并行

10000 chunk 建索引。

按批 32 切分。312 批。

CPU 单线程跑。每批 120ms。总 37 秒。

CPU 多线程能再加速 2-3 倍。chayuan-desktop 用 OpenMP 自动多线程。

GPU 跑批 32 约 80ms。总 25 秒。

CPU 多线程跟 GPU 速度接近（小批量场景）。

## 内存占用

批越大显存或 RAM 占用越大。

bge-m3 单次 256 token。约 500MB 显存。

批 32：约 600MB（内核共享）。

批 128：约 900MB。

批太大时 chayuan-desktop OOM 自动降批。

## 异步建索引

某些场景建索引不能阻塞用户交互。chayuan-desktop 把建索引放后台。

```python
async def build_index_async(kb_id):
    chunks = load_chunks(kb_id)
    for batch in batch_iter(chunks, size=32):
        embeddings = embed_batch(batch)
        save_to_vec_db(batch, embeddings)
        update_progress()
```

UI 显示进度条，不阻塞用户聊天。

## 调度策略

后台建索引和前台聊天共享 CPU/GPU。chayuan-desktop 调度。

策略一：低优先级。建索引线程优先级低，聊天来了让 CPU。

策略二：限速。建索引每秒最多嵌入 N 个 chunk，给聊天留空间。

策略三：检测空闲。用户没操作时全速建索引。用户开始聊天时降速。

chayuan-desktop 默认策略三（检测空闲）。

## 增量更新的批处理

KB 增量加新 chunk（folder-sync 监听到新文件）。可能一次只加 5-10 chunk。

5-10 chunk 的批不够大效率不高。chayuan-desktop 累积一段时间（30 秒）合并多次增量到一批。

延迟 30 秒入库。可接受。

## 失败的批回滚

批中某个 chunk 嵌入失败。chayuan-desktop。

策略一：跳过失败的，其他成功的入库。

策略二：整批失败，下次重试。

chayuan-desktop 用策略一。失败 chunk 标记。

## 批的可观测

监控面板显示。

批处理速度：tokens/s 或 chunks/s。

平均批大小。

最近 1 小时建索引进度。

## 国产化场景

国产 CPU（鲲鹏、飞腾）跑批处理同样有效。多核优势让批处理效率高。chayuan-desktop 在国产 CPU 上 batch=32 是最优默认。

## chayuan-server 的对应

chayuan-server 多用户场景下批处理更激进（batch=128 在 GPU 上）。chayuan-desktop 单机批小一些。

## WPS 加载项

chayuan-wps 在 WPS 里建库或追加文档调 chayuan-desktop。批处理对 WPS 透明。

## 总结

嵌入计算的批处理是 chayuan-desktop 在系统资源利用率上的工程优化。免费开源的AI软件 让 建索引快 不浪费 CPU/GPU。chayuan-desktop 的 批 32 默认 + 异步建索引 + 调度策略让 大量嵌入计算 在工程上高效。
