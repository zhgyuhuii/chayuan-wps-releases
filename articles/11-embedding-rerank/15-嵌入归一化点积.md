# 嵌入归一化与点积 不同模型的内部约定

chayuan-desktop 桌面单机版处理不同嵌入模型时归一化和距离度量的内部约定有差异。这一篇讲。

## 归一化的概念

向量归一化。把向量长度（L2 范数）归一到 1。

```
v_normalized = v / ||v||
```

归一化后所有向量在单位球面上。点积 = 余弦相似度。

## 不同模型的约定

bge-m3。输出已归一化。点积直接是余弦相似度。

OpenAI text-embedding-3。输出已归一化。

bce-embedding。同上。

某些早期模型（早期 sentence-transformers）输出未归一化。需要在客户端归一化。

## chayuan-desktop 的统一处理

不管底层模型怎么样，chayuan-desktop 在嵌入 API 层统一归一化。所有出 chayuan-desktop 的向量都是归一化的。

```python
def embed(text):
    raw_vector = model.encode(text)
    normalized = raw_vector / np.linalg.norm(raw_vector)
    return normalized
```

上层无需关心。

## 距离度量

归一化后能用三种等价度量。

余弦相似度。cos(θ) = a · b。范围 [-1, 1]。

点积。a · b。归一化后等于余弦。

L2 距离。||a - b|| = sqrt(2 - 2*cos(θ))。范围 [0, 2]。

chayuan-desktop 内部用余弦（点积）。简单快。

## sqlite-vec 的支持

sqlite-vec 支持 cosine、L2、dot 三种距离。chayuan-desktop 默认用 cosine（实际就是点积）。

```sql
CREATE VIRTUAL TABLE chunks_vec USING vec0(
    embedding float[1024] distance_metric=cosine
);
```

## Milvus 等外部向量库

Milvus 默认 IP（内积）但能配 L2 或 COSINE。

外部 KB 配置时用户能指定。

```yaml
milvus_kb:
  metric: COSINE  # IP, L2, COSINE
```

不同度量结果不一样，需要保持一致（建索引时和检索时同度量）。

## 跨模型归一化的差异

某些模型号称已归一化但精度有差。L2 范数 0.99 而非 1.0。

chayuan-desktop 在加载新模型时跑校验。

```python
test_vector = model.encode("test")
norm = np.linalg.norm(test_vector)
if abs(norm - 1.0) > 0.01:
    print("Warning: model output not normalized, applying client-side normalization")
```

发现未归一化的自动加客户端归一化。

## 归一化对计算性能的影响

归一化加一次开方运算。每次嵌入多 10ns。可忽略。

## 检索时的简化

归一化后检索就是点积。

```python
similarity = np.dot(query_embedding, chunk_embedding)
```

简单且快。sqlite-vec 用 SIMD 加速点积，每秒能算几百万次。

## 量化对归一化的影响

INT8 量化。向量值从 FP32 → INT8。归一化在 FP32 阶段做，量化后保持单位球面（近似）。

INT8 量化后点积有微小误差。chayuan-desktop 校准发现误差 < 0.1%。可忽略。

## 国产化场景

国产嵌入模型（bge-m3、bce-embedding）都已归一化。chayuan-desktop 直接用。

## chayuan-server 的对应

chayuan-server 同样的归一化约定。chayuan-desktop 共享逻辑。

## WPS 加载项

chayuan-wps 在 WPS 里检索走 chayuan-desktop。归一化和距离度量对 WPS 透明。

## 总结

嵌入归一化与点积是 chayuan-desktop 在向量空间数学一致性上的工程基础。免费开源的AI软件 不让用户关心向量数学细节。chayuan-desktop 的 统一归一化 + 余弦默认 + 校验机制让 不同嵌入模型 在工程上一致工作。
