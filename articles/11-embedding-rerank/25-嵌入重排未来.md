# 嵌入与重排的未来 长上下文模型会让它消失吗

chayuan-desktop 桌面单机版当前依赖嵌入和重排做 RAG。但 LLM 的上下文长度在快速增长。这一篇讨论嵌入和重排的未来。

## 长上下文模型的崛起

Claude 3.5 Sonnet。200k 上下文。

Gemini 1.5 Pro。1M 上下文（实验性 2M）。

Qwen2.5-72B-Instruct-1M。1M 上下文。

Qwen-Long。10M 上下文（实验性）。

理论上把所有相关文档塞进 prompt。LLM 直接基于全文回答。不需要 RAG。

## 长上下文 vs RAG 的现实

理论上长上下文能替代 RAG。实际中。

代价一：成本。Claude 200k 上下文每次调用比 4k 贵 50 倍。普通查询不值。

代价二：延迟。1M 上下文的 prompt 处理时间 30-60 秒。用户等不及。

代价三：注意力衰减。LLM 在长上下文中对 中间内容 的注意力下降（lost in the middle 现象）。检索精度反而不如 RAG。

代价四：长上下文 LLM 的训练数据有限。RAG 的精确检索 + 短上下文 LLM 在多数任务上仍是最佳。

## RAG 仍重要的原因

原因一：成本可控。RAG 命中相关 chunk 后只把这部分塞进 prompt。token 数量级降低。

原因二：增量更新。新加文档只需嵌入一份。LLM 长上下文每次都要重读。

原因三：可追溯。RAG 的引用气泡指向具体 chunk。长上下文模型回答没明确出处。

原因四：私有数据。本地 RAG 数据不出端。长上下文如果用云模型数据上云。

## 嵌入和重排的演进方向

方向一：更准的嵌入。bge-m3 之后的下一代嵌入模型在多语种、长文本、领域专精上提升。chayuan-desktop 跟进。

方向二：长 chunk 嵌入。bge-m3 上下文 8192。某些场景能直接嵌入整个章节。chunk 越大嵌入越稳定。chayuan-desktop 路线图支持长 chunk。

方向三：多模态嵌入。文本 + 图像 + 表格统一向量空间。当前 CLIP / Qwen-VL-Embed 在做。chayuan-desktop 路线图。

方向四：层次化嵌入。先嵌入文档级（粗粒度），再 chunk 级（细粒度）。检索时先粗后细。chayuan-desktop 路线图。

## 重排的演进

方向一：更轻的重排模型。bge-reranker-v2-m3 比 v1 快很多精度差不多。chayuan-desktop 跟进。

方向二：LLM as reranker。用 LLM 当重排模型（Claude 等大模型）。精度更好但成本高。chayuan-desktop 给重要查询用 LLM rerank 选项。

方向三：交互式 rerank。用户的反馈（点了哪个引用）反馈给重排模型。学习用户偏好。chayuan-desktop 路线图。

## 混合策略的演进

混合一：RAG + 长上下文。先 RAG 找相关 50 个 chunk 拼成 50k 上下文，长上下文 LLM 回答。比纯长上下文便宜，比纯 RAG 上下文丰富。chayuan-desktop 当前部分支持。

混合二：分层处理。简单查询走 RAG（成本低）。复杂查询走 RAG + 长上下文（精度高）。chayuan-desktop 的路由能做这个判断。

混合三：检索 + 反思。LLM 第一次回答后检查 是否引用足够。不够再检索。多轮检索。

## 嵌入和重排会消失吗

短期（1-2 年）。不会。RAG 仍是主流。

中期（3-5 年）。可能弱化。某些场景用长上下文替代。但嵌入和重排在 高效检索 上仍重要。

长期（5+ 年）。难说。AI 范式可能根本变化。

但 chayuan-desktop 的设计要为短中期做好。同时为长期准备。

## chayuan-desktop 的策略

策略一：保持 RAG 作为核心。所有检索、引用、知识库都基于 RAG。

策略二：长上下文模型接入。用户能选 1M 上下文模型。chayuan-desktop 让 prompt 容量自动适应。

策略三：嵌入和重排持续升级。跟进开源最佳。

策略四：路由智能化。判断哪些查询适合 RAG，哪些适合长上下文，哪些混合。

## 国产化场景

国产 LLM 也在追长上下文（Qwen2.5-1M）。chayuan-desktop 接入国产长上下文模型。但 RAG 在 数据本地化 上仍是必选。

## chayuan-server 的对应

chayuan-server 模式下长上下文模型成本能多用户分摊。chayuan-desktop 单机用户单独承担成本。混合策略对 chayuan-desktop 更重要。

## WPS 加载项

chayuan-wps 在 WPS 里使用 RAG 检索加引用。员工写报告时引用具体来源仍需要 RAG。长上下文不能替代引用气泡。

## 总结

嵌入与重排的未来是 chayuan-desktop 在 RAG 长期演进上的判断。免费开源的AI软件 既要跟进长上下文模型，又要保持 RAG 的核心价值。chayuan-desktop 的混合策略让 当前 RAG 优势 + 未来长上下文 兼容并蓄。RAG 短中期不会消失。
