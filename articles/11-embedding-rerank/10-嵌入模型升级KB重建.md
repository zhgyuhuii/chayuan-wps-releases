# 嵌入模型升级时的 KB 重建

chayuan-desktop 桌面单机版升级嵌入模型时已有 KB 需要重建索引。这一篇讲流程。

## 为什么必须重建

不同嵌入模型生成的向量不可比较。bge-m3 的向量和 m3e 的向量在数学上是不同空间。

升级嵌入模型后旧 KB 的向量不能用新模型的查询向量比对。检索失效。

只能重建。

## 升级的常见情况

情况一：版本升级。bge-m3 v1.0 → v1.5。维度可能不变（仍是 1024）但权重不同。

情况二：模型替换。bge-m3 → bce-embedding。维度可能不同（768 vs 1024）。

情况三：维度升级。bge-m3-1024 → bge-m4-2048。更高维度更多信息。

每种都需要重建。

## 重建的流程

第一步。chayuan-desktop 提示用户 检测到嵌入模型可升级。是否升级并重建索引。让用户决策。

第二步。用户确认。chayuan-desktop 备份当前 KB 索引（避免重建失败丢数据）。

第三步。下载新模型权重。验证完整性。

第四步。遍历所有 chunk。

```python
for chunk in all_chunks:
    new_embedding = new_model.encode(chunk.text)
    chunk.embedding = new_embedding
    save(chunk)
```

第五步。重建 sqlite-vec 索引（删除旧索引，重建立索引）。

第六步。验证。跑几个测试查询确认检索正常。

第七步。删除备份（用户确认后）或保留备份。

## 重建的代价

时间。1 万 chunk CPU 重嵌入约 5-10 分钟（256 token / chunk，bge-m3）。GPU 几十秒。

10 万 chunk 几小时（CPU）。

100 万 chunk 一天（CPU）。GPU 几小时。

家用单机一般几万 chunk，重建时间 几分钟到 1 小时。可接受。

## 增量升级

某些场景能跳过重建。

如果只是版本升级（模型权重微调，向量空间近似），chayuan-desktop 提示用户 可跳过重建，新旧向量混合检索精度可能略降。让用户选择。

绝大多数情况建议重建。

## 多 KB 的批量

用户有 5 个 KB 都用 bge-m3 v1。统一升级到 v1.5。chayuan-desktop 一次性给所有 KB 重建。

```
重建队列：
  KB 1: 已完成
  KB 2: 进行中 60%
  KB 3: 等待
  ...
```

进度条让用户看到进展。

## 重建期间的可用性

重建 KB A 时该 KB 不可检索。chayuan-desktop UI 提示 KB A 正在升级，临时不可用。

其他 KB 不受影响。

## 失败回滚

重建失败（OOM、磁盘满、模型损坏）。chayuan-desktop 自动回滚到备份。用户的 KB 不受影响。

只是升级失败需要重试或换方案。

## 版本管理

每个 KB 记录使用的嵌入模型版本。

```
{
  "kb_id": "office:zhangsan:meetings",
  "embedding_model": "bge-m3-onnx",
  "embedding_version": "v1.5",
  "embedding_dim": 1024,
  "indexed_at": "2026-05-10"
}
```

跨 KB 检索时检查版本一致性，不一致提示用户。

## 部门统一升级

多员工同一部门的 KB 应该升级到同一版本（参考前面 office 系列文章）。chayuan-desktop 没法自动协调多人升级。但提示 部门管理员协调统一。

某些场景部门部署 chayuan-server，集中升级所有员工 KB。

## 国产化场景

党政军单位嵌入模型升级谨慎。chayuan-desktop 的 提示 + 备份 + 回滚 让升级安全。

某些等保场景升级前要走变更管理流程。chayuan-desktop 的升级提示能输出变更说明文档（自动生成）便于流程审批。

## chayuan-server 的对应

chayuan-server 多用户场景下升级是企业级动作（管理员决策）。chayuan-desktop 单机版用户决策。

## WPS 加载项

chayuan-wps 在 WPS 里挑 KB 时如果某 KB 在升级，UI 提示。员工换其他 KB 用。

## 总结

嵌入模型升级时的 KB 重建是 chayuan-desktop 在长期演进上的工程关键。免费开源的AI软件 不锁定旧模型，让用户能跟上模型升级。chayuan-desktop 的 提示 + 备份 + 重建 + 回滚 流程让升级安全可控。
