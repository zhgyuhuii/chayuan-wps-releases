# 多语种嵌入 中英日韩共存的精度

chayuan-desktop 桌面单机版的嵌入需要处理中英日韩等多语种共存场景。这一篇讲精度。

## 多语种场景

场景一。技术文档中英混合（中文段落 + 英文 API 文档）。

场景二。会议纪要中英混合（中方说中文，外方说英文，主持人翻译）。

场景三。论文中英文摘要 + 主体不同语言。

场景四。日韩用户的多语种 KB。

## bge-m3 的多语种能力

bge-m3-onnx 默认支持。

中文。强（训练以中文为主）。

英文。强。

日语。中等（训练数据少但能用）。

韩语。中等。

阿拉伯、俄语等小语种。一般（不推荐重度使用）。

## 中英混合的精度

实测。中英混合段落用 bge-m3 嵌入查询。

中文 query 检索中文 chunk。准。

英文 query 检索英文 chunk。准。

中文 query 检索英文 chunk（跨语种）。次准（约低 10-20%）。

英文 query 检索中文 chunk。同上。

bge-m3 是多语种统一空间，跨语种检索能用但精度有损。

## 跨语种检索的优化

策略一：query 翻译。中文 query 用本地小模型翻译成英文，两次嵌入查询，结果合并。提高跨语种精度。代价是多一次嵌入。

策略二：chunk 翻译。建库时把英文 chunk 加上中文翻译版本（或反之）。每个 chunk 双语 chunk 都嵌入。代价是存储翻倍。

策略三：用专门双语模型。比如 BAAI/bge-m3 已经是多语种。某些场景换 multilingual-e5-large 等。

chayuan-desktop 默认策略一（query 双向翻译）。可在设置里关闭。

## 文档语言识别

入库前 chayuan-desktop 自动识别文档语言。每个 chunk 标 language 字段。

```
{
  "text": "...",
  "language": "zh"  // zh / en / ja / ko / mixed
}
```

检索时如果 query 是中文，过滤优先 language=zh 的 chunk。其次 mixed。最后跨语种。

## 中文专项强化

某些政企场景几乎只有中文。chayuan-desktop 设置里能开 中文专项 模式。

启用后用 bce-embedding-base-zh 等专门中文模型替代 bge-m3。在中文场景上略胜（大概 +5% 精度）。

代价是失去多语种能力。

## 日韩场景

日韩用户用 chayuan-desktop。bge-m3 的支持中等。

如果日韩内容多，建议换 multilingual-e5-large（更多日韩训练数据）。

chayuan-desktop 模型市场提供这种切换。

## 小语种

阿拉伯、土耳其、印地语等小语种 bge-m3 支持有限。chayuan-desktop 当前不专门优化。

如果有大量小语种内容建议用商业 OpenAI text-embedding-3 或 Cohere multilingual。但这违反离线原则。

## chunk 内的多语种混合

某些 chunk 本身是中英混合（一段中文里嵌几个英文术语）。bge-m3 能处理，效果接近中文 chunk。

## 重排的多语种支持

bce-reranker 中英文都支持。日韩稍弱。

如果日韩内容重要换 BAAI/bge-reranker-v2-m3 等。chayuan-desktop 模型市场可选。

## 国产化场景

党政军大多中文为主，少量英文。bge-m3 默认即可。

某些外事单位涉及多语种。chayuan-desktop 提示用户启用 跨语种翻译策略。

## chayuan-server 的对应

chayuan-server 多用户场景下可能不同用户有不同语种偏好。chayuan-desktop 单机版用户级配置。

## WPS 加载项

chayuan-wps 在 WPS 里检索多语种。员工写英文邮件时检索英文 chunk，写中文报告时检索中文 chunk。chayuan-desktop 自动识别 query 语言路由。

## 总结

多语种嵌入是 chayuan-desktop 在国际化场景的工程能力。免费开源的AI软件 让中英日韩等共存文档能统一检索。chayuan-desktop 的 bge-m3 默认 + 跨语种翻译 + 中文强化让 多语种 RAG 在桌面上落地。
