# 嵌入模型对短文本的劣势 补丁策略

chayuan-desktop 桌面单机版的嵌入模型对短文本（< 30 字）效果一般。这一篇讲补丁策略。

## 短文本的问题

bge-m3 等通用嵌入模型在长文本（200+ token）训练。短文本场景。

短查询。比如 张三 这两个字。

短 chunk。比如 标题、列表项、表格单元格。

短文本嵌入向量信息量少，区分度差。

## 实测精度

测试。100 条短查询（< 5 字）。

bge-m3 召回 top 5：精度 65%。

bge-m3 同长查询（10-20 字）：精度 85%。

短文本明显差。

## 补丁策略一：query expansion

把短 query 扩展成更长。让 LLM 帮助。

```
原 query: 张三
扩展: 关于张三的所有信息。张三的电话、地址、合同、会议参与情况等。
```

扩展后 query 嵌入更稳定。检索精度提升。

chayuan-desktop 设置里能开 自动 query expansion。开后短 query 自动扩展。

代价。多一次 LLM 调用，延迟加 0.5-1 秒。

## 补丁策略二：拼接上下文

短 chunk 的嵌入精度也差。chayuan-desktop 在嵌入前拼接上下文。

```
原 chunk: 表格行 "张三 财务 2020-01-15"
拼接后: 员工档案表的一行: 张三 财务 2020-01-15
```

加上 表格类型 标识让短 chunk 更有上下文。

chayuan-desktop 的切分策略中默认对短 chunk（< 50 token）拼章节标题或文档标题。

## 补丁策略三：BM25 协同

短文本 BM25 检索（基于关键词词频）有时比向量好。

chayuan-desktop 同时跑两路。

向量检索 top 50。

BM25 检索 top 50。

合并去重。重排打分。

短查询时 BM25 通常贡献关键命中。chayuan-desktop 自动启用混合检索。

## 补丁策略四：keyword boost

某些场景 query 含明确关键词（人名、产品名）。chayuan-desktop 检测后给含该关键词的 chunk 加分。

```python
if query == "张三":
    for chunk in candidates:
        if "张三" in chunk.text:
            chunk.score += 0.1
```

不重新嵌入，只调分。简单有效。

## 补丁策略五：实体识别

chayuan-desktop 用本地 NER 模型（轻量 BERT）识别 query 里的实体。

```
query: "张三的合同"
entities: PERSON=张三
```

把实体作为元数据过滤条件。chunk 的 metadata 含实体提取结果（建库时跑 NER）。

```
检索：query=合同 + entity_filter=PERSON=张三
```

只在 chunk 的 entities 字段含 张三 的范围内做向量检索。精度大幅提升。

## 补丁策略六：标题/锚点专门索引

短文本如标题和锚点。chayuan-desktop 单独建一个 标题索引。

文档的 H1/H2/H3 标题以及其他短关键短语单独索引。

检索短 query 时优先查标题索引。

```
query: "数据迁移"
title_search → 命中 "第 3 章 数据迁移方案"
```

直接命中标题让定位精准。

## 补丁策略七：长文本 hint

某些短查询本身有歧义。chayuan-desktop 提示用户提供更多上下文。

```
查询：张三

[搜索结果寥寥]

提示：查询过短，请提供更多上下文，例如 "张三的合同" 或 "张三 2024 年会议"
```

引导用户写更具体的查询。

## 自动启用补丁

chayuan-desktop 自动判断启用哪些补丁。

query 长度 < 5 token：启用 query expansion + BM25 协同 + keyword boost。

query 含人名 / 产品名：启用 entity filter。

query 命中标题词：启用标题索引。

用户能在设置里调整每个补丁的开关。

## 国产化场景

中文短查询（人名、机构名、产品名）多。chayuan-desktop 的补丁策略对中文场景更有效。

## chayuan-server 的对应

chayuan-server 模式下补丁策略相同。chayuan-desktop 单机版本地跑。

## WPS 加载项

chayuan-wps 在 WPS 里检索时 chayuan-desktop 自动应用补丁。WPS 用户感知就是 短查询也能找到结果。

## 总结

嵌入模型对短文本的劣势补丁是 chayuan-desktop 在 RAG 完整性上的工程修补。免费开源的AI软件 不让 短查询找不到 这种基础问题暴露给用户。chayuan-desktop 的多种补丁策略让 短文本检索 在工程上达到长文本的精度。
