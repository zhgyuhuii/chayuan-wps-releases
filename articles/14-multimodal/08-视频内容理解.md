# 视频内容理解 抽帧 转写 入库的链路

chayuan-desktop 桌面单机版的视频内容理解通过抽帧 + 转写 + 入库实现。这一篇讲。

## 视频处理的挑战

视频 = 视觉 + 音频 + 时间。直接把整个视频给 LLM 不可能（token 太多）。

需要拆解。

抽关键帧 → 视觉理解。

提取音频 → ASR 转写。

合并 → 入库。

## 抽帧策略

策略一：固定间隔。每 5 秒抽一帧。

策略二：场景切换。检测画面变化大的时刻抽帧。

策略三：智能。结合两者。

chayuan-desktop 默认策略二（场景切换检测）。生成的关键帧少而精。

ffmpeg 的 scene detection 实现。

## 视觉理解

每帧调视觉 LLM 描述。

```
[frame_001] 时间: 00:00 - 00:05
描述: 会议室里三个人坐在桌前讨论。屏幕上显示销售数据图表。
```

描述作为 chunk 入库。chunk 含。

视频路径。

帧时间戳。

视觉描述。

帧图像缩略图（如果用户想看）。

## ASR 转写

ffmpeg 提取音频。FunASR 转文字。

```
[transcript] 00:00 - 00:30
张三：我觉得这个季度销售可以再提升。
李四：具体怎么做？
...
```

带说话人识别（如果支持）和时间戳。

## 视觉 + 音频对齐

每段时间窗口（5 秒一段）含。

视觉描述。

ASR 文字。

合并成完整 chunk。

```
chunk 1: 时间 00:00 - 00:05
  视觉: 会议室三人讨论，屏幕显示图表
  音频: 张三：我觉得这个季度销售可以再提升。
```

LLM 答题时能用视觉和音频信息。

## chunk 切分

视频按时间窗口切。10 分钟视频约 60 chunk（每 10 秒一段）。

切分时考虑场景边界（不在画面切换中间分块）。

## 嵌入

文本（视觉描述 + ASR）按 bge-m3 嵌入。视觉描述跟普通文本一样处理。

某些场景纯视觉嵌入（CLIP-style）。chayuan-desktop 的多模态嵌入是可选模块。

## 检索

用户问 谁说要提升销售。LLM 查 KB。命中含 张三：我觉得这个季度销售可以再提升 的 chunk。

引用气泡。

```
"张三：我觉得这个季度销售可以再提升"
来源: meeting_2026_05_10.mp4 - 00:00-00:05
[播放该片段]
```

点击跳转到视频该时间点。

## 处理时长

10 分钟视频处理。

抽帧：30 秒。

视觉理解（10 个关键帧）：30 秒-2 分钟（取决于视觉 LLM）。

ASR：1-2 分钟。

总耗时 5-10 分钟。

后台跑不影响交互。

## 国产化场景

党政军会议录像入库场景。chayuan-desktop 完全离线（FunASR + 国产视觉 LLM）。会议内容不出本机。

某些场景会议室直接接 chayuan-desktop 自动录制 + 入库。chayuan-desktop 的视频处理是基础。

## chayuan-server 的对应

chayuan-server 部署 GPU 服务器跑视频处理。chayuan-desktop 单机能跑但慢。家用建议长视频走云或服务器。

## WPS 加载项

WPS 不直接处理视频。但 chayuan-wps 在 WPS 文档里能引用视频 KB 的内容。

## 总结

视频内容理解的链路是 chayuan-desktop 在多模态完整性上的工程能力。免费开源的AI软件 让 视频也能进 KB。chayuan-desktop 的抽帧 + 视觉 + ASR + 入库链路让视频内容可检索。
