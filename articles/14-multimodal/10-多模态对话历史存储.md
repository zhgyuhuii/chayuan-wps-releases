# 多模态对话历史的存储 文件指纹与小图缓存

chayuan-desktop 桌面单机版的多模态对话历史存储有特殊机制。这一篇讲。

## 多媒体存储的挑战

挑战一：体积大。一次会话含多张图、几个视频可能几百 MB。100 次会话几十 GB。

挑战二：去重。同一张图被多次引用。每次都存浪费。

挑战三：聊天导出。导出聊天历史时多媒体怎么处理。

挑战四：长期保留。1 年前的聊天还能看图吗。

## 文件指纹

每个多媒体文件计算 SHA256 哈希作为指纹。

```
img_abc123.jpg → SHA256: 89af...
img_xyz789.jpg → SHA256: 89af...  # 跟上面同一文件
```

哈希相同的文件存一份。多个会话引用同一指纹。

去重。

## 存储路径

```
~/.chayuan/media/
  ab/89af...8d23.jpg  # 按哈希前缀分目录
  ce/cefa...4567.mp4
```

避免单目录文件过多（影响文件系统）。

## 引用结构

聊天消息里的图像引用是哈希。

```
{
  "role": "user",
  "content": [
    {"type": "text", "text": "这图什么意思"},
    {"type": "image", "ref": "media:89af...8d23"}
  ]
}
```

UI 渲染时按哈希查实际文件。

## 缩略图缓存

每个原图生成缩略图（200x200）。同样按哈希存。

```
~/.chayuan/thumbnails/
  ab/89af...8d23_thumb.jpg
```

聊天历史里大量图时只加载缩略图，原图按需加载。

## 视频的处理

视频存原文件。

抽 5-10 帧作为关键帧缩略图存（同样按哈希）。

视频引用时显示关键帧轮播 + 播放按钮。

## 音频的处理

音频存原文件。

不生成缩略图（音频不需要）。

引用时显示波形图（动态生成）。

## 长期保留

默认所有多媒体永久保留。

设置里能配自动清理。

```yaml
media_retention:
  unused_after_days: 90  # 90 天没被引用清理
  total_size_cap_gb: 50  # 总大小超 50GB 清理最老的
```

## 备份

多媒体跟主聊天数据库分开存。备份策略可独立。

```
chayuan-desktop 设置 - 备份：
  聊天数据库：每天自动
  多媒体：每周自动（量大）
```

## 导出

聊天导出 PDF / docx 时多媒体内嵌或打包。

PDF：图像直接嵌入 PDF。视频 / 音频用占位符 + 链接。

docx：同上。

打包 zip 含完整多媒体。

## 共享

用户分享某段聊天给同事。chayuan-desktop 生成压缩包。

```
chat_share_2026-05-10.zip
  ├─ chat.json
  └─ media/
      ├─ 89af...8d23.jpg
      └─ ...
```

接收方导入到自己的 chayuan-desktop 能看到完整对话。

## 隐私

多媒体可能含敏感信息（PII、商业机密）。chayuan-desktop 的存储默认加密（AES-256）。

某些场景需要更严的隐私。chayuan-desktop 配置允许 永不上传 标记，强制本地处理。

## 国产化场景

党政军场景多媒体存储符合等保要求。chayuan-desktop 的本地存储 + 加密 + 审计完整覆盖。

## chayuan-server 的对应

chayuan-server 多用户场景下多媒体集中。chayuan-desktop 单机本地。两者协议一致。

## WPS 加载项

chayuan-wps 在 WPS 里引用 chayuan-desktop 的多媒体。WPS 用户感知就是 多媒体能在聊天和文档里流畅引用。

## 总结

多模态对话历史的存储是 chayuan-desktop 在长期数据管理上的工程基础。免费开源的AI软件 让 多媒体不重复、可清理、可导出、可加密。chayuan-desktop 的指纹去重 + 缩略图 + 备份策略让多媒体存储高效。
