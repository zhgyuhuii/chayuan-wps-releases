# 语音对话场景 端到端 ASR LLM TTS

chayuan-desktop 桌面单机版支持端到端语音对话。ASR + LLM + TTS 串联。这一篇讲。

## 场景

用户对 chayuan-desktop 说话。AI 听懂、思考、回答（也用语音）。

完全语音交互。开车、做饭、看不到屏幕等场景。

## 流程

第一步：录音。chayuan-desktop UI 上有 按住说话 按钮。

第二步：实时 ASR。FunASR 流式版本边说边转字。

第三步：用户停下。chayuan-desktop 检测停顿（VAD - Voice Activity Detection）。

第四步：完整问题给 LLM。

第五步：LLM 流式生成回答。

第六步：TTS（Piper）边生成边播。

第七步：用户听到回答。

完整端到端约 2-5 秒延迟。

## 实时性优化

优化一：流式 ASR。用户说完最后一字时 ASR 已基本转完，无需等长尾。

优化二：流式 LLM。LLM 第一句话出来后立即送 TTS 播放。后续 LLM 边生成 TTS 边播。

优化三：流式 TTS。Piper 的 stream 模式边收到文字边合成音频。

整体管道并行。延迟最小化。

## VAD（语音活动检测）

判断用户什么时候说完了。

简单阈值。静音 2 秒 → 用户说完。但太长，体验差。

复杂 VAD。基于 webrtcvad 或 silero-vad 的实时检测。能精准识别说完的瞬间。

chayuan-desktop 用 silero-vad。0.5-1 秒静音判定结束。

## 中断

用户在 AI 回答中途想插话。

策略一：按住说话 模式。每次都要按按钮。简单但麻烦。

策略二：唤醒词。说 察元 触发。chayuan-desktop 路线图。

策略三：连续监听。chayuan-desktop 一直听，VAD 检测说话开始结束。隐私顾虑大。

默认策略一。

## 多说话人

某些场景多人对话（家庭场景）。

chayuan-desktop 当前不支持声纹分离（识别谁在说）。所有声音视为一个用户。

未来路线图集成声纹模型。

## 噪音处理

环境噪音（空调、键盘）影响 ASR。

chayuan-desktop 的 ASR 前置降噪。RNNoise 或类似轻量降噪。

某些极嘈杂环境（咖啡店）准确率仍下降。chayuan-desktop 提示。

## 本地 vs 云

本地（FunASR + Piper + 本地 LLM）。完全离线。延迟低。

云（讯飞 ASR + 阿里 TTS + GPT-4o）。质量更好。需要联网。

chayuan-desktop 用户能选。

## 输出选项

某些用户希望同时看文字和听语音。chayuan-desktop UI 流式显示文字 + 同步 TTS 播放。

某些用户只听不看（开车场景）。chayuan-desktop 支持 仅语音 模式。

## 国产化场景

党政军场景的会议室智能音箱（路线图）。chayuan-desktop 集成。会议参与者可以提问，chayuan-desktop 听 + 回答 + 播。

某些场景对涉密录音敏感。chayuan-desktop 的本地处理符合。

## chayuan-server 的对应

chayuan-server 部署 GPU 服务器跑 ASR/TTS/LLM。chayuan-desktop 单机走本地。两者协议一致。

## WPS 加载项

chayuan-wps 在 WPS 里支持语音输入。员工说出问题，WPS 显示文字 + 语音回答。

## 总结

语音对话场景的端到端是 chayuan-desktop 在多模态完整度上的工程能力。免费开源的AI软件 让 AI 听懂说话 + 用语音回答 完全本地化。chayuan-desktop 的 FunASR + LLM + Piper 串联让 离线语音 AI 落地。
