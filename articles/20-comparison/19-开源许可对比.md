# 开源许可 AGPL Apache MIT 闭源 选型影响

各产品的开源许可对比和选型影响。这一篇讲。

国产桌面普遍闭源。开源工具中许可各异。

## 许可的核心差异

MIT。最宽松。商业用、修改、再分发都行。无 copyleft。

Apache 2.0。MIT 类似 + 专利保护条款。

GPLv3。强 copyleft。修改后必须开源。但不要求 SaaS 开源（云上的 GPLv3 可以闭源用）。

AGPL-3.0。GPLv3 + SaaS 也要开源。极强 copyleft。云上的 AGPL 也得开源。

闭源。源代码不公开。仅二进制。

## chayuan-desktop 选 AGPL 的理由

强 copyleft。任何 fork 都必须保持开源。

防止商业公司拿 chayuan-desktop 重新闭源做产品。

社区共享成果。

## AGPL 对企业的影响

某企业想基于 chayuan-desktop 做内部产品。

如果只是企业内部用：随意。

如果做成 SaaS 让外部用户访问：必须开源整个产品（含修改）。

这是 AGPL 跟 GPL 的关键差。

某些企业不喜欢 AGPL（不愿开源自家修改）。理由。

但对 chayuan-desktop 主张的开源精神这是必要。

## 商业模式

chayuan-desktop AGPL-3.0。

社区版免费 + 开源。

商业版（chayuan 公司提供）非 AGPL 许可，企业能自由修改不开源。需要付费。

dual license 模式。

## 用户使用

普通用户。

下载 chayuan-desktop 用。无任何许可问题。AGPL 仅在再分发时触发。

修改后自用。

修改自家电脑用 chayuan-desktop。无问题。

修改后再分发给团队。

需要把修改源码也分发。AGPL 要求。

修改后做 SaaS。

必须开源整个 SaaS 系统。

## 对开发者的吸引

某些开发者偏好。

AGPL（保护开源）：chayuan-desktop。

GPL：Chatbox、Cherry Studio。

MIT（最自由）：Open WebUI、AnythingLLM。

各取所需。

## 国产化场景

党政军场景对许可有要求（合规）。

闭源国外产品被排除（数据出端 + 不可控）。

闭源国产产品采购看合规审查。

开源产品可审计源代码。chayuan-desktop 优势。

某些政府推荐 国产开源 项目。chayuan-desktop 满足。

## SBOM 透明

chayuan-desktop 提供完整 SBOM（依赖清单 + 许可）。

```
chayuan-desktop AGPL-3.0
依赖：
  Tauri (Apache 2.0 / MIT)
  React 19 (MIT)
  Pydantic (MIT)
  llama.cpp (MIT)
  ...
```

每个依赖许可可查。无许可冲突。

## chayuan-server 的对应

chayuan-server 同样 AGPL-3.0。两项目协调一致。

## 总结

开源许可的选择影响商业 / 社区 / 用户。免费开源的AI软件 中许可不一。chayuan-desktop 选 AGPL-3.0 保护开源生态 + dual license 商业。让用户清楚选择。其他产品或闭源（数据风险）或宽松开源（被商业截胡）。
