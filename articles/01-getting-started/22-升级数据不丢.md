# 升级到下一个版本 察元AI数据怎么不丢 升级日志的看法

察元AI 桌面单机版的版本节奏不算密集，但每次升级总有人担心数据会不会丢。这种担心是正当的，因为单机版所有的对话历史、知识库索引、模型钥匙都在 CHAYUAN_ROOT 里，升级过程一旦有差错，损失是实实在在的。这一篇讲清楚升级机制，给一份升级前后的检查清单。

先看升级的实际流程。chayuan-desktop 升级有两条路。一条是覆盖安装，msi/dmg/deb 直接装新版本，老版本的安装目录被替换，CHAYUAN_ROOT 不动。另一条是先卸载老版本再装新版本，CHAYUAN_ROOT 仍然不动，但安装目录会被清干净再生成。两条路对数据都是安全的，前提是 CHAYUAN_ROOT 跟安装目录是分开的。如果你早期把 CHAYUAN_ROOT 错放进了 Program Files 之类的安装目录，升级时数据会被一并清掉。这是最常见的一条踩坑。

升级前的准备。第一步，关闭 chayuan-desktop，确认 sidecar 进程退出。第二步，备份 CHAYUAN_ROOT 整个目录到外置硬盘或者另一个分区。这一步是底线，万一升级失败可以原地恢复。第三步，记录当前版本号、模型供应商列表、知识库清单。chayuan-desktop 设置的 关于 页有版本号，知识库列表在主界面侧栏可见。

升级中的操作。覆盖安装的话双击新 msi 走完安装。dmg 把新 .app 替换 /Applications 下的老 .app。deb 用 dpkg -i 装新版会自动覆盖。Linux 上偶尔会遇到 dpkg 提示配置文件冲突，按 keep current 保留你自己的配置即可。

升级后的首启动。chayuan-desktop 启动时会跑一次数据迁移检查。机制是用 alembic 这类迁移工具对 CHAYUAN_ROOT/data 下的 SQLite 文件做 schema upgrade。新版本可能加了新表、新列、新索引。迁移过程是非破坏性的，但要花几秒到几十秒不等。看到主界面 splash 转一阵才进主界面，正常。

迁移日志在 CHAYUAN_ROOT/logs/migration.log 里。打开看一眼，找 Running migration、Successfully applied、ERROR 这几个关键词。正常情况下你会看到从老版本到新版本的一系列迁移步骤，每个都成功。

升级后的检查清单。第一，模型供应商列表是否完整，钥匙是否仍然能用。第二，知识库列表是否完整，能否新建对话调用。第三，对话历史是否在，能否打开老对话。第四，挑一个老知识库做一次问答，看引用气泡能否展开。第五，进 chayuan-wps WPS AI 插件 试一句话，确认加载项还能连上桌面单机版后端。

升级失败的几种情况。第一种，sidecar 起不来。看 server.log 里的 alembic 报错。如果是 schema 迁移失败，最稳的办法是把 CHAYUAN_ROOT/data 备份的副本放回去，回滚到老版本继续用，等下一个 patch 修了再升。第二种，启动后界面空白。多是 webview 缓存跟新版本不兼容，删除 chayuan-desktop 的 webview 缓存（Tauri 特定路径），重启即可。第三种，模型钥匙失效。少见，但如果 credentials 模块升级动了密钥派生算法，老钥匙解不开。这种情况官方会在升级日志里明确说明，并提供导出导入工具。

升级日志的看法。每个 release 都有 RELEASE_NOTES_vX.Y.md 文件。看里面三件事：破坏性变更（breaking changes，重要）、数据迁移说明（datamigration，重要）、新功能列表（次要）。前两件直接关系到你的升级风险评估。如果某次发布带破坏性变更，建议先在另一台测试机上试一次，再升主力机。

国产化支持下的升级注意。麒麟 UOS 上更新通道通常走内网镜像，确认新版本 deb 已经入了内部源再升。麒麟 V10 SP1 跟 SP2 之间的 glibc 差异已经被新版 chayuan-desktop 兼容，但建议先看一下 release notes 确认你的子版本是否在支持列表内。

回滚机制。chayuan-desktop 默认不带自动回滚，但因为 CHAYUAN_ROOT 是用户管的，回滚的成本就是装回老版本 msi 加上恢复备份的 CHAYUAN_ROOT。这件事比想象中简单。前提还是那一条：升级前一定要备份。

免费开源的AI软件 的好处之一是版本节奏自己掌握。不喜欢某个版本的变化可以不升，老版本继续用。chayuan-desktop 的 v3 系列已经稳定，新功能在 v4 路线图里慢慢开，老用户没有被强行升级的压力。
