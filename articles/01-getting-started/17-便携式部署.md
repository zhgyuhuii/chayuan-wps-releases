# 装到U盘上能跑吗 察元AI便携式部署的可行边界

「装到U盘上随身带」这种想法在 IT 圈不算新鲜，但放到 AI 桌面应用里有点反常识。模型权重几个 G、向量库几个 G、对话历史源源不断写盘，便携模式还能跑得动吗。这一篇讲 chayuan-desktop 桌面单机版的便携式部署边界。

先讲什么叫便携。我说的便携是把整个应用加上数据放在一块外置 SSD 或者高速 U 盘上，插到任何一台电脑都能跑察元AI 而不需要安装。免费开源的AI软件 在便携这件事上有先天优势：源代码可见、目录结构清楚、不依赖系统级注册表。

chayuan-desktop 的安装包结构本身有便携的可能性。Tauri 外壳是一个绿色 exe（Windows）或 .app（macOS）或可执行二进制（Linux），不强依赖系统目录；嵌入式 Python sidecar 是 PyInstaller 打的 onedir，把整个 Python 运行时和依赖塞在一个目录里，也不依赖系统 Python；模型权重在 CHAYUAN_ROOT/models 下，自己掌握；向量库和对话历史在 CHAYUAN_ROOT/data 和 CHAYUAN_ROOT/vectors，也自己掌握。

便携部署的步骤。第一，把 chayuan-desktop 的解压版（不是 msi/dmg/deb）放到外置 SSD 的一个目录，比如 X:\Apps\chayuan-desktop。第二，把 CHAYUAN_ROOT 也指到外置盘上，比如 X:\Data\Chayuan。第三，写一个启动脚本，先 set CHAYUAN_ROOT=X:\Data\Chayuan 再启动 chayuan-desktop.exe。

第二步的 CHAYUAN_ROOT 指向是关键。FirstRunSetup 选目录这一步选 X 盘的 Data\Chayuan，所有数据后续就落在这个外置盘上。换电脑插上 U 盘跑同一个启动脚本，CHAYUAN_ROOT 仍然是 X 盘那个路径，对话历史、模型钥匙、向量库都跟着走。

但是有几个坎。第一坎是密钥派生。chayuan-desktop 的模型钥匙加密用 Tauri Stronghold，密钥派生跟操作系统的用户绑定。同一个外置盘插到不同电脑，对应的用户身份不一样，加密的钥匙解不开。表现是模型供应商列表都在，但请求模型时报 401。处置方法是在每台电脑上都重新填一遍钥匙，或者用 chayuan-desktop 提供的密钥导出导入工具走专门通道。

第二坎是 sqlite-vec 文件锁。SQLite 在外置 SSD 上的写性能取决于盘速度，便宜 U 盘上可能慢得让人想换电脑。建议用 USB 3.2 或者 NVMe 外置盒，传输速率别低于 200MB/s。同一个 SQLite 文件不要同时被两个 chayuan-desktop 打开，否则会锁住。

第三坎是模型权重路径。bge-m3-onnx、RapidOCR 这些权重文件在 CHAYUAN_ROOT/models 下，跟随便携盘走没问题。但如果你接了本地 Ollama 服务，那部分模型不在便携盘里，跨电脑就用不了。便携模式下推荐走云端模型供应商，这样不依赖本地推理服务。

第四坎是 Windows 的注册表残留。Tauri 主进程默认不写注册表，但 webview2 runtime 的状态可能落到目标电脑的注册表里。这种残留无害，不影响便携使用。

第五坎是杀毒软件。每插一台新电脑，杀毒软件会扫一遍外置盘上的 chayuan-desktop.exe 和 chayuan-server.exe。第一次扫描时间略长。这是没办法避免的小代价。

便携模式的实际场景在哪。一是出差，把 chayuan-desktop 插到客户电脑做演示；二是临时办公，几个工位轮换使用同一份资料；三是讲课或培训，把课件资料用 folder-sync 索引在便携盘里，到任何电脑插上即可演示。这些场景里便携模式比想象中好用。

WPS AI 插件 chayuan-wps 没法跟着便携盘走，因为它是 WPS Office 的加载项，安装位置在 WPS 管理范围内。便携模式下加载项无法使用，这是一个实际限制。如果你的工作流强依赖 WPS 加载项，便携并不适合。

便携部署的总结：技术上可行，体验上有边界，最适合的场景是出差演示和临时使用，不适合作为日常主力。免费开源的AI软件 的可移植性给了你这种选择，但选择本身要考虑使用场景。
