# 本地离线知识库的存放策略 CHAYUAN_ROOT到底放哪里

第一次打开察元AI 桌面单机版会看到 FirstRunSetup 向导，第一屏问的就是数据目录放哪。这个问题看起来无关紧要，其实直接决定后面三件事：备份是不是省心、跨机迁移是不是方便、出问题时数据是不是好捞回来。这一篇专门讲 CHAYUAN_ROOT 的选择。

先看 CHAYUAN_ROOT 是什么。它是 chayuan-desktop 后端 sidecar 的根目录环境变量，由 Tauri 主进程在 spawn 子进程时注入。这个目录下面会拆成若干子目录：data 放对话历史和元数据库，kb 放各类知识库索引，vectors 放本地离线知识库的 sqlite-vec 文件，models 放下载下来的嵌入和 OCR 权重，credentials 放加密后的模型钥匙，logs 放运行日志。所有跟你这台机器相关的察元AI 状态，都收敛在这一棵树里。

为什么不要放系统盘的用户目录。Windows 默认会把 AppData 指到 C 盘的隐藏目录，万一某次系统重置或者用了优化软件清缓存，这棵树有可能被误删。macOS 的 Library 目录稍好一些，但仍然不利于备份。Linux 上传统的 ~/.local 是合适的，但如果你后期要把整套搬到 NAS、移动硬盘、外接 SSD，还是放在一个明确的、可读可写、不会被系统软件碰的目录更稳。

我给办公族的建议是：单独挑一个数据分区，比如 D:\Chayuan，或者 macOS 的 /Volumes/Data/Chayuan，或者 Linux 的 /srv/chayuan。这个目录最好满足几个条件。第一，磁盘空间不要太紧，预留至少 20G，知识库一旦开始入库会膨胀；第二，所在分区做日常增量备份的时候要被覆盖到，这样万一硬盘坏了不会哭；第三，权限要明确属于当前用户，避免后台 sidecar 写盘失败。

如果你装在公司发的电脑上，公司 IT 通常会规定数据要落在某个被管控的目录。这个时候应当跟 IT 说清楚 CHAYUAN_ROOT 这个目录会承载敏感数据，比如模型钥匙、私有知识库、对话历史，建议跟 OneDrive 或公司云盘做一次对账，决定要不要纳入备份。免费开源的AI软件 在这一点上其实很方便，因为所有数据都在一个目录里，IT 一眼就看清楚边界。

不要随便把 CHAYUAN_ROOT 指到一个网络盘或者 NAS 上。Tauri 端是允许这么做的，但 sqlite-vec 在远程文件系统上的写性能很难保证，索引重建和大批量写入容易卡住。如果你确实要把数据放在 NAS，我推荐的做法是定期把整个 CHAYUAN_ROOT 用 rsync 或者 robocopy 同步过去，做一份冷备份，主目录还是放在本机 SSD 上。

如果你在多台电脑上都装了 chayuan-desktop，CHAYUAN_ROOT 不要互相同步成一份。这样会出现两台机器同时写同一个 SQLite 文件的情况，损坏几乎是必然。正确的做法是每台机器各有独立的 CHAYUAN_ROOT，需要把数据搬过去的时候用导出导入工具，或者用知识库迁移脚本。

最后，单机版默认是关鉴权的，所以 credentials 目录里的密钥用 Tauri Stronghold 加密，密钥派生跟操作系统的用户绑定。这意味着你把整个 CHAYUAN_ROOT 拷贝到另一台电脑上，密文会还在但解不开。要跨机器搬密钥需要走专门的导出流程。这个细节在后面 18 安全隐私 那一类里我会再展开。

CHAYUAN_ROOT 选好，后面 chayuan-desktop 的所有事情就都有一个看得见的家，包括之后要跟 WPS AI 插件 chayuan-wps 共用的那份知识库索引。
