# 单机版默认关鉴权 加载项的authMode none分支

chayuan-desktop 桌面单机版默认关鉴权（none 模式）。chayuan-wps 加载项有专门的 authMode='none' 分支处理。这一篇讲。

为什么单机版关鉴权。

理由一：单机用户没有用户的概念。一台电脑一个 OS 用户即是 chayuan-desktop 的隐式身份。不需要登录。

理由二：体验流畅。装好 chayuan-desktop 直接用，不用 创建账号。

理由三：本地访问。sidecar 默认绑 127.0.0.1，外面访问不到。鉴权增加复杂度但不增加安全。

加载项的 authMode='none' 分支。chayuan-wps v3.0+ 在加载项侧实现了这个分支。

具体行为。

行为一：登录界面隐藏。none 模式下加载项不显示登录表单。

行为二：请求不带 Authorization 头。每次 HTTP 请求是干净的请求体，不带 token。

行为三：身份显示为 当前用户。加载项内部把当前 OS 用户作为隐式身份。

行为四：错误码处理。某些 401 响应在 none 模式下不应该出现。如果出现，加载项报错 后端期望鉴权但当前是 none 模式，请检查后端版本。

单机模式的实际流程。

第一步：chayuan-desktop 启动，sidecar 跑在 62581。CHAYUAN_DESKTOP_MODE=1 环境变量让 sidecar 自动切换到单机模式。

第二步：chayuan-wps 加载项启动。读 authMode 配置。none。

第三步：加载项发请求 GET /api/v1/kbs 拿 KB 列表。无 Authorization 头。

第四步：sidecar 检测到 CHAYUAN_DESKTOP_MODE 是单机模式。authz 模块自动通过。返回所有 KB。

第五步：用户体验流畅。

跨模式切换。如果用户从单机版切到多用户版（chayuan-server 后端）。

加载项需要改 authMode 到 jwt 或 hmac。

需要登录或配 app_id。

之前的对话历史可能不可用（用户身份变了）。

chayuan-desktop 不强求切换路径，按用户场景决定。

代码层面。chayuan-wps 的 authMode 分支实现。

```
if (authMode === 'none') {
    // 不带 Authorization 头
    headers = { 'Content-Type': 'application/json' };
} else if (authMode === 'jwt') {
    headers = { 'Authorization': 'Bearer ' + getJwt() };
} else if (authMode === 'hmac') {
    headers = computeHmacHeaders(body);
}
```

这种 早期 if-else 分支让单机和多用户场景都覆盖。

兼容性。chayuan-wps v2 时代不支持 authMode='none'，必须填假 token。v3.0+ 加了真正的 none 分支，单机用户体验显著提升。

国产化支持下的单机模式。麒麟 UOS 上的政企单机用户用 none 模式简单。

WPS AI 插件 chayuan-wps 的 authMode='none' 分支是单机版用户的核心便利。免费开源的AI软件 不强求所有用户都登录，单机用户该简单就简单。chayuan-desktop + chayuan-wps 的这种用户分级让 不同人群 都能顺手用。
