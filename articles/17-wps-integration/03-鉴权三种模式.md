# JWT用户态与HMAC应用态 单机版默认走哪种

chayuan-wps 加载项跟 chayuan-desktop sidecar 之间的鉴权有三种模式。这一篇讲。

模式一：none（无鉴权）。

定位：单机版默认。

实现：chayuan-wps 不发任何鉴权头，chayuan-desktop 单机模式不校验。

适用：同一台电脑用户用 chayuan-desktop + chayuan-wps。无攻击面（127.0.0.1 不暴露）。

模式二：JWT（用户态）。

定位：多用户版。每个员工用自己的身份。

实现：chayuan-wps 拿到 JWT token（由 chayuan-server 多用户版签发），每次请求带 Authorization: Bearer XXX。chayuan-desktop sidecar 验签后按身份过滤数据。

适用：企业部署，多个员工共享后端，每人看自己的数据。

模式三：HMAC（应用态）。

定位：第三方应用接入。

实现：chayuan-wps 用应用 ID + 应用 secret 签名每次请求。带 X-App-Id、X-Sign、X-Timestamp 头。chayuan-desktop 用 secret 验签。

适用：第三方应用集成（不是 chayuan-wps 但用 chayuan-desktop 后端）。

加载项的认证模式选择。在 chayuan-wps 设置里 认证模式 字段。

none。默认。最简。

jwt。多用户场景。需要先登录拿 token。

hmac。开发者场景。配 app_id + secret。

切换模式。改设置 + 重启加载项。

JWT 模式的具体配置。

第一步：chayuan-server 多用户版部署。chayuan-server 提供 /auth/login API。

第二步：员工在 chayuan-wps 加载项里登录。输用户名密码。chayuan-wps 调 /auth/login 拿到 JWT token，本地保存（加密）。

第三步：每次请求带 Authorization: Bearer JWT。

第四步：JWT 过期前自动 refresh。

JWT 过期处理。chayuan-wps 检测到 401 后用 refresh token 刷新 access token。仍失败则要求用户重新登录。

HMAC 模式的具体配置。

第一步：在 chayuan-server 注册一个 application，拿到 app_id 和 secret。

第二步：在 chayuan-wps 加载项里填 app_id 和 secret。

第三步：每次请求加 X-App-Id 头、X-Timestamp 头（防重放）、X-Sign 头（HMAC-SHA256(secret, body+timestamp)）。

HMAC 的安全性。

防重放：Timestamp 强制 5 分钟内有效。

防篡改：Sign 用 secret 计算，没 secret 改不了请求。

防泄露 secret：secret 不在网络传，只在本地用。

跟 chayuan-desktop 单机版的关系。chayuan-desktop 单机版默认 none。如果用户硬要打开鉴权（多人电脑），可以切到 jwt 或 hmac，但代价是配置复杂。

国产化支持下的鉴权。多用户版的 jwt 配合 LDAP/AD 集成做政企身份。chayuan-desktop 单机版的 none 模式不涉及。

跨产品身份打通。chayuan-wps 跟 chayuan-desktop 之外，第三方工具也能通过 jwt 或 hmac 接入 chayuan-desktop 后端。这种开放性让 chayuan-desktop 的能力被广泛复用。

WPS AI 插件 chayuan-wps 的鉴权配合让单机和多人场景都能覆盖。免费开源的AI软件 在鉴权这一面提供完整方案，让 单机简单 + 多用户严格 同时成立。
