# 选区与全文的上下文 加载项怎么把它送到后端

chayuan-wps 加载项把 WPS 文档的当前选区或全文作为上下文送给 chayuan-desktop。这一篇讲。

## 场景

场景一：选区。用户在 WPS 选了某段文字。问 AI 这段什么意思。加载项把选区文字作为上下文。

场景二：全文。用户问 总结这份文档。加载项把整个 WPS 文档内容作为上下文。

场景三：组合。某段 + 全文。比如 这段是哪一节的主旨，结合全文看。

每种都需要送给后端。

## 选区获取

WPS API。

```js
const selection = WpsApplication.Selection;
const text = selection.Text;
const range = selection.Range;
```

加载项把选区文字 + 范围信息送给 chayuan-desktop。

## 全文获取

```js
const doc = WpsApplication.ActiveDocument;
const fullText = doc.Range.Text;
```

整个文档文本。

如果文档很大（万字+），全文可能超过 LLM 上下文。加载项需要截断或摘要。

## 截断策略

策略一：直接截断到 N 字。简单但可能截断关键信息。

策略二：分块送。让 LLM 多轮处理每块。

策略三：先在加载项 / chayuan-desktop 摘要再送。

策略四：把全文入临时 KB，让 LLM 检索。

chayuan-wps 默认策略四（RAG 化）。无需截断。

## RAG 化全文

加载项发送全文到 chayuan-desktop。chayuan-desktop。

切 chunk。

嵌入。

存到临时 KB（会话级，不持久化）。

LLM 在该 KB 上检索回答。

整个流程对用户透明。秒级。

## 上下文传递的协议

加载项 → chayuan-desktop 走 OpenAI 兼容协议（前面文章讲）。

```json
{
  "messages": [
    {"role": "system", "content": "..."},
    {"role": "user", "content": "..."}
  ],
  "extra": {
    "wps_context": {
      "selection_text": "...",
      "full_doc_path": "...",
      "current_paragraph": 5,
      "doc_metadata": {...}
    }
  }
}
```

extra 字段传 WPS 上下文。chayuan-desktop 解析后用。

## 引用回链需要的信息

加载项发送的不只是文字，还需要。

文档路径。便于后续引用回链。

段落索引。便于跳转到具体段落。

文档 metadata。作者、日期等。

完整信息让 chayuan-desktop 后续能精确响应。

## 用户授权

WPS 文档可能含敏感信息。加载项发送给 chayuan-desktop 前。

如果走云模型，弹用户确认 文档内容会发送给 OpenAI，是否继续。

如果走本地模型，无需确认（本机处理）。

策略一致 chayuan-desktop（前面文章）。

## 多文档协同

某些场景用户需要 跨文档分析。

```
对比这份 contract 和 office:legal:contracts 中的标准合同
```

加载项把当前 WPS 文档 + KB 检索结果一起送给 chayuan-desktop。

LLM 综合两边信息回答。

## 大文档处理

万字以上文档送全文不现实。chayuan-wps 的策略。

每次只发选区 + 周围段落（前后 5 段）。

长文整体走 RAG 化（前面讲）。

## 国产化场景

党政军写公文常引用其他公文。chayuan-wps 的选区 + 全文 + 跨文档让 引用工作 在 AI 辅助下高效。

## chayuan-server 的对应

chayuan-server 模式下加载项发送给 chayuan-server（不是 chayuan-desktop）。协议一致。

## chayuan-desktop 的处理

chayuan-desktop 收到加载项请求后处理。跟桌面端用户的请求一样。共享后端逻辑。

## 总结

选区与全文的上下文是 chayuan-wps 加载项的核心交互。免费开源的AI软件 让 WPS 用户的文档内容 自然进入 AI 上下文。chayuan-wps 的选区 + 全文 + RAG 化 + 多文档让 AI 在 WPS 内有最丰富的上下文。
