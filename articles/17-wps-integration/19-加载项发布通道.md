# 加载项的发布通道 公司分发与公共商店

chayuan-wps 加载项的发布通道。这一篇讲。

## 几种通道

通道一：WPS 公共商店。

WPS 加载项市场。普通用户从 WPS 主程序里搜索安装。

需要金山审核。

通道二：政企内部商店。

某些政企搭内部加载项市场。员工 WPS 从这里装。

不走公共审核。但需要内部审批。

通道三：直接分发。

加载项 .wpsaddin 文件直接发给员工。

员工拖入 WPS 安装。

通道四：MDM 推送。

企业 IT 用 MDM 工具集中推送加载项到员工 WPS。

员工无感安装。

## 公共商店发布

提交流程。

打包 .wpsaddin。

填写元数据（名称、描述、截图、版本号）。

提交到 WPS 加载项市场。

金山审核（5-10 工作日）。

通过后上架。普通用户能搜到。

## 政企内部商店

搭建。

某政企的 WPS 内部市场是 HTTP 服务。

```
http://addins.corp.com/wps-addins/
  manifest.json (列出所有可用加载项)
  chayuan-wps/
    3.0.0/
      manifest.xml
      package.zip
```

员工 WPS 配置内部市场 URL。

升级。新版 chayuan-wps 上传到内部市场。员工 WPS 自动检测更新。

权限。某些加载项只对特定部门可见。manifest.json 含权限信息。

## 直接分发的工程

某些场景不走任何市场。直接发包给员工。

适合：试用版、定制版、临时版。

代价：升级麻烦（每次重新发包）。

## MDM 推送

政企 IT 集中管理员工电脑。

WPS 配置由 MDM 推送。加载项也是。

```
MDM → 推送 chayuan-wps_3.0.0.wpsaddin → 员工 WPS 自动安装
```

员工无感。强制安装（IT 决定）。

## 签名 + 信任

公共商店的加载项金山签名。

内部商店的加载项可能金山签名也可能企业自签。

WPS 客户端配置信任的签名链。

```
WPS - 加载项 - 信任设置 - 信任企业 CA 签名
```

避免恶意加载项。

## 版本兼容

不同 WPS 版本对加载项 API 有差。chayuan-wps 在 manifest.xml 声明最低支持 WPS 版本。

```xml
<RequiredWpsVersion>11.5</RequiredWpsVersion>
```

低版本 WPS 不让安装。

## 升级管理

公共商店升级。WPS 自动检查并提示。

内部商店升级。WPS 按内部商店配置。

直接分发升级。员工手动替换。

MDM 升级。IT 集中推。

## 撤回机制

某加载项发现严重 bug 需要撤回。

公共商店：联系金山下架。

内部商店：管理员从市场删除。

直接分发：通知员工卸载。

MDM：IT 推送卸载指令。

## 国产化场景

党政军场景多用内部分发或 MDM。chayuan-wps 的多通道发布让政企部署灵活。

某些场景必须经过国家信创认证才能内部分发。chayuan-wps 走信创认证流程。

## chayuan-server 的对应

chayuan-server 跟加载项发布通道无直接关系。但 chayuan-server 部署后员工的 chayuan-wps 都连同一个 chayuan-server。

## 总结

加载项的发布通道是 chayuan-wps 在企业级部署上的工程能力。免费开源的AI软件 让 加载项分发 适应各种场景。chayuan-wps 的公共商店 + 内部商店 + 直接分发 + MDM 四种方式覆盖主流需求。
