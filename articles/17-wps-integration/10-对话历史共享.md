# 同一份对话历史 加载项发起的对话进入桌面历史

chayuan-wps 加载项发起的对话同步到 chayuan-desktop 的对话历史。这一篇讲。

## 共享的意义

员工早上在 chayuan-desktop 跟 AI 聊了 大客户拜访策略。

下午在 WPS 写访客报告。chayuan-wps 加载项侧栏。

理论上这是 同一个工作。聊天历史应该统一。

不分桌面 / WPS。

## 实现链路

链路。

第一。chayuan-wps 发起对话调 chayuan-desktop 的 chat API。

第二。chayuan-desktop 创建会话 / 续接会话。session_id 关联。

第三。chayuan-desktop 把会话写入历史数据库（同桌面端历史）。

第四。chayuan-wps 在加载项侧栏显示当前会话。

第五。后续打开 chayuan-desktop 桌面端，能在历史里看到 WPS 发起的会话。可继续对话。

## session 的唯一性

每个会话有 session_id。

桌面端创建。

WPS 创建。

某场景延续上一个会话（用户主动选）。

session_id 关联所有消息。

## 跨端续接

用户上午在桌面跟 AI 聊。session_42。

下午切到 WPS。chayuan-wps 加载项打开。

用户能选 续接 session_42 或开新会话。

```
最近会话：
  [session_42] 大客户拜访策略 (上午)
  [session_43] 报告写作 (上午)
[+ 新会话]
```

选 session_42 续接。chayuan-wps 显示历史消息 + 让用户继续问。

## 当前文档的关联

chayuan-wps 在 WPS 里启动时知道当前 WPS 文档。

会话 metadata 含 wps_doc_path。

```json
{
  "session_id": "...",
  "wps_doc_path": "/path/to/contract.docx",
  "started_in": "wps"
}
```

后续即使在桌面端打开历史，也能看到 这个会话是在 WPS 里写 contract.docx 时启动的。便于回忆。

## 引用的跨端

WPS 里发起的引用（点击跳到 WPS 文档段落）。

回到桌面端打开历史。点同一引用。桌面端如何处理。

策略一。打开 WPS（启动 WPS 应用）+ 跳段落。

策略二。降级展示。桌面端 PDF Reader 打开 PDF（如果有）。或仅展示引用文字。

chayuan-desktop 的策略一。能更完整体验。

## 写回的跨端

WPS 里 AI 写回到文档。这个写回操作记到历史。

桌面端历史能看到 AI 在 X 时间向 Y 文档插入了内容。

完整可追溯。

## UI 一致

加载项侧栏的会话 UI 跟桌面端一致风格（小尺寸版本）。

引用气泡、消息流、工具调用展示。

学习成本低。

## 同步延迟

chayuan-wps 跟 chayuan-desktop 后端实时同步（同一进程）。无延迟。

跨设备场景（chayuan-server 中心化）。chayuan-wps 跟 chayuan-server 通信。chayuan-desktop 也跟 chayuan-server 通信。同步通过 chayuan-server 中转。延迟几百毫秒。

## 隐私

聊天历史含敏感内容。chayuan-desktop 的本地存储默认。chayuan-wps 也是本地（共用 chayuan-desktop 后端）。

不上传任何地方（除非用户主动用云模型，仅 prompt 上云）。

## 国产化场景

党政军场景跨端 一致工作流 是核心需求。chayuan-wps + chayuan-desktop 历史共享让员工 在哪里都连续工作。

## chayuan-server 的对应

chayuan-server 多用户场景下历史集中。多设备同步更自然。

## 总结

同一份对话历史的桌面 / WPS 共享是 chayuan-desktop + chayuan-wps 的工程一致性。免费开源的AI软件 让 工作不分应用。chayuan-desktop 的统一后端 + session 关联 + UI 一致让用户在 WPS 和桌面间无缝切换。
