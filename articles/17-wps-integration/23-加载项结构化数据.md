# 加载项与结构化数据 销售台账的实时问答

chayuan-wps 加载项跟结构化数据（数据库 / WPS 表格）的协同。销售台账实时问答。这一篇讲。

## 场景

销售经理李四要写月度销售报告。

数据源。

WPS 表格 sales_2026_05.xlsx（个人销售台账）。

公司 ERP（结构化 KB structured:erp）。

公司 BI 数据仓库（structured:doris）。

需要从这几个源拉数据写报告。

## 加载项的能力

chayuan-wps 加载项。

把当前 WPS 表格作为结构化 KB 处理。

调用 chayuan-desktop 的 text2sql 工具。

跨 KB 联合查询。

返回结果 + 引用。

## 第一步 把 WPS 表格作为 KB

李四在 WPS 表格 sales_2026_05.xlsx 打开。

加载项检测到是表格。提示。

```
当前文档是销售台账表格。
是否将其作为临时结构化 KB 用于本次会话？
[确认]
```

加载项调 chayuan-desktop。

chayuan-desktop。

读 xlsx。每 sheet 一个表。

转 SQLite 临时表（前面 office 系列文章讲）。

注册为临时 KB。

## 第二步 提问

李四问。

```
本月销售排名前 10 的客户是谁？
```

加载项调 chayuan-desktop text2sql。

LLM 生成 SQL。

```sql
SELECT customer_name, SUM(amount) AS total
FROM sales_2026_05  -- 临时表
WHERE month = '2026-05'
GROUP BY customer_name
ORDER BY total DESC
LIMIT 10;
```

执行。返回结果。

## 第三步 跨 KB 联合查询

```
这 10 个客户里，哪些在 ERP 里有未结清账单？
```

涉及两个 KB。

WPS 表格的临时 KB（top 10 客户名单）。

ERP 的 structured:erp。

chayuan-desktop。

第一步：从 WPS 表格 KB 拿到 top 10 客户名（前一轮的结果）。

第二步：拿名单去 ERP 查未结清账单。

```sql
-- ERP
SELECT customer_name, SUM(unpaid) FROM accounts 
WHERE customer_name IN (...)
  AND status = 'unpaid'
GROUP BY customer_name;
```

第三步：合并两边结果。

LLM 输出。

```
top 10 客户中有 3 个有未结清账单：
- 客户 A：未结清 50 万
- 客户 B：未结清 30 万
- 客户 C：未结清 12 万

来源：
[1] WPS 销售台账（临时 KB）
[2] ERP 应收账款表
```

## 第四步 写回报告

李四点 插入分析到报告末尾。

加载项把分析插入 WPS 文档（不是表格 - 是 docx 月报）。

```
本月销售排名 top 10 客户中，有 3 家存在未结清账单：
- 客户 A：未结清 50 万元
- 客户 B：未结清 30 万元
- 客户 C：未结清 12 万元

需要 finance 团队关注。

[来源链接：销售台账 + ERP 应收账款表]
```

## 第五步 生成图表

李四进一步问 给我画一个 top 10 销售柱状图。

加载项调 chart_render。

```
[销售 top 10 柱状图]
```

图像插入 WPS 月报。完整图文。

## 整体工作流

李四用 chayuan-wps 的加载项。

跨 WPS 表格 + ERP + BI 拉数据。

LLM 整合 + 分析。

写回到 WPS 月报。

整个过程 30 分钟。手工跑可能 2 小时。

## 国产化场景

党政军场景常需要跨系统查询写报告。chayuan-wps + 结构化 KB 让 跨数据源分析 在 WPS 内一站式完成。

## chayuan-server 的对应

chayuan-server 模式下结构化 KB 集中。员工 chayuan-wps 通过 chayuan-server 查所有数据。

## 总结

加载项与结构化数据的协同是 chayuan-wps 在 BI 工作流上的工程能力。免费开源的AI软件 让 写报告 不只是抄数据，是 智能整合 + 自然语言查询。chayuan-wps 的临时 KB + 跨源查询 + 写回让 数据驱动的报告 高效产出。
