# 流式与非流式 同一接口的两种返回

chayuan-desktop 桌面单机版的模型网关支持流式（SSE）和非流式两种返回。这一篇讲。

## 两种模式的差异

流式。stream=true。模型边生成边返回 token。SSE 协议（Server-Sent Events）。每个 token 一个 event。用户看到逐字打字效果。

非流式。stream=false。等模型完整生成，一次性返回 JSON。需要等几秒到几十秒不等。

## 用户体验差异

流式好处。第一个 token 出来快（一般 0.5-2 秒）。用户感觉响应快。看到 token 流动有 真在思考 的感觉。

非流式好处。简单。无需 SSE 解析。适合脚本化调用。

chayuan-desktop 默认聊天界面用流式。WPS 文档插入用非流式（要等完整再贴）。

## 厂商的支持差异

OpenAI、Anthropic、Qwen、智谱、文心。都支持流式。

某些私有部署（自架的小框架）只支持非流式。chayuan-desktop 的网关探测到不支持流式时自动降级。

## SSE 的格式

OpenAI 风格。

```
data: {"choices":[{"delta":{"content":"你"}}]}
data: {"choices":[{"delta":{"content":"好"}}]}
data: [DONE]
```

每个 data: 是一个 event。\n\n 分隔。chayuan-desktop 解析每行，累积 delta.content。

Anthropic 略有不同（content_block_delta、message_delta 等多种 event）。chayuan-desktop 网关有适配器。

## chayuan-desktop 的统一接口

上层应用只看到 chayuan-desktop 的统一流接口。

```
chayuan-desktop.chat.complete({
  messages: [...],
  stream: true,
  on_token: (token) => { ... }
})
```

无论底层是哪家厂商，回调都一致。

## 错误处理

流式过程中可能中途出错。

网络断开。chayuan-desktop 检测 SSE 流中断，弹提示 网络中断 用户能 重新生成 或 续写。

模型限速。某些厂商在流式中触发限速，chayuan-desktop 收到 429 中断流，按 fallback 链切换。

模型拒绝（content filter）。某些回答因为内容被过滤中途停止。chayuan-desktop 显示 部分内容已过滤。

## 流式的取消

用户在流式过程中点 停止 按钮。chayuan-desktop 调 fetch 的 AbortController 取消请求。

某些厂商支持 partial response 计费（生成多少算多少），某些不支持（中途取消可能仍按完整计费）。chayuan-desktop 在不同厂商上行为不同。

## 流式的累积展示

UI 收到每个 token 把它追加到当前消息文本。当前消息显示 正在生成 状态（光标闪）。

收到 [DONE] 时切换到 已完成 状态，显示底部的引用气泡和评分按钮。

## 流式与工具调用

工具调用（function calling）跟流式叠加复杂。模型在生成过程中决定调工具。chayuan-desktop 处理。

第一阶段。流式生成工具调用决策。看到 tool_calls 字段触发工具执行。

第二阶段。工具结果回写到 messages，再发起一次流式请求让模型基于工具结果继续生成。

用户看到 第一段思考 → 工具执行（loading）→ 第二段回答。

## 国产化场景

政企用户对响应速度敏感（领导问问题等不及）。chayuan-desktop 的流式让 第一字 0.5 秒内出来。本地推理（Ollama）流式更快。

## chayuan-server 的对应

chayuan-server 模式下 chayuan-desktop 把流式请求转发，chayuan-server 中转 SSE 流。中间会增加一点延迟（几十毫秒），不影响体验。

## WPS 加载项

chayuan-wps 在 WPS 里支持流式展示（聊天侧栏）。WPS 文档插入用非流式（要等完整再贴整段）。

## 总结

流式与非流式的同一接口处理是 chayuan-desktop 在工程统一性上的基础。免费开源的AI软件 接入多厂商必须做这种封装，避免上层应用为每家厂商写一套。chayuan-desktop 的网关让流式调用 跟非流式一样简单。
