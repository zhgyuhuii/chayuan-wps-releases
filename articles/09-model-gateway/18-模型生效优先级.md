# 模型生效优先级 用户选择 大于 默认 大于 自动

chayuan-desktop 桌面单机版的模型网关每次请求实际用哪个模型按 优先级 决定。这一篇讲优先级体系。

## 三层优先级

第一层：用户当前选择。聊天界面顶部用户手动选了某模型。优先级最高。

第二层：用户配置的默认。设置 - 模型 - 默认模型 里配置的类别默认。次高。

第三层：chayuan-desktop 自动推荐。基于内置规则的候选默认（参考前面晋升文章）。最低。

## 优先级的应用顺序

请求到达。chayuan-desktop 决策实际模型。

第一步。检查请求是否指定了 model 参数。如果指定就用（用户当前选择最高优先级）。

第二步。如果没指定 model，按请求类别（chat / embed / image / rerank）查用户配置的类别默认。

第三步。如果用户没配置类别默认，用 chayuan-desktop 内置自动推荐。

## 显式指定的优先级

某些场景上层应用显式指定模型 ID。比如 chayuan-wps 加载项的某个 流畅写作 功能强制用 gpt-4o（因为质量好）。这种显式指定优先级最高，即使用户的默认是 qwen-turbo。

显式指定的好处。让上层能针对特定任务选最合适的模型。

显式指定的代价。如果指定的模型禁用或失败，要么报错要么走 fallback 链。chayuan-desktop 选 fallback。

## 类别默认的细分

类别内能再细分。

```
chat:
  default: gpt-4o
  cheap_default: qwen-turbo  # 低优先级备选
  premium_default: gpt-4o    # 高质量场景
```

某些场景 chayuan-desktop 自动选 cheap_default。比如 摘要生成 这种简单任务。

## 跨类别的智能切换

请求里有图像 → 自动切到 image 类别。即使用户当前选的是 gpt-4o（不带视觉的版本），自动升级到 gpt-4o-vision。

请求里有 tools → 用支持 tools 的模型。如果当前模型不支持，自动切到支持的（同厂商优先）。

## fallback 链的优先级

主模型失败时走 fallback 链。链路里的模型优先级。

fallback 第一个 > fallback 第二个 > ... > 本地模型兜底。

链路 = 用户配置或自动生成。

## 优先级的可视化

chayuan-desktop 设置 - 模型 - 当前生效。

```
当前 chat 类生效：
  显式指定：（无）
  类别默认：gpt-4o (用户配)
  fallback 链：gpt-4o → claude-3.5 → qwen-plus → ollama:qwen2.5
  实际首选：gpt-4o
```

让用户清晰看到每个类别实际用什么。

## 调试模式

某些用户排查问题。chayuan-desktop 设置 - 调试 - 模型路由日志。开启后每次请求记录。

```
[2026-05-10 14:23] chat request
  desired: (none)
  default: gpt-4o
  selected: gpt-4o
  result: success
```

便于问题诊断。

## 默认配置的迁移

用户升级 chayuan-desktop 版本。新版本可能引入新模型成为推荐默认。

迁移规则。已有用户配置不动（尊重用户偏好）。但提示 我们推荐 X 作为新默认，是否切换。让用户主动选。

## 国产化场景

政企用户希望默认走国产模型。chayuan-desktop 设置里有 国产优先 一键开关，把所有类别默认切到国产模型。简化合规配置。

## chayuan-server 的对应

chayuan-server 模式下默认模型可能由企业管理员配置（用户不能改）。chayuan-desktop 单机版完全用户自由。

## WPS 加载项

chayuan-wps 在 WPS 里默认按 chayuan-desktop 的优先级走。但 WPS 加载项里某些功能（写作建议）可能显式指定模型。这跟 chayuan-desktop 设置不冲突，按优先级规则就好。

## 总结

模型生效优先级是 chayuan-desktop 在多层模型选择策略下的工程清晰度保证。免费开源的AI软件 接入多模型 + 多层默认必须有清晰优先级才不混乱。chayuan-desktop 的 用户选择 > 类别默认 > 自动推荐 + fallback 链让 实际用哪个模型 永远可解释。
