# 模型自动升级 当厂商发了新版我怎么不踩坑

chayuan-desktop 桌面单机版的模型网关在厂商发新版模型时帮用户判断要不要升级。这一篇讲。

## 厂商发新版的常见情况

情况一。直接发布新模型 ID。GPT-4o 出来后 GPT-4 仍在运行。用户能继续用旧版。

情况二。同 ID 升级（latest）。Anthropic 的 claude-3-5-sonnet-latest 自动指向最新版本。用户没改 ID 但实际跑的是新版。

情况三。旧版被弃用。GPT-3.5-turbo-0301 弃用，调用返回 deprecation warning。

情况四。旧版下线。GPT-3 早期版本完全下线，调用 404。

每种处理不同。

## chayuan-desktop 的检测

启动时拉 /v1/models 列表对比上次。发现新模型自动加入。发现旧模型消失提示用户。

```
检测到 OpenAI 新模型：gpt-4o-2024-11-20
检测到下线模型：gpt-3.5-turbo-0301
建议：将默认模型从 gpt-3.5-turbo-0301 切换到 gpt-4o-mini
```

## latest 标识的处理

chayuan-desktop 推荐用户用 latest 标识符（如果厂商支持）。比如 claude-3-5-sonnet-latest。这样新版自动跟。

但 latest 也意味着不可控。某天厂商升级新版可能行为变化。

chayuan-desktop 设置里能选 锁定具体版本 或 跟随 latest。默认锁定（保稳）。

## 新版的回归测试

某些用户对模型质量敏感。新版可能比旧版强但也可能在特定场景退化。

chayuan-desktop 的 Arena 模块（评测）能跑。

第一步。用户准备一组测试 prompt（自己常用任务）。

第二步。Arena 同时让旧版和新版回答。

第三步。用户盲评哪个更好。

第四步。结果反馈到 chayuan-desktop，决定是否切换。

不让用户被 厂商发新版 牵着走。

## 行为变化的检测

某些细微行为变化。新版默认温度更低、新版更倾向拒绝某些请求、新版输出格式微调。

chayuan-desktop 的 Arena 能跑回归测试，对比旧新版在常用任务上的差异。差异大的字段（拒答率上升、token 数变化）chayuan-desktop 弹提示。

## 弃用警告的展示

模型卡片里 deprecated=true 时 UI 显示警告。

```
⚠ gpt-3.5-turbo-0301 已弃用，将于 2026-06 下线
建议切换到：gpt-4o-mini（更便宜更快）
```

弃用日期来自厂商官方公告（手动维护或自动抓）。

## 自动迁移建议

某模型即将下线。chayuan-desktop 给迁移建议。

```
gpt-3.5-turbo-0301 → gpt-4o-mini
理由：
  - 同等定价（实际更便宜 50%）
  - 上下文长度从 16k 升到 128k
  - 视觉支持
  - 工具调用支持
```

让用户一键迁移。chayuan-desktop 把所有 fallback 链、显式指定的旧 ID 替换为新 ID。

## 不强制升级

chayuan-desktop 永远尊重用户意愿。即使旧版下线，chayuan-desktop 也只是提示，不主动改用户配置。

下线后调用返回 404。chayuan-desktop 走 fallback 链。用户最终意识到要改配置。

## 国产化场景

国产模型升级也常发生。文心 3.5 → 文心 4.0、Qwen-1.5 → Qwen-2.5。chayuan-desktop 的检测和迁移建议同样适用。

某些国产模型升级是免费（同价），用户大概率愿意升级。chayuan-desktop 的提示帮用户不错过升级机会。

## chayuan-server 的对应

chayuan-server 多用户场景下模型升级是企业级决策（管理员决定全员切换）。chayuan-desktop 单机版用户级。

## WPS 加载项

chayuan-wps 在 WPS 里挑模型时如果选了即将下线的模型也弹同样提示。让员工对模型生命周期有感知。

## 总结

模型自动升级是 chayuan-desktop 在多模型生态长期运营的工程支持。免费开源的AI软件 接入多厂商必须跟上模型迭代。chayuan-desktop 的检测 + 提示 + 迁移建议 + Arena 回归测试让 升级 是有数据支持的决策。
