# 模型限速与配额 单机版怎么自己控速

chayuan-desktop 桌面单机版的模型网关在用户侧主动控制调用速率。这一篇讲为什么和怎么做。

## 为什么单机版要自己控速

厂商有自己的速率限制。OpenAI 的 RPM（每分钟请求数）和 TPM（每分钟 token 数）。Tier 1 账号 RPM 500，Tier 4 账号 RPM 10000。

如果不控速，前端连续点几次发送，瞬间触发 429 限速错误。

主动控速避免触发限速。chayuan-desktop 在客户端排队，按厂商配额节流。

## 配额的来源

chayuan-desktop 设置里能填厂商配额。

```
openai: { rpm: 500, tpm: 30000 }
deepseek: { rpm: 60, tpm: 100000 }
zhipu: { rpm: 100, tpm: 200000 }
```

不填默认按厂商常见 Tier 1 配额。

## 控速算法

令牌桶算法。每个厂商一个独立的桶。容量是 RPM 的 10%（起始可以快速突发），每秒填充 RPM/60 个令牌。

请求到达。先尝试取一个令牌。能取走则放行。取不到则排队等。

token 维度类似。每个请求的 token 数量从 token 桶里扣。

## 排队的 UI

用户连续发请求，第二个请求被限速等待。chayuan-desktop UI 显示 排队中... 0:03。让用户知道为什么没反应。

排队超时（默认 30 秒）时给提示 限速等待过久，是否切换厂商。引导用户走 fallback 链。

## 多 Key 轮换

同一厂商多个 Key 轮换调度增加总配额。OpenAI 的 RPM 是 Key 级别的。两个 Key 总 RPM 翻倍。

chayuan-desktop 设置里能配多 Key，自动轮换。

```
openai: 
  - key: sk-aaa, rpm: 500
  - key: sk-bbb, rpm: 500
  total_effective_rpm: 1000
```

## 厂商发的限速错误

即使主动控速，偶发还是会触发 429。chayuan-desktop 的网关识别 429 后。

第一。按厂商响应里的 Retry-After header 等待。

第二。如果连续 5 次 429，临时把这个厂商降速 50%（保守起见）。

第三。30 分钟后恢复正常配额。

## 配额可视化

chayuan-desktop 设置 - 模型 - 配额状态。展示每个厂商当前可用配额、已用配额、本月 token 消耗。

异常情况（接近上限、被限速）用颜色提示。

## 单机 vs 多用户

单机版的控速只考虑当前用户。

chayuan-server 多用户版的控速更复杂，要考虑全局共享配额（多个用户共用同一个企业 Key）。

chayuan-desktop 的算法预留了 多实例协同 接口，未来支持局域网内多台单机协同共享配额。

## 国产化场景

政企用户买的国产模型 API 配额有限（早期定价）。chayuan-desktop 的控速避免突发请求耗尽月度配额。

某些政府场景对调用频次有合规要求（不能暴力刷）。chayuan-desktop 默认温和控速符合这种场景。

## chayuan-server 的协同

chayuan-server 模式下 chayuan-desktop 把请求转发给 chayuan-server，chayuan-server 做集中控速。这种 客户端不控速，服务端控速 模式更精准。

## WPS 加载项

chayuan-wps 在 WPS 里发起调用经过 chayuan-desktop 网关，复用同一控速逻辑。WPS 不需要自己实现控速。

## 总结

模型限速与配额是 chayuan-desktop 在工程稳定性上的小但实用的功能。免费开源的AI软件 接入多厂商必须考虑速率限制问题。chayuan-desktop 的令牌桶 + 多 Key 轮换 + 错误自适应让 不被厂商断流 在工程上有保证。
