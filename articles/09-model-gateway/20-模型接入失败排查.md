# 模型接入失败排查 网关层的日志和探针

chayuan-desktop 桌面单机版的模型网关接入新模型偶尔失败。这一篇讲排查思路。

## 失败的常见类型

类型一：连接失败。chayuan-desktop 连不上厂商域名。网络问题。

类型二：401 认证失败。Key 错或过期。

类型三：404 模型不存在。模型 ID 拼错。

类型四：429 限速。配额耗尽。

类型五：500 厂商问题。厂商内部错误。

类型六：响应格式异常。返回的 JSON 不符合 OpenAI 协议。

每种都有不同排查路径。

## chayuan-desktop 的诊断面板

设置 - 模型 - 厂商 - 测试连接。

点击后 chayuan-desktop 跑一遍。

第一步。DNS 解析厂商域名。失败说明 DNS 配置或网络问题。

第二步。TCP 连接 443 端口。失败说明防火墙或路由问题。

第三步。HTTPS 握手。失败说明证书或 TLS 问题。

第四步。GET /v1/models。失败说明认证或路径问题。

第五步。POST /v1/chat/completions（minimal payload）。失败说明账户或额度问题。

每步都给详细错误信息。

## 网络问题排查

某些政企内网代理只允许特定域名。chayuan-desktop 设置里能配 HTTP 代理。

如果用户机器走特定 VPN 才能访问外网。chayuan-desktop 配置里能开 跟随系统代理。

某些 DNS 污染场景。chayuan-desktop 内置自定义 DNS（如 1.1.1.1、114.114.114.114）作为 fallback。

## Key 排查

401 是最常见。常见原因。

Key 复制时多了空格。chayuan-desktop 自动 trim。

Key 过期或被重置。让用户去厂商后台确认。

Key 没绑定支付方式（OpenAI 新账户）。让用户充值。

Key 类型错（API Key 跟 Session Key 不同）。chayuan-desktop 的设置里写明每个厂商需要哪种 Key。

## 模型 ID 排查

404 通常是 ID 拼错。

OpenAI 的 gpt-4 vs gpt-4o vs gpt-4-turbo。

Anthropic 的 claude-3-5-sonnet-20241022 vs claude-3-5-sonnet-latest。

不同厂商命名规则。chayuan-desktop 的下拉菜单避免拼错。但用户自定义模型容易出错。

## 限速排查

429 + Retry-After header。chayuan-desktop 自动按 header 等待。

429 但无 Retry-After。chayuan-desktop 用指数退避策略。

429 持续频发。说明账户实际配额低。chayuan-desktop 提示用户升级 Tier 或加 Key。

## 5xx 排查

厂商内部错误。chayuan-desktop 自动重试 1 次。仍失败走 fallback 链。

某些 5xx 跟特定模型相关（比如 Claude-3 偶尔 529 overloaded）。chayuan-desktop 临时降权该模型。

## 响应格式排查

某些私有部署的 OpenAI 兼容服务返回字段缺失（比如没有 usage 字段）。chayuan-desktop 容错。能解析的解析，不能解析的用默认值。

某些服务把 content 包在 extra_body 里。chayuan-desktop 适配某些常见变体。

## 详细日志

chayuan-desktop 设置 - 调试 - 详细日志。开启后所有请求和响应（脱敏 Key 后）写入日志文件。

```
[2026-05-10 14:23:45] POST https://api.openai.com/v1/chat/completions
  Headers: Authorization: Bearer sk-***...***xyz
  Body: {"model":"gpt-4o","messages":[...]}
[2026-05-10 14:23:46] Response 200
  Body: {"choices":[...]}
  Latency: 1234ms
```

排查时把日志发给开发者。

## 国产化场景

国产厂商接入失败常见。

域名错。dashscope.aliyuncs.com vs dashscope.aliyun.com，写错路径。

接入鉴权方式特殊。某些厂商用阿里云签名 v3 算法不是 Bearer Token。chayuan-desktop 内置常见厂商的鉴权适配。

## chayuan-server 的对应

chayuan-server 模式下日志更集中（全用户共用一份服务端日志）。chayuan-desktop 单机日志只在本机。

## WPS 加载项

chayuan-wps 在 WPS 里调用失败时弹诊断信息。员工能 复制错误码 给 IT 排查。chayuan-desktop 的诊断面板能直接打开。

## 总结

模型接入失败排查是 chayuan-desktop 在工程可维护性上的关键。免费开源的AI软件 接入十几家厂商必然遇到接入问题。chayuan-desktop 的诊断面板 + 详细日志 + 错误分类让 排查 是看面板就能定位的事。
