# 临时禁用某个模型 不删配置只下线的开关

chayuan-desktop 桌面单机版的模型网关支持 临时禁用 某个模型。配置不删，只是从模型选择器隐藏。这一篇讲。

## 场景

场景一。某厂商正在维护，调用都失败。临时禁用避免每次默认走它。

场景二。某模型最近表现差（比如新版本退化）。临时禁用回滚到旧版本。

场景三。预算紧张。先禁用贵的（GPT-4），只用便宜的（Qwen-Turbo）。

场景四。账户被限制。临时禁用避免重复触发。

每种场景都不希望删配置（删了麻烦再加）。

## 禁用的开关

每个模型卡片有 enabled 字段。

```yaml
id: gpt-4
enabled: true
```

设置 - 模型 - 全部模型 表格里每行有 启用 切换。

## 禁用的效果

UI 上。模型选择器里不显示这个模型。当前选了它的会话切回默认 chat 模型。

API 调用。如果某个上层应用代码硬编码了禁用的模型 ID，chayuan-desktop 网关返回 model disabled 错误。

fallback 链。链路里如果包含禁用的模型，跳过它直接走下一个。

预算预估。禁用的模型不参与统计。

## 禁用的范围

按模型禁用。最常用。

按厂商禁用。某厂商整体不可用。chayuan-desktop 设置里能 一键禁用 OpenAI 全部模型。

按 Key 禁用。多 Key 配置中某个 Key 暂停使用。

按类别禁用。比较少用。

## 自动禁用机制

chayuan-desktop 内置自动禁用。

模型连续失败 N 次，临时自动禁用 30 分钟。30 分钟后探测恢复。这是健康检查的一部分。

预算超限的厂商或模型自动禁用本月剩余时间。下个月自动恢复。

被自动禁用的模型 UI 显示 已临时下线，原因 X。

## 用户手动覆盖

某模型被自动禁用但用户确认要用。

UI 提供 强制启用 按钮。chayuan-desktop 取消自动禁用，让用户尝试。

如果还是失败 chayuan-desktop 弹错误提示，用户决定再试还是放弃。

## 禁用 vs 删除

禁用。配置保留，只是不可用。一键启用恢复。

删除。配置完全删除。重新启用要重新填 Key 和参数。

chayuan-desktop 推荐 短期不用就禁用。删除是 永远不用 的语义。

## 禁用的导出导入

chayuan-desktop 配置导出（备份用）包含每个模型的 enabled 状态。导入时还原。

## 禁用的可视化

chayuan-desktop 设置 - 模型 - 状态总览。

```
启用模型：23 个
禁用模型：7 个
  - gpt-4 (用户禁用)
  - gpt-3.5-turbo (已弃用)
  - claude-2 (已弃用)
  - qwen-turbo (临时下线: 连续失败)
  ...
```

让用户清晰看到模型状态分布。

## 国产化场景

某些国产厂商策略调整、账户冻结、合规审查。chayuan-desktop 的临时禁用让用户能快速响应。比如 某厂商发了风控通知 用户先禁用，等通知解除再启用。

## chayuan-server 的对应

chayuan-server 多用户场景下禁用是企业级管理（管理员禁用，所有用户都不能用）。chayuan-desktop 单机版用户级禁用。

## WPS 加载项

chayuan-wps 在 WPS 里挑模型时不显示禁用的模型。如果之前选的是被禁用的，WPS 自动切回默认模型。

## 总结

临时禁用模型是 chayuan-desktop 在工程灵活性上的小但实用功能。免费开源的AI软件 让用户对模型生效有细粒度控制。chayuan-desktop 的禁用 + 自动禁用 + 用户覆盖 三层让模型管理在工程上灵活。
