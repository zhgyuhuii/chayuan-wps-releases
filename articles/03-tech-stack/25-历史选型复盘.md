# 哪些库被替换了 一份察元AI历史选型的复盘清单

chayuan-desktop 桌面单机版从早期版本到 v3.0 一路演化，期间换过若干技术栈和库。这一篇做一份复盘清单，记录哪些被换掉、为什么。给同行做参考，也是工程实诚的体现。

第一项：Electron 换 Tauri。chayuan-desktop 早期某个版本基于 Electron，v2.x 时代换成 Tauri 1，v3.0 升 Tauri 2。换 Electron 的理由前面讲过：体积、内存、启动速度三件事。这次替换是 chayuan-desktop 工程上最大的一次重写，但收益也最明显。

第二项：Vue 换 React。早期 chayuan-desktop 前端用 Vue 2。后来重构成 React 18，再升到 React 19。换 Vue 的理由是 团队 React 经验多 + 流式 UI 在 React 18+ 的并发渲染下表现更好 + 生态库（Tanstack Query、Zustand）更成熟。换框架重写的工作量也不小，但是分阶段完成，有过渡期共存。

第三项：LangChain 换自家代码。早期某个版本用 LangChain 做 RAG 编排和工具调用。后来重写成自家 retrieval/query 模块加 tools_factory 模块。换的理由是 LangChain 的抽象错位、版本不稳、依赖膨胀、性能不透明。重写让代码量增加但可控性大幅提升。

第四项：Webpack 换 Vite。前期前端构建用 Webpack。后来换 Vite。换的理由是 dev mode 体验和生产构建速度。Webpack 仍然是优秀工具，但 Vite 在新项目上更顺手。

第五项：Postgres 备选换 SQLite。早期评估过 Postgres + pgvector 作为存储。后来确定 SQLite + sqlite-vec 是单机版最佳。Postgres 的内存占用和服务管理对单机版不友好。

第六项：standard logging 换 loguru。早期日志用标准库。后来换 loguru，因为 API 友好。

第七项：requests 换 httpx。早期 HTTP 客户端用 requests，但 requests 不支持 async。后来换 httpx，原生支持 async，跟 FastAPI 的 async 架构契合。

第八项：fastapi 没换。FastAPI 从早期用到现在没换，因为它一直是 Python web 框架的最佳选择。

第九项：Tesseract 换 RapidOCR。早期 OCR 用过 Tesseract，中文精度不够。换成 RapidOCR-ONNX，中文精度大幅提升。

第十项：FAISS 换 sqlite-vec。早期向量库评估过 FAISS（Facebook 的向量库）。FAISS 是文件嵌入式但 API 不友好，部署起来不如 sqlite-vec 自然。换之后维护成本下降。

第十一项：openai 库换自家网关。早期模型调用用 openai 官方 SDK。后来重写成自家 httpx 加协议归一化的网关层。原因是 openai SDK 跟其他厂商的 SDK 不一致，要统一管理 18+ 家厂商的协议差异，自家网关更灵活。

第十二项：sentence-transformers 换 ONNX 直推。早期嵌入计算用 sentence-transformers 库。它依赖 PyTorch，包大。换成 ONNX Runtime 直接推 bge-m3-onnx，体积大幅缩减。

第十三项：alembic 没换。schema 迁移用 alembic 一直没换。它是 SQLAlchemy 生态的标准工具。

第十四项：pytest 没换。测试框架 pytest 一直没换。它是 Python 测试的事实标准。

第十五项：pnpm 替换过 npm。前端包管理早期用 npm，后来换 pnpm。pnpm 的 workspace 管理对 monorepo 友好，磁盘占用低。这是 chayuan-desktop 跟 chayuan-wps、chayuan-server 三个仓库共享时的默认。

第十六项：Vitest 替换过 Jest。前端测试早期用 Jest，后来换 Vitest。Vitest 跟 Vite 集成原生，速度快。

第十七项：Tailwind v2 升 v3。从 v2 升 v3 是无痛升级，主要是 JIT 模式带来的开发体验提升。

第十八项：Pydantic v1 升 v2。从 v1 到 v2 有 API breaking change，chayuan-desktop 一次性迁移完成。v2 的性能和 typing 优势明显。

第十九项：标准 SQLAlchemy 1.4 升 2.0。chayuan-desktop 跟着 SQLAlchemy 大版本升级，主要受益于 async 原生支持。

第二十项：早期评估过的方案。Electron + Vue + LangChain + Postgres + FAISS + Tesseract + openai SDK，这套组合是 chayuan-desktop 早期某次评估的方案。最终全部换成现在的栈。每一次换都有具体理由。

WPS AI 插件 chayuan-wps 的技术栈相对稳定（Vue 3 + Vite + TypeScript），变化没有 chayuan-desktop 这边多。

技术栈演化是开源项目的常态。免费开源的AI软件 不应该被早期决策锁死，发现更合适的工具就该换。chayuan-desktop 的这份复盘清单是工程上 不固执 的具体体现。
