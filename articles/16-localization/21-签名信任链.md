# 国产化支持的运行时签名与信任链

chayuan-desktop 桌面单机版的运行时签名和信任链。这一篇讲。

## 签名的意义

软件签名。证明软件来源可信，未被篡改。

OS 在安装或运行时校验签名。不通过的拒绝。

党政军场景对签名严格。

## 几种签名

OS 包签名。

deb 包：dpkg-sig 或 reprepro。

rpm 包：rpm --addsign。

msi（Windows）：Authenticode。

dmg（macOS）：Apple Developer ID。

代码签名。

二进制本身的签名。Windows 和 macOS 强。

## chayuan-desktop 的签名链

链路。

第一。开发者本地编译生成二进制。

第二。CI/CD 用 chayuan 公司私钥签名。

第三。发布到镜像（含签名）。

第四。用户下载后 OS 校验签名。

第五。chayuan-desktop 启动时再次校验自身二进制。

第六。chayuan-desktop 加载子模块（mcp 工具、模型）前校验。

层层信任。

## 公钥分发

chayuan-desktop 的公钥发布。

公司官网。

GitHub releases。

国产 OS 应用商店（chayuan-desktop 上架后）。

某些政企的内部分发渠道。

用户首次安装时验证公钥。后续更新自动用同一公钥校验。

## 国密算法签名

某些政企场景要求国密算法（SM2 + SM3）。

chayuan-desktop 的国密签名链是路线图。

当前主流签名用 RSA-2048 + SHA-256。已经满足大部分需求。

## 信任链的断开处理

某 chayuan-desktop 二进制签名校验失败。

可能原因。

被恶意篡改。

下载过程出错。

公钥不匹配（升级时换公钥）。

OS 提示 软件签名无效，拒绝运行。

用户重新下载或检查公钥。

## 自签名场景

某些政企内部部署。chayuan-desktop 用 政企内部 CA 签名。

```
chayuan-desktop 配置：
  signature_authority: 公司 CA 公钥
```

只接受公司 CA 签名的版本。chayuan 官方版被拒。

防止员工私自装非官方版。

## 第三方组件签名

chayuan-desktop 用的第三方库（llama.cpp、ONNX Runtime 等）也有自家签名。

链路。

第三方维护者签自己的库。

chayuan-desktop 编译时把第三方库内嵌。

最终 chayuan-desktop 二进制由 chayuan 签名（包含内嵌第三方）。

用户校验 chayuan 签名即可。

## 模型权重的校验

模型权重不签名（模型大文件）。但有 SHA256 哈希。

```
bge-m3-onnx.zip 
  SHA256: 89af...
```

chayuan-desktop 下模型时校验哈希。不一致重下。

## 升级的信任

升级链。

chayuan-desktop 启动时检查 update.chayuan.com（或内网镜像）。

发现新版。下载升级包。

校验签名。校验通过应用升级。

校验失败回滚。

避免恶意中间人替换升级包。

## 国产化场景

党政军场景对软件信任链严格。chayuan-desktop 的签名 + 公钥分发 + 校验满足。

某些场景要求 国产 CA 签名。chayuan-desktop 路线图含国密 SM2 签名 + 国家 CA。

## chayuan-server 的对应

chayuan-server 同样需要签名和信任链。chayuan-desktop 的工程经验复用。

## WPS 加载项

chayuan-wps 是独立加载项。也有自家签名。WPS 安装加载项时校验 chayuan-wps 签名。

## 总结

运行时签名与信任链是 chayuan-desktop 在政企部署上的工程基础。免费开源的AI软件 让 软件可信 是采购的硬要求。chayuan-desktop 的多层签名 + 公钥分发 + 国密路线让信任链工程可控。
