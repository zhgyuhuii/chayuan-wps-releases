# 全模型支持的真正用法 多泳道无上限的模型对抗

chayuan-desktop 桌面单机版的模型对抗（Arena）功能让用户同时给多个模型发同一句话，并行回答比对。这一篇讲。

为什么要模型对抗。每家模型有自己的擅长。GPT-4o 通用强。Claude 3.5 推理深。文心擅长中文公文。通义擅长技术。让用户挑模型时光看广告不准，亲眼看到对比才有判断。

对抗界面。chayuan-desktop 主界面顶部有 模型对抗 入口。点开新建一组对抗。每组分多 泳道。每泳道一个模型。统一发送一句话，所有泳道并行回答。

无上限多泳道。chayuan-desktop 不限制泳道数。理论上同时跑 10、20、30 个模型都行。实际限制是限速和成本（前面文章讲过）。

场景。

场景一：选最佳模型。问某类问题，看哪个模型回答最满意。

场景二：风格对比。同一 prompt 看不同模型的写作风格差异。

场景三：精度对比。给一组测试集让多个模型回答，人工评分谁更准。

场景四：成本性能权衡。看延迟、token 数、成本。

UI 设计。

每泳道独立流式输出。同时看多个回答增长。

每泳道独立 metadata：模型名、延迟、token 数、成本估算。

允许给某个泳道点 喜欢，多次累计形成 ELO 排名。

允许导出对比为 markdown 报告。

并发实现。chayuan-desktop 的 sidecar 用 asyncio 并发调多个厂商 API。每个 API 调用独立 task。一个泳道失败不影响其他。

模型对抗导出。一键导出整组对抗为 markdown 文件。含原 query、每模型回答、评分、时间戳。

历史。所有模型对抗记录在 CHAYUAN_ROOT/data 的 arena_records 表。后续能查 上次跟豆包对比 GPT-4o 谁赢。

ELO 排名。chayuan-desktop 的简易 ELO 实现：每次对抗用户给某个模型 喜欢，那个模型 +10 分，其他不变。多次累积形成排名。

实战意义。某个团队选默认 chat 模型时跑一周 arena，把日常问题问几次每天，最后看 ELO 排名决定。这种 数据驱动选模型 比 看广告 准。

国产化支持下的对抗。chayuan-desktop 的对抗在 国产 vs 海外 场景下有特殊意义。让客户看到国产模型的真实水平，加强信心。

WPS AI 插件 chayuan-wps 当前在 WPS 里没有对抗界面（路线图上）。模型对抗主要在桌面客户端用。

多泳道无上限的对抗是 chayuan-desktop 在多模型时代的核心能力。免费开源的AI软件 不偏向特定厂商，让用户用数据说话。chayuan-desktop 的 arena 让 全模型支持 这件事真有用。
