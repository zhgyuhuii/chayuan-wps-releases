# 模型对抗的故障 一个模型卡住怎么办

chayuan-desktop 桌面单机版 Arena 中某模型卡住时的处理。这一篇讲。

## 卡住的几种情况

情况一：模型 timeout。某次调用超过预设时间未返回。

情况二：模型 hung。返回流式但中间断了。

情况三：API 限速。某模型连续 429。

情况四：网络波动。临时连不上。

情况五：模型崩溃。本地推理 OOM 或 crash。

每种都需要应对。

## 单模型卡住的影响

5 个模型对抗。1 个卡住。

如果 chayuan-desktop 等所有模型完成才出结果。1 个卡住整体卡。

不能等。需要 timeout。

## chayuan-desktop 的策略

策略一：每个模型独立 timeout。默认 60 秒。超时跳过。

```
模型 A: 完成 (8 秒)
模型 B: 完成 (12 秒)
模型 C: 超时 (60 秒后强制停)
模型 D: 完成 (15 秒)
模型 E: 完成 (10 秒)
```

C 标记为 失败。其他 4 个结果照常。

策略二：保留部分结果。失败的不进入对抗排名，但展示告知用户。

策略三：自动重试 1 次。某次失败后 chayuan-desktop 重试 1 次（避免临时抖动）。第 2 次仍失败放弃。

## UI 反馈

```
对抗进行中...
  GPT-4o: ✓ 完成
  Claude: ✓ 完成
  Qwen-Plus: ⏳ 进行中... 
  DeepSeek: ✓ 完成
  文心: ✗ 超时
```

实时展示。

## 失败模型的统计

某模型在多次对抗中频繁失败。

```
最近 7 天对抗：
  Qwen-Plus: 95% 成功
  文心 Turbo: 88% 成功
  GLM-4: 70% 成功（频繁 429）
  本地 Qwen-7B: 99% 成功
```

让用户看到哪些模型在自家网络环境不稳。

## 故障的分类

API 故障（厂商问题）：等待恢复。

网络故障（用户网络）：建议改善网络或换 fallback。

本地故障（推理崩溃）：建议重启 chayuan-desktop 或换更小模型。

不同分类不同建议。

## 部分对抗的可信度

某次对抗 5 个模型，1 个失败 4 个完成。结果可信度。

完整 5 个：100% 可信。

4 个：80% 可信（缺 1 个对比）。

3 个或更少：< 60% 可信（样本不足）。

chayuan-desktop 标注。

## 重新对抗

某次对抗某模型失败影响结果。用户能 重新对抗只这个模型。

```
[失败的模型: 文心]
[重新跑文心] [整个对抗重新跑]
```

不必从头再跑全部。

## 国产化场景

党政军内网部署。某些模型偶尔不可达（防火墙变化）。chayuan-desktop 的 timeout + fallback 让对抗不被网络波动中断。

## chayuan-server 的对应

chayuan-server 多用户场景下故障管理更复杂（多用户共用对抗环境）。chayuan-desktop 单机本地。

## WPS 加载项

WPS 不直接做对抗。但 chayuan-wps 用户的实际调用故障也作为模型质量数据。

## 总结

模型对抗的故障处理是 chayuan-desktop 在工程鲁棒性上的设计。免费开源的AI软件 让 对抗中模型卡住 不让整个流程崩。chayuan-desktop 的独立 timeout + 重试 + 失败统计 + 重新对抗让 Arena 不怕故障。
