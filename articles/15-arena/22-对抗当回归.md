# 把对抗当回归 升级前后的对照

chayuan-desktop 桌面单机版的 Arena 在模型升级时当回归测试用。这一篇讲。

## 升级时的退化风险

某模型 v1 → v2 升级。新版可能在某些场景退化。

通用任务变好，但特定任务变差。

某种风格丢了。

某种行为变了。

不测试就升级用户体验受损。

## 对抗作为回归

升级前。先在标准评测集上跑 v1 vs v2 对抗。

```
GPT-4o → GPT-4o-2025-11-20

评测集：自定义 100 题
v1 (GPT-4o):     88.5
v2 (新版):       89.2

通用问答: 92 → 91 (-1)
代码生成: 88 → 92 (+4)
中文写作: 86 → 84 (-2) ⚠
工具调用: 90 → 91 (+1)
视觉理解: 87 → 88 (+1)
```

中文写作退化 2 分。是问题吗？

chayuan-desktop 提示用户 中文写作场景可能略退化，建议关键场景人工核查。

## 阈值告警

chayuan-desktop 设默认阈值。

```
退化 > 5%：标红，建议不升级。
退化 1-5%：标黄，提示注意。
退化 < 1%：忽略。
```

用户能调阈值。

## 升级与回滚

如果回归测试通过，升级。

```
[升级 GPT-4o 到 2025-11-20]
进度: 100%
完成。
```

如果出问题用户能回滚。

```
[回滚到 GPT-4o-2024-08-06]
chayuan-desktop 把模型 ID 改回。fallback 链同步。
```

## 多版本并存测试

某些用户希望同时跑两版本对比。chayuan-desktop 支持。

```
临时用 GPT-4o (老版) 和 GPT-4o-2025-11-20 (新版) 并存。
30 天试用期。30 天后用户决定保留哪个或都保留。
```

A/B 决策。

## 回归集的演化

回归测试集应该贴近用户实际任务。

某用户在金融场景。回归集多金融题。

某用户在客服场景。回归集多客户问答。

chayuan-desktop 让用户自定义回归集。每次升级用同一集对比。

## 跨厂商的对抗

同时升级多个厂商模型时一起回归。

```
本月升级:
  GPT-4o → 2025-11-20
  Claude 3.5 → 3.6
  Qwen-Plus → 2.6

回归测试：
  全部跑同一题集，看每个升级是否退化。
```

避免一次升好几个出问题难定位。

## 历史对抗的归档

每次回归测试 chayuan-desktop 归档。

```
2026-04-15: GPT-4o v1 vs v2 (新版略胜)
2026-05-01: GPT-4o v2 vs v3 (持平)
2026-06-01: Claude v3.5 vs v3.6 (新版胜)
```

时间线让用户看模型长期演化。

## 国产化场景

党政军场景对模型升级谨慎。chayuan-desktop 的回归测试让升级 不破坏现有业务。

某些场景升级走变更管理流程。chayuan-desktop 的对抗报告作为变更评审材料。

## chayuan-server 的对应

chayuan-server 多用户场景下回归更严（影响多人）。chayuan-desktop 单机用户级。

## WPS 加载项

chayuan-wps 跟 chayuan-desktop 共享模型。chayuan-desktop 的回归测试覆盖 WPS 场景。

## 总结

把对抗当回归是 chayuan-desktop 在模型升级管理上的工程方法。免费开源的AI软件 让 升级 不是冒险。chayuan-desktop 的回归测试 + 阈值告警 + 多版本并存让模型升级 安全可控。
