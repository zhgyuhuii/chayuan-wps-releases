# 模型对抗与生产 选模型的工程化

chayuan-desktop 桌面单机版 Arena 是选模型的工程化工具。这一篇讲怎么从对抗到生产决策。

## 对抗 → 生产的链路

链路。

第一步。对抗。多模型在测试集上跑。

第二步。分析。多维度评分。

第三步。决策。基于评分选默认模型。

第四步。试点。小范围用户先用新模型。

第五步。监控。实际使用中跟踪指标。

第六步。回归测试。新版本对比旧版本看是否退化。

## 决策矩阵

```
任务         首选        次选       本地兜底
chat         GPT-4o      Claude     Qwen-7B
code         Claude      DeepSeek   Qwen-Coder
中文写作      Qwen-Plus   文心       Qwen-7B
视觉         Qwen-VL     GPT-4V     Qwen-VL-7B
工具调用     GPT-4o      Claude     -
摘要         DeepSeek    Qwen-Plus  Qwen-1.8B
```

每个任务有首选、次选、本地兜底。chayuan-desktop 的 fallback 链按此配置。

## 试点策略

新模型上线先在 10% 用户试。

```
chayuan-desktop 设置 - 模型 - 试点：
  对话默认模型：
    90%: 现用 (GPT-4o)
    10%: 试点 (Claude 3.5)
```

收集数据 1-2 周。比较 2 组用户的满意度、留存、错误率。

良好则推广。

## 监控指标

生产环境监控。

模型成功率。

用户满意度（满意 / 不满意 反馈）。

平均延迟。

平均成本。

工具调用准确率。

幻觉率（用户标错的次数）。

每个指标定基线。突变时告警。

## 回归测试

新模型升级前。

跑既定的回归测试集（100 题）。

对比新旧版分数。

退化超 5% 警告。

```
回归测试结果:
  GPT-4o → GPT-4o-2025-11-20
  通用问答: 92% → 90% (-2%)
  代码生成: 88% → 89% (+1%)
  视觉理解: 90% → 92% (+2%)
  
总体: 持平或略升。可升级。
```

## 模型生命周期

新模型出来 → 对抗 → 评估 → 试点 → 推广 → 监控 → 旧模型下线。

完整生命周期管理。chayuan-desktop 给企业一个工程化框架。

## 选型的工程化原则

原则一：基于数据。不靠厂商宣传。

原则二：跟实际任务挂钩。基准测试 ≠ 真实场景。

原则三：考虑成本。质量好但太贵不实用。

原则四：保留 fallback。主模型挂时仍能服务。

原则五：定期重测。模型在变，对抗结果也在变。

## 国产化场景

党政军采购需要工程化论证。chayuan-desktop 的对抗 + 生产监控 + 回归测试是完整方法论。

## chayuan-server 的对应

chayuan-server 多用户场景下选型工程化更复杂（涉及全员）。chayuan-desktop 单机简化。

## WPS 加载项

chayuan-wps 跟 chayuan-desktop 共享模型选型。chayuan-desktop 选好了 WPS 跟着用。

## 总结

模型对抗与生产是 chayuan-desktop 的工程化方法论。免费开源的AI软件 让 AI 模型选型 不是技术人员的玄学，是工程项目。chayuan-desktop 的对抗 + 试点 + 监控 + 回归让选型可落地可衡量。
