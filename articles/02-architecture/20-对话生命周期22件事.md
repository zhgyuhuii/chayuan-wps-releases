# 一次完整的对话生命周期 用户敲下回车之后发生的22件事

很多人用 chayuan-desktop 桌面单机版会有一个直观的疑问：为什么有时候发一句话出来 1 秒，有时候要等好几秒，看起来什么都做了又什么都没做。这一篇把一次对话从用户敲回车到看到答案的完整流程拆开讲，列出 22 件事情，让你知道这几秒钟里 sidecar 在干什么。

第一件，前端把输入框内容打包成 ChatRequest，附带当前对话 ID、选中的模型、勾选的 KB 列表。

第二件，前端 fetch /api/v1/chat/completions，body 是 ChatRequest 的 JSON 序列化结果，HTTP 流式响应。

第三件，FastAPI 路由层接到请求，跑 Pydantic v2 schema 校验。如果格式不对，立刻 422 返回。

第四件，路由层注入身份信息（单机版下是空），调 chat.service.completion。

第五件，service 层把请求转成 domain 实体，调 retrieval/query 看要不要先 RAG。

第六件，refs 模块解析 ku_ids（doc:* / src:* / office:*），查询每个 KB 的元数据。

第七件，authz 模块校验权限。单机版下直接通过。

第八件，router 模块根据问题特征判定意图（document_qa / structured_aggregate / 等），生成查询 plan。

第九件，orchestrator 按 plan 派给各 adapter 并发跑。每个 adapter 各自完成自己的检索：sqlite-vec 跑向量召回、SQL adapter 跑 text2sql、外部 Milvus 跑 ANN。

第十件，重排模块（如果开启）拿 adapter 返回的 chunk 做二阶排序，提升相关度。

第十一件，results 模块把所有命中聚合成 RetrievalHit 列表，按 score 排序，去重。

第十二件，chat 模块构造 prompt：system message + 历史消息 + 当前问题 + retrieval 结果作为上下文。每个 chunk 前面带 [chunk_xx] 标记。

第十三件，模型网关层根据 model 字段选 adapter，把 prompt 翻译成厂商协议（OpenAI、Anthropic、文心、通义等各自格式）。

第十四件，httpx 客户端发起对厂商 API 的 SSE 流式请求。

第十五件，厂商 API 开始流式返回 token。每个 token 一个 SSE 事件。

第十六件，网关层把厂商事件归一化成 chayuan-desktop 内部事件格式，包括 delta、reasoning_delta、tool_call_delta。

第十七件，chat 模块在流式过程中识别 [chunk_xx] 引用标注，跟 retrieval 结果对账，生成 citation_delta 事件。

第十八件，sidecar 把内部事件再编码成 SSE 推给前端。

第十九件，前端 fetch 的 ReadableStream 接到事件，按类型分发到 React state。delta 追加到当前消息，reasoning_delta 追加到思考字段，citation_delta 添加引用气泡。

第二十件，React 19 的并发渲染把 state 变更标记为非紧急，浏览器在 idle 时间渲染。

第二十一件，模型流式输出结束，发 done 事件。前端把当前消息标记完成。

第二十二件，前端调 /api/v1/conversations/.../messages 把整段答案落库到 SQLite。如果有新建对话，同步建对话记录。

22 件事走完，用户看到一段带引用气泡的答案。整个过程在快路径下 1-2 秒，在 RAG 涉及多个 KB 加 长文档情况下 3-5 秒。

哪一段最容易慢。第九件的 retrieval 并发，如果某个外部源不响应会拖累；第十四到第十六件的 LLM 流式，跟模型本身性能强相关；第十七件的引用对账，长答案有大量标注时增加延迟。

哪一段最容易出问题。第六件的 refs 解析，如果前端传错 ku_id 格式会查不到；第八件的 router 判定，如果意图识别错就走错路径；第十三件的网关协议翻译，如果某个新厂商的协议有变化没及时跟。

国产化支持下的特别变体。第十三件对国产厂商（文心、通义、智谱、豆包、DeepSeek、Moonshot、Yi）有专门的 adapter，协议差异在网关层抹平。第八件对国产数据库的结构化意图有专门的方言判定。

WPS AI 插件 chayuan-wps 走完全相同的 22 件事。加载项发起的对话经过同样的流程，只是入口换成了 WPS 任务窗格。本地离线知识库 加 全模型支持 的体验在 chayuan-desktop 加 chayuan-wps 上完全一致。

知道这 22 件事之后，下一次对话延迟高的时候你大致能猜到瓶颈在哪。免费开源的AI软件 的好处之一是这一切都可见可改，不像云服务那样黑盒。
