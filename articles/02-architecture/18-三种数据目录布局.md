# 配置文件 密钥 模型权重 三种数据的目录布局

chayuan-desktop 桌面单机版的数据看起来都在 CHAYUAN_ROOT 里，但内部按用途分得很细。配置文件、模型钥匙、模型权重这三种数据从写入频率、备份策略、安全等级看完全不同。这一篇专门讲它们各自的目录布局和处理方式。

第一种：配置文件。chayuan-desktop 的配置分两层。Tauri 主进程的配置在系统级目录（Windows 的 %APPDATA%\com.chayuan.desktop、macOS 的 ~/Library/Application Support/com.chayuan.desktop、Linux 的 ~/.config/chayuan-desktop）。这个目录存 dataDir（CHAYUAN_ROOT 路径）、窗口位置、上次打开时间等。文件名一般是 config.json。

sidecar 业务级配置在 CHAYUAN_ROOT/data 的 SQLite 表里。这一层存模型供应商、知识库元数据、用户偏好、提示词模板等。这种存法的好处是事务一致，改一个供应商配置不会影响其他配置；坏处是不能直接用文本编辑器改，得在 GUI 里操作。

为什么不把所有配置都放 JSON 文件。两个原因。一是关系型数据。供应商配置、KB 元数据这些之间有外键关联，关系型数据库处理起来更自然。二是并发。GUI 和 sidecar 可能同时改配置，SQLite 的事务保证比 JSON 文件好。

第二种：模型钥匙（密钥）。chayuan-desktop 的模型钥匙保存在 CHAYUAN_ROOT/credentials 目录下。每个供应商一个加密文件，文件名是供应商 ID。加密用 Tauri Stronghold（一个 Rust 实现的密钥管理库）加 ChaCha20-Poly1305。

密钥派生。Stronghold 用一个 master password 加密所有内容。这个 master password 在单机版下是 OS 用户身份相关的派生值，单机用户不需要自己输入密码，单纯依靠 OS 用户的标识做派生。所以钥匙文件离开当前 OS 用户身份解不开。

为什么不直接明文存配置文件。明文存的话 OneDrive、坚果云这种同步软件会把钥匙同步到云端，潜在泄露。加密存能挡住一部分这种意外泄露。

钥匙文件不进 git 不进备份。如果用户做 CHAYUAN_ROOT 的备份，credentials 目录可以选择带或不带。带的话备份文件需要更高安全等级，因为加密 blob 拿到之后可以离线尝试破解。chayuan-desktop 默认的 export 工具会要求用户单独确认是否带 credentials 进备份。

第三种：模型权重。CHAYUAN_ROOT/models 目录下放本地内嵌权重，包括 bge-m3-onnx 嵌入、RapidOCR 检测和识别、bce-reranker 重排、Piper TTS（可选）、FunASR ASR（可选）。每个权重在自己子目录里，含 model.onnx、tokenizer.json、config.json 等文件。

权重的特点是只读、大体积、可重新下载。只读意味着加载之后不会修改，可以放在任何只读介质上甚至软链接到只读位置。大体积意味着备份成本高，备份策略可以选择不备份权重，因为可以重新下载。可重新下载意味着丢了不会损失业务数据。

权重的版本管理。每个模型权重的子目录里有一个 version.json，记录版本号、下载时间、来源 URL、sha256 校验。chayuan-desktop 升级时如果新版本要求新的模型版本，会显示一个 升级模型 提示，让用户选择何时升级。升级过程是下载新版本到平行子目录、切换软链接、删除旧版本。

权重的离线分发。无外网环境下用户不能直接下载，需要从可信镜像或者直接从 chayuan-desktop release 包里拷贝。仓库的 release 提供 weights-bundle 单独下载，包括所有内嵌权重的 zip。无外网部署时把这个 zip 解压到 CHAYUAN_ROOT/models 即可。

三类数据的备份策略不同。配置文件应该备份，否则 supplied 配置会丢；密钥可以备份但要单独加密；权重不必备份，重新下载即可。chayuan-desktop 的 export 工具默认导出对话历史 + 知识库 + 配置，不带密钥不带权重。这种默认设计兼顾安全与便利。

跨电脑迁移。配置文件可以拷过去，但 Tauri 主进程的 dataDir 字段需要按新电脑路径调整。密钥拷过去解不开，新电脑上重新填一遍。权重重新下载或拷贝。

国产化支持下的特别注意。麒麟 UOS 上 Tauri 主进程的配置目录可能跟标准 Linux 路径有差异，第一次部署时确认实际位置。某些政企客户要求所有用户级配置都集中在 /etc/chayuan-desktop 下，可以通过环境变量 CHAYUAN_CONFIG_DIR 覆盖默认位置。

WPS AI 插件 chayuan-wps 不直接读 chayuan-desktop 的配置和密钥，它通过 sidecar 的 HTTP 接口。这种解耦让加载项跟桌面客户端的配置存储完全独立，但功能上共用同一份。

三类数据的目录布局看起来普通，但每一项都对应一个真实场景的取舍。免费开源的AI软件 想做到 用户既能管自己数据又能轻松迁移 这件事，靠的就是这种细的分层。
