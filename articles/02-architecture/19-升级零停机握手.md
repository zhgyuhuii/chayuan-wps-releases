# 升级时如何零停机 老sidecar与新sidecar的握手

chayuan-desktop 桌面单机版的升级流程在用户体验上看起来很简单：装新版本，重启应用。但是从用户没察觉到的角度看，老 sidecar 和新 sidecar 之间有一段优雅交接，目的是不让正在进行的对话和写盘任务因为升级而丢。这一篇讲这段握手是怎么设计的。

先看升级的实际触发。用户装了新版本之后，新 Tauri 主进程启动时检测到当前 CHAYUAN_ROOT 还有老版本数据，schema 版本不一致，需要走升级流程。或者更常见的：用户主动重启 chayuan-desktop，安装包是新版本，新 Tauri 主进程启动时发现没有老 sidecar 在跑（因为重启之前用户已经退出），直接走全新启动加 schema 升级。

零停机的边界条件。chayuan-desktop 是单机应用，单进程后端。升级时严格说不可能完全零停机，因为新老 sidecar 不能同时绑同一个端口。所谓零停机的意思是 用户视角不感知后端切换，前端表现连续。

完整升级流程时序。第一步：用户接到升级通知，点击 立即升级。第二步：chayuan-desktop 弹一个对话框 准备升级，请保存当前对话。用户确认。第三步：前端把当前所有未保存对话调 sidecar 接口存盘。第四步：Tauri 主进程发 POST /api/v1/system/shutdown 给老 sidecar，老 sidecar 优雅退出（关闭数据库连接、写日志、释放资源）。第五步：Tauri 主进程下载新版本安装包到临时目录。第六步：Tauri 主进程关闭自己。第七步：自动启动安装程序，覆盖老版本。第八步：新版本主进程启动，spawn 新 sidecar。第九步：新 sidecar 跑 schema 迁移（alembic upgrade）。第十步：健康检查通过，主界面打开，恢复升级前的对话。

第三步的存盘很关键。如果不存就升级，正在流式接收的回答会丢失，已经发了一半的请求会断。chayuan-desktop 升级前会扫描所有打开的对话 Tab，把当前 state 全部刷到 SQLite，包括未完成的流式回答。

第九步的 schema 迁移。alembic 是 Python 的 schema 迁移工具，每个版本在仓库里有对应的 migration 文件。新 sidecar 启动时检查当前数据库版本，按时间顺序应用所有未跑过的 migration。这个过程要花几秒到几十秒不等，期间 health 接口返回 starting，前端的 splash 画面继续显示。

向后兼容的 schema 设计。chayuan-desktop 的 schema 演进遵循几条原则：只加不删（避免破坏老版本）、加新字段优先于改字段、需要删字段的话先标记 deprecated 至少一个版本再真删、字段名字一旦定下来不改。这种保守的策略让 schema 迁移大多数时候是无破坏性的。

破坏性升级的处理。少数情况下不得不破坏 schema，比如某个表彻底重新设计。这种升级在 release notes 里会明确标记 breaking change，要求用户先备份再升级。新 sidecar 启动时检测到老 schema，会显示一个 数据迁移 弹窗，让用户确认。

升级失败的回滚。如果新 sidecar 启动失败（比如某个依赖加载不了），Tauri 主进程会等 60 秒，超时后弹出错误对话框，提供 重试 或 联系支持 按钮。用户可以选择卸载新版本回到老版本，CHAYUAN_ROOT 数据如果在升级前备份了可以恢复。

未来的两个 sidecar 并存的可能。chayuan-desktop 当前的设计是一个进程一个端口，升级是先关后开。未来如果要做真正的零停机（比如长时间任务不能被打断），可能引入双 sidecar 模式：新 sidecar 启动到 62582，前端逐步从老 sidecar 切换到新 sidecar，老 sidecar 处理完所有进行中任务后退出。这种设计在企业级部署里更有意义，桌面单机版当前还用不上。

升级后的健康检查。新 sidecar 起来后前端做几件事：拉取最新的模型供应商列表确认未丢失、拉取知识库列表确认仍可访问、显示一个 升级完成 的轻提示告诉用户当前版本号。如果发现某项数据丢失，给用户一个 恢复备份 按钮指向最近的 export 文件。

国产化支持下的特别注意。麒麟 UOS 上的升级要走 deb 包流程，sudo dpkg -i 替换二进制。loongarch64 平台要确保新版本有龙芯架构构建。升级流程其他逻辑跟 x86 一致。

WPS AI 插件 chayuan-wps 在 chayuan-desktop 升级期间会断开 sidecar 连接。加载项里显示 后端正在升级，请稍候，等 sidecar 起来后自动重连。如果 chayuan-wps 加载项本身也升级，需要在 WPS 加载项管理界面单独操作，跟 chayuan-desktop 升级是两件事。

升级零停机这件事说到底是 让用户不感知到产品在变化。免费开源的AI软件 在升级体验上做得平稳，对长期用户的留存影响很大。chayuan-desktop 在这一段的工程投入不小，因为单机版没有 SaaS 那种 灰度发布 的工具，每次升级都是 all or nothing。
