# 本地离线知识库的数据落盘策略 SQLite WAL与目录布局

chayuan-desktop 桌面单机版的所有数据都在 CHAYUAN_ROOT 这棵目录树里。这一篇拆开看里面到底放了什么，每个子目录承担什么职责，SQLite 怎么配置才能让单机版扛得住高频读写。

CHAYUAN_ROOT 下面的核心子目录有八个。data 放对话历史、知识库元数据、用户配置等关系型数据。kb 放知识库的具体实例文件，每个 KB 有一个独立目录。vectors 放本地离线知识库 的 sqlite-vec 向量索引文件。models 放内嵌模型权重，包括 bge-m3-onnx、RapidOCR、bce-reranker。credentials 放加密后的模型钥匙。logs 放运行日志按天滚动。cache 放临时文件和解析缓存。uploads 放用户上传的原始文件副本。

data 目录里的核心 SQLite 文件叫 chayuan.db。schema 包括 conversations（对话）、messages（消息）、knowledge_bases（KB 元数据）、knowledge_refs（KB 引用记录）、settings（配置项）、audit_log（审计）等表。文件大小日常使用一两百兆，长期累积到几个 G 不少见。

WAL 模式。SQLite 默认是 rollback journal 模式，写操作会阻塞读。chayuan-desktop 启动时显式开 WAL（pragma journal_mode=WAL），写入先落到 chayuan.db-wal 文件，读不被阻塞，写吞吐量提升明显。WAL 的代价是多了 chayuan.db-wal 和 chayuan.db-shm 两个辅助文件，备份时要一起拷。

synchronous 设置。SQLite 默认 synchronous=FULL 每次写都 fsync，磁盘性能不友好。chayuan-desktop 用 synchronous=NORMAL，性能好且数据完整性可接受。极端情况下断电可能丢失最近几秒的写入，对桌面应用是合理代价。

vectors 目录。每个文档库有一个独立的 sqlite-vec 文件，比如 doc_技术资料.db。这个文件里有 vec0 表存放 chunk 向量，普通表存放 chunk 元数据。一个文档库几万个 chunk 大约几十兆，几十万 chunk 几个 G。多个 KB 各自存自己的文件，删除 KB 直接删对应文件。

为什么向量数据单独存文件而不是放主 chayuan.db。两个原因。一是隔离。某个 KB 数据损坏不会影响主库其他数据。二是性能。sqlite-vec 的 ANN 索引在大数据量下有特殊优化，单独文件让 vacuum 等维护操作不影响主库。

models 目录。bge-m3-onnx 在 embeddings/bge-m3-onnx/，RapidOCR 在 ocr/rapid-ocr/，bce-reranker 在 reranker/bce/。每个子目录里有 model.onnx、tokenizer.json、config.json 等文件。这些文件首启动时下载，后续更新走显式版本切换。

credentials 目录。模型钥匙加密后存到这里，加密用 Tauri Stronghold 加 ChaCha20-Poly1305。每个供应商的钥匙是一个加密 blob。文件名按供应商 ID 区分。密钥派生跟 OS 用户绑定，跨电脑拷贝解不开。

uploads 目录。用户拖到对话窗口或导入到 KB 的原始文件保存在这里。按 KB 分子目录，文件名带时间戳前缀避免冲突。如果建库时勾了 不保留原文件，这里只暂存解析过程，解析完删除。

cache 目录。临时解析中间产物、下载缓存、模型推理缓存。chayuan-desktop 不依赖 cache 持久化，删了不影响功能，自动重建。日常清理是 OK 的。

logs 目录。server.log 是 sidecar 主日志，按天滚动，保留 30 天。crash-*.log 是崩溃日志，单独保留 10 份。migration.log 是 schema 迁移日志。这些文件用户可以看可以删，但建议保留近期日志便于排查。

文件锁与并发。SQLite 在 WAL 模式下支持多读单写。chayuan-desktop sidecar 是单进程，内部用线程池跑 SQL 操作，不会有跨进程锁冲突。但如果用户把 CHAYUAN_ROOT 放在 OneDrive 同步目录，OneDrive 客户端会扫描数据库文件，可能造成短暂锁定。建议 CHAYUAN_ROOT 不要放在同步目录。

跨备份恢复。chayuan-desktop 内置了 export 工具，可以把 CHAYUAN_ROOT 整体打包成一个加密 zip。恢复时反向操作。这是单机版的官方备份方式。免费开源的AI软件 用户可以选择不依赖这个工具，直接拷贝整个目录也行。

国产化支持下的细节。麒麟 UOS 的某些版本上 SQLite 默认不开 WAL，需要 chayuan-desktop 显式设置。loongarch64 平台上 sqlite-vec 扩展加载有时需要专门构建，PyInstaller 包里附带了对应架构的 .so。

WPS AI 插件 chayuan-wps 不直接读写 CHAYUAN_ROOT，所有数据访问通过 sidecar 的 HTTP 接口。这种设计避免了多客户端并发写同一份 SQLite 的冲突。

数据落盘策略看似细节，决定的是单机版稳不稳。chayuan-desktop 在 SQLite 配置、目录布局、文件锁处理上的取舍，背后是大量的实际场景测试。
