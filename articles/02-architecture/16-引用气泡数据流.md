# 引用气泡的数据流 一次问答里 retrieval 与 chat 怎么对账

chayuan-desktop 桌面单机版的引用气泡是 察元智库 体验里最受关注的细节之一。每次 RAG 问答下面会浮一组气泡，每个气泡能展开原文段落。这种 答案对应原文 的对账机制不是前端瞎贴的，是 retrieval 模块和 chat 模块在后端做了一道精确的匹配。这一篇拆开看这个数据流。

先看理论上要做什么。LLM 拿到检索出来的若干 chunk 作为上下文生成答案，同时被要求标注每段答案对应哪些 chunk。前端拿到答案和标注，把标注渲染成可点击的气泡，点击展开原文。这件事看起来直接，但每一步都有坑。

第一步：retrieval 拿到 chunk 之后给每个 chunk 一个临时 ID。这个 ID 在当次请求里有效，比如 [doc:技术资料#chunk_42]。retrieval 返回的不只有文本，还有原文 metadata（页码、段落、文件路径等）。

第二步：chat 模块构造 prompt。把所有 chunk 文本拼成上下文，每个 chunk 前面带 ID 标记。比如：[chunk_42] 该系统的压力测试要求峰值 QPS 不低于 1000 ……。同时在 system prompt 里告诉 LLM：你必须在每段事实后面用 [chunk_id] 标注来源，未标注的事实不能出现在答案里。

第三步：LLM 生成答案。理想情况下答案里会有 [chunk_42] [chunk_57] 这种标注。实际情况是不同模型的标注合规度差异很大，有的几乎不标注，有的标错位置，有的把 chunk_id 写错。

第四步：后端解析标注。chat 模块在流式输出过程中识别答案里的 [chunk_xx] 模式，把它们抽出来作为引用信息。每个引用包含模型给出的 chunk_id 和它在答案里的位置。

第五步：跟 retrieval 的 chunk 列表对账。chat 模块把模型给出的 chunk_id 跟 retrieval 实际返回的 chunk 列表比对。匹配成功的 chunk_id 转成完整的引用元数据（含 ku_id、原文 metadata、信任度分数）。匹配失败的 chunk_id 丢弃（模型可能编造了不存在的 ID）。

第六步：推流给前端。引用信息以 citation_delta 事件形式跟正文 delta 混合推给前端。每个 citation 事件携带 引用占位符位置 和 完整引用元数据。

第七步：前端渲染气泡。前端在正文渲染时，根据引用事件的位置插入气泡组件。气泡显示文件名、页码、信任度。点击之后从引用元数据里取原文 chunk 文本，在右侧抽屉展开。

信任度分数怎么来。retrieval 返回的每个 chunk 带一个 score（向量召回 + 重排后的综合分）。chat 在写引用元数据时把 score 带过来。前端显示成 5 颗星或者百分比，让用户知道这个引用有多可信。

模型不标注怎么办。某些模型生成时不带 [chunk_xx] 标注。chat 模块在这种情况下做兜底：把答案文本跟 retrieval 返回的 chunk 文本做相似度匹配（基于 BM25 或简单的 fuzzy match），找到最可能的 chunk 关联。这种兜底召回率不如显式标注，但能保证 没有标注的答案 也有引用展示。

模型编造 chunk_id 怎么办。前面第五步的对账会把不存在的 chunk_id 丢弃。前端只显示真实存在的引用，避免误导用户。

跨 KB 引用。一次问答可能涉及多个 KB 的 chunk。每个 chunk_id 在 retrieval 返回时已经带 ku_id 前缀，对账时不会跨 KB 混淆。前端按 ku_id 给气泡分类显示，文档库的气泡是一种颜色，结构化的另一种，向量库的另一种。

引用气泡的展开内容。点开气泡之后右侧抽屉显示三个东西：原文 chunk 文本（高亮当前命中的部分）、来源元数据（KB 名、文件名、页码、段落）、跳转按钮（打开原文件到指定页或定位到指定段）。这种展示让用户能 一键回原文。

国产化支持下的对账细节。结构化数据库的引用展示 SQL 而不是 chunk。chat 模块对结构化引用有一套不同的渲染：summary 显示 SQL，展开显示表名、列名、行数、影响时间。前端按 kind 字段分流到不同渲染组件。

WPS AI 插件 chayuan-wps 共用同一套引用气泡数据流。加载项里的引用展示在 WPS 边栏，点击之后能跳到 WPS 文档对应位置或打开 PDF 阅读器到指定页。这是 chayuan-desktop 加 chayuan-wps 协同的最有价值场景之一：在 WPS 写报告时直接引用本地知识库，引用气泡能精确定位原文。

引用气泡这件事做得对，免费开源的AI软件 才有 可信 这一面。如果模型只生成漂亮的话术但答案对不上原文，用户用一阵子就不再信任。chayuan-desktop 在这条对账链路上做的工作，本质是把 AI 输出从 听起来对 拉回到 能查证。
