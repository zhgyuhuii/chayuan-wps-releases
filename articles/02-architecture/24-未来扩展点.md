# 未来扩展点 哪些位置预留了plugin接口

chayuan-desktop 桌面单机版的代码看一遍能发现很多 看上去不必要那么抽象 的设计。这些抽象不是过度工程，是给未来可能加的功能预留的接口。这一篇讲清楚目前已经预留好的几个扩展点，让二次开发者或者未来贡献者知道在哪里下手。

第一个扩展点是 知识源连接器。retrieval/query/adapters 目录下每个 adapter 是一个具体的源类型（document、structured、vector、office、web）。新增一种源类型只需要写一个新 adapter 实现 search、explain、citations 三个方法，注册到 router 即可。比如要加一个 邮件库 类型，让 chayuan-desktop 把 IMAP 邮件作为 KB，写一个 mail adapter 注册成 src:mail:* 命名空间就完了。

第二个扩展点是 模型厂商。模型网关层用 adapter pattern。新增一家厂商写一个 adapter 处理协议翻译，注册到模型卡片库。chayuan-desktop 当前接了 18+ 家，新增的成本是几十行代码加一份模型卡片清单。这种设计让 全模型支持 的范围可以持续扩展。

第三个扩展点是 工具。内置 30+ 工具是写在 tools_factory 模块里的。每个工具实现一个 BaseTool 接口，包括 name、description、args_schema、run 方法。新增工具只需要写一个新类、注册到工具表。OpenAPI 自动导入工具的功能直接基于这个接口，从 Swagger 文件生成 BaseTool 实例。

第四个扩展点是 文件解析器。document RAG 的解析链路在 knowledge_source/document 模块。每种文件格式（PDF、Word、Excel、PPT、Markdown 等）有对应的 parser。新增一种格式（比如 EPUB 电子书）只需要写一个 parser 实现 parse(file_path) 返回 Document 列表。

第五个扩展点是 嵌入模型。embedding 模块有一个抽象接口。本地内嵌的 bge-m3-onnx 是一个实现，外部厂商的 embedding 也是按这个接口接入。新增本地嵌入模型（比如换成 GTE 或者 自训练模型）只需要写一个 embedder 实现，注册到模型供应商即可。

第六个扩展点是 重排模型。rerank 模块跟 embedding 类似，有自己的接口。bce-reranker 是一个实现，未来可以加 cohere、jina 等。重排开关在 retrieval 层可配置。

第七个扩展点是 多模态。multimodal 模块当前覆盖 T2I、T2V、TTS、ASR 四个子模块。每个子模块有 adapter 接口，对接厂商或本地服务。新增一种多模态能力（比如音乐生成）按这个 pattern 写新模块。

第八个扩展点是 MCP 协议。MCP 客户端和服务端都在 mcp 模块。MCP 工具的注册逻辑跟内置工具共用一份接口，所以 MCP 工具自然成为 30+ 内置工具的扩展。新增 MCP 工具不需要改 chayuan-desktop 代码，只需要在 MCP server 端实现，chayuan-desktop 自动接入。

第九个扩展点是 governance。配额、审计、RBAC、PII 脱敏、数据血缘这些子模块各有接口。单机版下都退化为简化实现，企业版里可以替换成完整实现。这种退化设计让两套形态共用一份代码。

第十个扩展点是 评估模块。eval 子模块支持 KB recall 评估。未来可以加更多评估类型，比如 LLM 生成质量评估、工具调用准确率评估、长链推理评估。每种评估有自己的接口，结果统一输出到 eval-report 目录。

第十一个扩展点是 前端组件。前端 UI 在 chayuan-client 仓库，按功能模块组织。每个对话区、KB 选择器、模型对抗、设置页都是独立组件。新增一种 UI 形态（比如多面板分屏对话）按 React 组件 pattern 写新组件即可。

第十二个扩展点是 部署形态。chayuan-desktop 当前主要是单机桌面，但代码兼容多用户、共享后端、systemd 托管多种形态。新增部署形态（比如 docker 部署、k8s 部署）只需要在 packaging 目录加部署脚本和配置。

预留接口的代价。每个抽象接口比直接实现多一些代码，初期看冗余。但每次新增功能时这些接口的回报很明显。chayuan-desktop 的演进速度比同类产品快的部分原因，就是这些预留扩展点的存在。

什么时候不该用扩展点。如果某个功能预期只用一次，比如某个临时的运营脚本，就不应该塞进 adapter 接口。免费开源的AI软件 的扩展性是为了长期价值，不是为了 看起来抽象。代码组织的判断永远在 需要灵活 和 不要过度 之间找平衡。

WPS AI 插件 chayuan-wps 通过 sidecar 调用所有上述扩展点，加载项侧不需要改代码就能利用 chayuan-desktop 的新功能。这种 后端扩展前端自动受益 的链路设计，让两个产品的演进松耦合。
