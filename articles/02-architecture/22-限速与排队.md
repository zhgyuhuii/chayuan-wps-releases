# 全模型支持下的限速与排队 单机版的内置worker pool

chayuan-desktop 桌面单机版连了多个厂商之后，问题来了：你一台电脑同时跑几个对话，每家厂商的 RPM 限速怎么不被触发；你接了本地 Ollama 跑 7B 模型，多个对话怎么排队不至于卡住整个 GUI。这一篇讲清楚 chayuan-desktop 的限速与排队机制。

先看厂商限速的差异。OpenAI 给一般账户的限速是 60 RPM，付费账户更高。Anthropic 类似数量级。国内厂商比如 DeepSeek、智谱、文心都有自己的限速规则，付费层级越高限速越宽松。本地推理服务（Ollama、vLLM）的限速是单卡能力，通常单时间一两个并发。

chayuan-desktop 的限速策略。每个供应商有一个 worker pool，限制并发数。默认 OpenAI 这种厂商 pool size 是 10，国产厂商默认 5，本地推理默认 1。这些值在设置里可调。pool 满了的请求进队列等。

队列策略。chayuan-desktop 的内部 worker pool 用 asyncio.Semaphore 实现。每个请求 acquire 一个 slot，处理完 release。队列长度无限制，但前端会显示 在排队 状态告诉用户。

退避策略。如果厂商返回 429（限速），网关层做指数退避：第一次重试等 1 秒，第二次 2 秒，第三次 4 秒，最多三次。每次退避之前会给前端推一个 限速等待 状态事件，让用户知道在等什么。

按厂商不按模型限速。同一个厂商可能有多个模型（比如 OpenAI 的 gpt-4o、gpt-4-turbo、gpt-3.5），它们共享 RPM 限制。chayuan-desktop 的限速 pool 按 provider id 划分，不按 model id。

按 Key 不按厂商限速。同一个厂商可能有多个 Key（用户填了好几个 Key 做轮换）。chayuan-desktop 在限速时按当前请求选用的 Key 划分，每个 Key 独立 pool。这种细粒度让用户可以通过加 Key 来扩 pool。

本地推理的特殊处理。本地 Ollama 默认只能跑一个对话，第二个等。chayuan-desktop 把本地推理 provider 的 pool size 设为 1，避免同时给 Ollama 推多个请求触发 OOM。如果用户的机器有多块 GPU 或者跑了多个 Ollama 实例，可以手动调高 pool size。

embedding 计算的并发。本地嵌入跑在 ONNX Runtime 上，CPU 多核 batched 处理效率最高。chayuan-desktop 的 embedding 模块默认 batch size 32，按 OS 核数自动并发。批量入库时 embedding 是瓶颈，单条入库则不是。

RAG 检索的并发。一次问答涉及多个 KB 时，orchestrator 并发派给 adapter。每个 adapter 内部各自有自己的并发控制，比如 sqlite-vec 单进程读，外部 Milvus 走 gRPC 连接池。整体并发上限按 sidecar 启动时的 OS 核数和内存动态调整。

工具调用的并发。LLM 一次回合可能调多个工具。chayuan-desktop 把这些工具调用并发执行，每个工具的 adapter 有自己的并发限制（比如 web search 默认 3，rate limit 比较紧的工具默认 1）。

GUI 不阻塞。所有限速等待和排队发生在 sidecar 进程，前端只通过 SSE 接到状态事件展示，GUI 始终响应。这是异步架构的好处，不像同步 RPC 会让前端冻住。

排队过长的提示。如果某个请求在队列里等超过 30 秒，前端会弹一个提示 当前厂商繁忙，建议切换其他模型 或 取消重试。用户可以选一个低负载的厂商重试，避免硬等。

限速日志。每次限速触发都会写一条日志到 CHAYUAN_ROOT/logs/rate-limit.log，包括 provider、key id（脱敏）、时间、原因（队列等待 / 厂商 429 / 本地资源不足）。这个日志能帮你定位 哪家厂商最容易限速。

未来的优先级队列。当前队列是 FIFO，所有请求平等。未来可能加 优先级 字段，比如交互式对话优先于后台批量任务。这种优化在批量任务多的场景下有意义。

国产化支持下的特别处理。国产厂商的 RPM 限速规则各不相同，chayuan-desktop 维护了一份每家厂商的默认限速参数，用户基本不需要自己配。新接厂商时这份配置需要更新。

WPS AI 插件 chayuan-wps 的请求跟桌面客户端的请求共享同一份 worker pool。在 WPS 里发起一段长文写作时，桌面客户端的对话可能等队列。这个共享让 chayuan-desktop 整体的资源使用受限于 sidecar 一份配置，不会出现两个客户端各自打爆厂商。

限速与排队这件事在单用户场景下看起来不需要，实际只要你接了多家厂商加了几个 Tab 就开始遇到。免费开源的AI软件 把这一层做得稳定，用户体感才是 不卡。
