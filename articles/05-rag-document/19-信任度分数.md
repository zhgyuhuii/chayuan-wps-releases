# 引用气泡里的信任度分数是怎么算出来的

chayuan-desktop 桌面单机版的引用气泡上有一个 信任度 分数，5 颗星或者百分比表示。这个分数不是装饰，是给用户判断 这个引用有多可信 的。这一篇讲清楚分数怎么算。

先看分数的几个层次。

层次一：原始向量距离。query 向量跟 chunk 向量的 cosine 距离。范围 0-1。距离越小越相关。chayuan-desktop 把它转成 1 - distance 作为初始 score。

层次二：重排（rerank）后的分数。如果 KB 开了重排，bce-reranker 给每个候选 chunk 打分（0-1）。这个分数比向量距离更精准（因为重排模型考虑了 query 跟 chunk 的细粒度交互）。

层次三：综合 score。chayuan-desktop 把向量距离和重排分数做加权。默认权重是 30% 向量 + 70% 重排（经验值）。综合分数还是 0-1 范围。

层次四：归一化展示。给用户看的星级或百分比是综合 score。100% 是 5 星，80% 是 4 星，60% 是 3 星，以此类推。chayuan-desktop 通常显示分数大于 50% 的 chunk 给前端，太低分的过滤掉。

跨 KB 的分数比较。不同 KB 用不同嵌入模型，向量距离的尺度可能不同。chayuan-desktop 在同一查询的多 KB 结果聚合时做归一化：每个 KB 内 score 归一到 0-1，跨 KB 比较才有意义。

结构化 KB 的信任度。SQL 命中的 score 不是从向量距离来。chayuan-desktop 给 structured 来源的 chunk score=1.0（执行成功）或者 0（执行失败）。中间状态少见。这种 二元 score 跟向量来源混在一起时归一化处理。

向量库的信任度。外部 Milvus 等返回的相似度分数 chayuan-desktop 接受并归一。各家向量库的距离度量可能不同（cosine、L2、dot product），归一化按各自特征处理。

办公库 office:* 的信任度。跟 doc:* 一样基于向量距离 + 重排。

web 来源的信任度。web search 工具返回的搜索结果 score 来自搜索引擎的相关度排序。chayuan-desktop 把这个 score 直接用，归一到 0-1。

用户感知的信任度。前端给用户的 5 星 是综合 score 的简化展示，不暴露底层数学。但是用户能从星数判断 这个引用相关程度高不高。

低信任度的处理。某些命中的 chunk score 较低（比如 30%）。chayuan-desktop 仍把它喂给 LLM 作为上下文，但前端展示时星级低，用户能看到 这是相对弱相关的引用。

信任度跟答案准确率的关系。高信任度的引用通常意味着 chunk 跟 query 高度相关，模型基于此回答的准确率也高。但不绝对。模型可能从高信任度 chunk 里仍然误读，或者从低信任度 chunk 里却正确总结。信任度只是 检索阶段 的指标，不直接等于 答案对不对。

信任度的临界值。chayuan-desktop 默认过滤 score < 0.4 的 chunk 不喂给 LLM。这个阈值用户可以在 KB 设置里调。阈值高过滤更严，召回少；阈值低召回多但噪声多。

重排开关对信任度的影响。如果 KB 关闭了重排（为了速度或者节省资源），信任度只来自向量距离。这种 score 跟开重排比，区分度差。chayuan-desktop 默认开重排，关掉是用户主动选择。

跨问题的信任度对比。不同 query 的 score 不可比。比如 query A 的 top1 是 0.9，query B 的 top1 是 0.7，不能直接说 A 的回答更可信。score 只在同一 query 内有意义。

国产化支持下的信任度。中文 query 跟中文 chunk 的距离计算跟英文情况一致。bce-reranker 在中文上表现良好，重排后的 score 区分度不错。

调试信任度。开发者可以在 chayuan-desktop 的 trace 日志里看到每个 chunk 的原始向量距离、重排分数、综合 score。这些数据对调优 KB 检索精度有用。

WPS AI 插件 chayuan-wps 的引用气泡同样展示信任度星级。在 WPS 里写报告时用户能一眼看到 哪些引用最可信。

信任度分数是 chayuan-desktop 给用户的 检索可视化 信号。免费开源的AI软件 把检索这件事做得透明，用户对 AI 答案的信任不再是 黑盒就那样。chayuan-desktop 在这一面的工程化是体验差异点之一。
