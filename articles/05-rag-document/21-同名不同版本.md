# 同名文件不同版本的检索冲突 怎么避免拿到旧版

办公场景里同一份资料经常有多版本。合同 v1、v2、v3。产品规范 2024 版、2025 版。chayuan-desktop 桌面单机版的 KB 里如果同时存了多版本，检索时怎么避免拿到旧版是个实际问题。这一篇讲应对策略。

先看冲突的几种形态。

形态一：版本号在文件名里。比如 合同_v1.pdf 合同_v2.pdf 合同_v3.pdf 在同一目录。folder-sync 把三份都入库，每个版本作为独立 chunk。检索 合同条款 时三个版本的 chunk 都可能命中，模型综合可能误用旧版条款。

形态二：版本号在路径里。比如 \2024\预算.xlsx 跟 \2025\预算.xlsx。chayuan-desktop 也都入库，但路径不同的 chunk 容易区分。

形态三：版本号在内容里。文件名一样，文档第一页写了 版本号 v3.0。这种比形态一更难处理，因为外部看不到文件级别的版本差异。

形态四：完全替换。新版本直接覆盖了老文件路径。folder-sync 增量同步识别 hash 变化，自动用新版本覆盖旧 chunk。这种情况自动处理无冲突。

chayuan-desktop 当前的处理。

策略一：依赖 metadata。chayuan-desktop 把文件名、路径、修改时间作为 chunk metadata。检索时不主动按版本过滤，但前端展示引用气泡时会显示文件名和修改时间，让用户能看到 这是哪个版本。

策略二：用户主动归档。建议用户把旧版本文件移到 archive 目录，folder-sync 不扫这个目录。或者在 KB 里给旧版本 chunk 打 archived 标签，检索时默认排除。

策略三：版本号识别启发。chayuan-desktop 的 parser 可以从文件名提取版本号（v1、v2、2024、2025），写到 metadata。chunk 里也有版本号 metadata。检索时如果 query 暗示 最新版本，按 metadata 过滤选最新的。

策略四：modified_at 加权。chayuan-desktop 在 score 计算时可以给较新的 chunk 加权。这种 隐式偏向最新 让 多版本共存 时新版本优先命中。但用户问 旧版条款是什么样 时这种加权可能误导。

实际场景的最佳实践。

实践一：每次新版本发布时把旧版本文件后缀打 archive_。比如 合同_v1_archive.pdf。chayuan-desktop 的 folder-sync 默认不扫 archive_ 后缀。

实践二：给 KB 加 retention_policy。比如 doc:历史合同 KB 只保留终版，doc:草稿合同 KB 保留所有版本。两个 KB 检索时勾不同的。

实践三：重要资料用 终版 KB 单独管理。不混在大 KB 里。

实践四：检索时 query 明确版本要求。比如问 2025 版预算的内容 而不是问 预算的内容。chayuan-desktop 的 router 会从 query 里提取版本约束。

国产化支持下的版本管理。中国办公场景里版本管理常用 V1.0、V2.0 这种英文 + 数字格式，chayuan-desktop 都能识别。如果用 一稿、二稿、定稿 这种中文版本词，chayuan-desktop 也能识别（启发规则覆盖）。

如果你真需要严格版本控制。chayuan-desktop 不是版本控制系统。建议用专门的 DMS 或者 git 仓库管理版本，再把 终版 推到 chayuan-desktop 入 KB。这种 工具配合 比让 chayuan-desktop 既做检索又做版本管理更稳。

WPS AI 插件 chayuan-wps 在引用气泡里展示文件版本元数据（如果有）。用户在 WPS 写报告时看到引用是 v1 版本的内容会主动判断 这是不是最新版。

未来版本管理的可能。chayuan-desktop 路线图里有 chunk-level 版本字段 和 文档系列 概念，能让多版本共存时自动识别 最新有效版。当前还没实现。

同名文件不同版本是 chayuan-desktop 用户实际场景里的小坑。免费开源的AI软件 给用户工具，不强求所有用户的版本管理流程。chayuan-desktop 的应对是 提供 metadata 和过滤工具，让用户按自己流程做。
