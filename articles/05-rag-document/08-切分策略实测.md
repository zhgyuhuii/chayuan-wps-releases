# 本地离线知识库的切分策略 chunk_size与chunk_overlap实测影响

chayuan-desktop 桌面单机版的文档 RAG 链路里，切分（chunking）这一步直接影响检索精度。chunk_size 和 chunk_overlap 这两个参数怎么调，对最终命中效果差别很大。这一篇讲切分策略的实测影响。

先看 chunk_size 的含义。一段连续文本按多少 token 切成一个 chunk。chayuan-desktop 默认 512 token（约 1000 字符的中文）。可调范围 128 到 2048。

chunk_overlap 的含义。相邻 chunk 之间重叠多少 token。比如 overlap=50 意味着第二个 chunk 的前 50 token 跟第一个 chunk 的后 50 token 一样。chayuan-desktop 默认 50。

为什么要 overlap。避免重要句子被切到两个 chunk 中间，命中时只能拿到半截。overlap 让边界附近的信息在两个 chunk 都出现，至少有一个能完整命中。

chunk_size 大小的影响。

小 chunk（128-256）。每个 chunk 信息少，检索精度高（正好命中相关那一小段），但对模型的上下文片段也小，回答时可能缺少必要 context。适合 信息密度高 的文档（比如 FAQ、术语表）。

中 chunk（512）。chayuan-desktop 默认。平衡检索精度和上下文完整。覆盖大多数场景。

大 chunk（1024-2048）。每个 chunk 信息多，对模型 context 友好，但检索精度下降（一个 chunk 里有多个不同主题的内容，向量相关度被稀释）。适合 长篇叙述 文档（比如学术论文、长篇报告）。

实测对比。chayuan-desktop 在自家 KB recall 评估集上跑过测试。chunk_size 256 在精确问答上的 recall@5 是 0.85，chunk_size 512 是 0.91（最高），chunk_size 1024 是 0.83。这种 中等最优 在大多数 RAG 系统里都成立。

chunk_overlap 大小的影响。

无 overlap（0）。最节省存储和计算，但边界 chunk 信息不全。某些场景命中率明显下降。

小 overlap（50）。chayuan-desktop 默认。边界覆盖好，存储开销小。

大 overlap（100-200）。命中精度略好但存储和嵌入计算成本上升。chunk 总数增加。

实测对比。同样 KB，chunk_overlap 0 的 recall@5 是 0.87，overlap 50 是 0.91，overlap 100 是 0.92，overlap 200 是 0.92。说明 overlap 50 已经是性价比好的位置，再加收益微小。

切分策略的边界条件。

不要按字符数硬切。chayuan-desktop 的切分按 token 数（用嵌入模型的 tokenizer 估算），且优先在句子边界切，避免半截句子。这种 语义切分 比硬切准。

代码块不切。前面 markdown 文章里讲过，代码块作为一个不可分单元。

表格不切。markdown 表格作为一个单元。

特别长的段落。如果一段超过 chunk_size 很多（比如长 3000 token 没换行的段落），chayuan-desktop 按句子切，避免破坏语义。

特别短的段落。如果一段不到 chunk_size 很多（比如 100 token 的段落），chayuan-desktop 不会强制合并相邻段落。每段是独立 chunk，避免不同主题混淆。

chunk metadata 的传递。每个 chunk 携带原文的 heading 路径、页码、段落序号。这些 metadata 让检索结果有 上下文坐标。

不同文档类型的最佳切分参数可能不同。chayuan-desktop 当前用同一组默认值（512 + 50），用户可以在 KB 设置里调。某些用户对 学术论文 用 1024 + 100，对 FAQ 用 256 + 30。

切分策略改变后要不要重建索引。要。chunk 切分变了，每个 chunk 的边界变了，原索引的向量不再对应新 chunk。chayuan-desktop 让用户改完切分参数后必须触发重建。

chunk_overlap 跟去重的关系。overlap 让相邻 chunk 内容部分重复，检索时同一段内容可能命中两个 chunk。chayuan-desktop 在 results 模块做去重，避免给模型重复信息。

国产化支持下的中文切分。中文跟英文 token 化方式不同（一个汉字大致一个 token，英文一个单词大致一个 token）。chayuan-desktop 的切分按 token 数，中文跟英文实测效果接近。混合中英文文档也能正常处理。

WPS AI 插件 chayuan-wps 不直接控制切分参数。加载项里挑 KB 时按已有 KB 的设置走。要调切分参数得回到 chayuan-desktop 桌面客户端 KB 设置里改。

切分策略是 chayuan-desktop 文档 RAG 调优的关键参数。免费开源的AI软件 给用户调参的空间，配上默认的合理值，能覆盖绝大多数实际场景。
