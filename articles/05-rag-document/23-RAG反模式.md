# 文档RAG的常见反模式 把所有PDF直接糊进去

用 chayuan-desktop 桌面单机版做文档 RAG 的时候，用户经常踩同一类坑。这一篇汇总几个常见反模式，给上手 chayuan-desktop 的人避坑。

反模式一：把所有 PDF 都丢一个 KB。

错法。建一个 doc:全部资料 KB，把电脑上几千份 PDF 全部 folder-sync 进去。

为什么不行。KB 太大检索精度下降，不同主题 chunk 互相干扰；提问时要勾选所有 KB 容易混乱；删除某主题难。

正确做法。按主题、部门、时间等维度拆成多个小 KB。比如 doc:技术规范 doc:合同档案 doc:营销资料。提问时挑相关的几个。

反模式二：用文档库回答聚合问题。

错法。把销售台账 Excel 当文档库入库，问 上个月华南地区销售总额是多少。

为什么不行。文档库走向量召回，能找到包含相关字段的 chunk，但不会聚合数字。模型可能编一个数字或者数错。

正确做法。Excel 数据走结构化 KB（src:* 类型）。问聚合问题时 chayuan-desktop 的 router 自动调 text2sql。

反模式三：忽略 chunk_size 默认值。

错法。chunk_size 用默认 512 token 不管，但是文档是密集的术语表（每条 50 token）或者长篇散文。

为什么不行。术语表用 512 chunk 把多个无关术语揉一起。长散文用 512 切到半截上下文。

正确做法。术语表场景 chunk_size 调到 128-256。长散文调到 1024。chayuan-desktop 在 KB 设置里支持调。

反模式四：不开重排。

错法。某些用户为了节省 1 秒延迟关掉重排，但又抱怨检索精度低。

为什么不行。重排带来 10-15% 的精度提升，关掉之后检索质量明显下降。

正确做法。除非极度延迟敏感，建议开重排。

反模式五：文件命名混乱。

错法。文件名 a.pdf b.pdf c.pdf 或者全是 文档1 文档2 文档3。

为什么不行。引用气泡展示文件名时用户看不出哪份是哪份。

正确做法。文件命名要有信息。比如 2026Q1产品规划.pdf 比 doc1.pdf 强很多。

反模式六：没建 metadata。

错法。把所有文件直接拖到 KB，不打 tag 不分类不写描述。

为什么不行。KB 大了之后没法按属性过滤检索。

正确做法。每个 KB 起描述性名字，给文件加 author/department/confidentiality 等 metadata。folder-sync 时按目录路径自动推断。

反模式七：query 太短。

错法。问 销售。

为什么不行。一两个字的 query 信息量不够，向量召回模糊，命中范围广精度低。

正确做法。问完整句子。比如 上个月华南地区销售情况怎么样。

反模式八：忽略引用气泡。

错法。看到答案就直接采信，不点开引用气泡看原文。

为什么不行。AI 偶尔会误读 chunk 或者引用错位。引用气泡是验证 答案是否真有据 的工具。

正确做法。对重要问题点开几个引用气泡，确认原文真说了这个事。

反模式九：embedding 模型频繁切换。

错法。今天换 bge-m3，明天换 bce，后天换 GTE。每次都要重建索引。

为什么不行。嵌入模型切换不是看心情的事，每次重建几小时。

正确做法。选一个嵌入模型坚持用。换之前看清楚收益是不是值得重建代价。

反模式十：把 KB 当永久云存储。

错法。把所有重要文件只存在 chayuan-desktop 的 uploads 目录，不在别处备份。

为什么不行。chayuan-desktop 是 AI 助手不是备份系统。万一数据损坏或者卸载就丢了。

正确做法。原文件保留在原始位置（比如 NAS、网盘），folder-sync 入库到 KB。chayuan-desktop 的 KB 是 副本，不是 主存。

国产化支持下的额外反模式。

反模式十一：忽略国产 OS 的字体。麒麟 UOS 默认字体可能让某些 PDF 渲染异常，OCR 兜底也受影响。建议装 fonts-noto-cjk。

WPS AI 插件 chayuan-wps 上的反模式。在加载项里勾上所有 KB 一起检索，结果太杂乱。建议每次只勾相关的 1-3 个。

避开这些反模式之后 chayuan-desktop 的体验立刻不一样。免费开源的AI软件 给用户工具，但用对工具的方式靠用户自己学习。这份反模式清单是 chayuan-desktop 用户社区累积的经验。
