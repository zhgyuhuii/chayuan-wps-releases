# 本地离线知识库的最短路径 一份CSV五分钟出答案

很多人想用察元AI 桌面单机版处理一份本地的 CSV 数据但不知道从哪开始。这一篇用最直接的方式讲一遍：从 CSV 到回答，五分钟之内搞定。

场景设定。你手上有一份 sales.csv 文件，几百行销售数据，列包括订单号、客户名、产品、金额、日期、地区。你想问 上个月华南地区的总销售额是多少 这种问题。

第一种做法：当成结构化数据。这是最准确的做法。

打开 chayuan-desktop，点 知识库 - 新建知识库。类型选 结构化数据 / SQLite 嵌入式。给它起个名字，比如 销售台账。选择 sales.csv 文件，chayuan-desktop 会把它转成本地 SQLite 表。你可以预览字段名和类型，必要时调整（比如把 金额 列改成 numeric 类型）。点 创建，等几秒。

新建对话，挑模型，在 KB 选择器里勾 销售台账。问 上个月华南地区的总销售额是多少。chayuan-desktop 的 router 识别出聚合意图，调 structured adapter 跑 text2sql。生成的 SQL 大致是 SELECT SUM(金额) FROM sales WHERE 日期 BETWEEN '2026-04-01' AND '2026-04-30' AND 地区='华南'。AST 校验通过，执行，返回数字。模型用自然语言总结答案。引用气泡展示 SQL 和命中行数。

整个过程从 CSV 到答案大约三五分钟，主要时间花在 chayuan-desktop 解析 CSV 和你检查字段类型上。

第二种做法：当成文档库。这种做法适合 CSV 内容是 文本数据 而不是 数值数据 的场景。比如客户反馈、问卷、笔记摘录。

新建知识库，类型选 文档库 / 单文件上传。选 sales.csv，chayuan-desktop 把每行作为一个 chunk 入库。问 哪些客户买了产品 A，AI 在 chunk 里检索包含 产品 A 的行，引用气泡展示命中行。

这种做法的局限。如果你问 总销售额 这种聚合问题，文档库走不通，因为它只能找到包含答案的 chunk，不能 加总。所以纯数据问题应该走结构化 KB。

第三种做法：混合。某些场景两种都建。比如 sales.csv 是数据，但旁边还有一份 sales_explanation.docx 是数据说明。chayuan-desktop 支持你建两个 KB：sales.csv 走结构化，docx 走文档。问问题时勾上两个 KB，模型综合回答。

误区一：直接拖 CSV 到对话窗口。这样会触发文档库入库，纯数据场景不准。建议显式建 KB 选 结构化 类型。

误区二：CSV 列名是中文。中文列名能用，但 SQL 生成时会用反引号包起来。如果你的列名带特殊字符（空格、点），改成简单字母数字下划线更稳。

误区三：CSV 里数值带千分号或货币符号。比如 ¥1,234,567。chayuan-desktop 在解析时尝试自动转换，但不一定都能成功。建议导出 CSV 时纯数字格式，避免符号。

误区四：CSV 里日期格式不统一。比如有的 2026-04-01 有的 2026/4/1 有的 1日 4月 2026。chayuan-desktop 的 SQL 生成不能可靠处理混合格式，建议导出时统一日期格式。

误区五：超大 CSV。几十万行以上的 CSV 解析慢，建议分文件或者直接接外部数据库。chayuan-desktop 的结构化 KB 用 SQLite 存，几十万行能扛住，但更大数据建议接外部 PG 或达梦。

实际跑的命中率。我用一份真实的 sales.csv 跑过测试，简单聚合问题（总和、平均、最大值、最小值）命中率 95%+，多条件 WHERE 查询命中率 90%+，复杂 JOIN 跨表查询命中率 70-80%。这个表现对日常办公场景够用。

国产化支持下的 CSV。chayuan-desktop 在 CSV 编码上自动检测（UTF-8、GBK、GB18030）。中文列名和数据都能处理。如果遇到乱码，先用 Excel 打开 CSV 另存为 UTF-8 再导入。

WPS AI 插件 chayuan-wps 中可以挂同一份 sales.csv KB。在 WPS 表格里写报告时直接引用 销售台账 KB 的查询结果。这种工作流让数据分析跟报告写作贯通。

五分钟从 CSV 到答案 是 chayuan-desktop 给办公用户最直接的产品体验。免费开源的AI软件 想让 普通员工不靠 IT 支持就能用，CSV 这种入门场景必须做得简单。chayuan-desktop 在这件事上的设计是合格的。
