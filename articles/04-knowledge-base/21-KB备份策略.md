# 本地离线知识库的备份策略 单机版下用户怎么自己导出

chayuan-desktop 桌面单机版的 KB 数据完全在用户手里，备份这件事自然也是用户自己负责。这一篇讲清楚 KB 备份的几种方式和实操。

先看 KB 数据的物理位置。在 CHAYUAN_ROOT 目录下。doc:* 类型的 KB 数据在 vectors/doc_KB名.db（sqlite-vec 文件）和 uploads/doc_KB名/（原文件副本）。元数据在 data/chayuan.db 的 kb 表。office:* 类似。src:* 主要是连接配置在 data/chayuan.db 的 connectors 表，实际数据在外部系统不归 chayuan-desktop 备份。

最简单的备份方式：整体备份 CHAYUAN_ROOT。把整个 CHAYUAN_ROOT 目录用 zip 或 tar 打包到外置硬盘。这种 整体打包 最稳，所有数据加配置一并备份。缺点是体积大，每次全量。

备份前要做的事。第一步关闭 chayuan-desktop，确认 sidecar 退出。第二步等几秒让 SQLite WAL 文件 checkpoint。第三步开始拷贝。如果 chayuan-desktop 还在跑，SQLite 文件可能处于不一致状态，备份出来的可能损坏。

增量备份。如果 CHAYUAN_ROOT 太大每天全量不现实，用增量备份工具。Linux/macOS 上 rsync 或 borgbackup 的增量备份适合这种场景。Windows 上 Veeam 或 Duplicati 的增量也行。

chayuan-desktop 自带的 export 工具。设置 - 备份与导出 一栏可以导出指定 KB 或全部 KB 到加密 zip 包。这个 zip 包含 KB 元数据 + chunk 数据 + 向量索引 + 原文件副本，但不含模型权重和钥匙。文件名带时间戳。

只备份关键 KB。如果某些 KB 重要某些不重要，可以只对重要 KB 用 export 工具。chayuan-desktop 的 export 支持选择 KB 列表。

云端备份的注意。某些用户喜欢备份到 OneDrive、坚果云、阿里云盘等。这些云盘加密程度有限，建议先用 export 工具加密后再上传。或者用 Cryptomator 这种工具加密后再同步。

git 仓库备份。某些用户把 CHAYUAN_ROOT 放在一个 git 仓库里，定时 commit。这种方式对小型 KB 可行，但 vectors/*.db 是二进制大文件，git 处理不友好。建议用 git-lfs 或者 git-annex。

加密备份。chayuan-desktop 的 export 工具默认用密码加密。用户输入一个密码，导出包用这个密码 AES-256 加密。还原时输入同一密码。这种加密让备份安全送到云端。

恢复流程。新装一台 chayuan-desktop，跑 FirstRunSetup 选好 CHAYUAN_ROOT。设置 - 备份与导出 - 从备份恢复，选择 zip 包，输入密码。恢复成功后 KB 列表立刻看到所有内容。

跨电脑迁移。前面 21-跨电脑迁移 文章讲过。本质就是用 export + import 工具，或者直接拷 CHAYUAN_ROOT。两种方式互通。

备份频率建议。日常使用：每周整体备份一次到外置硬盘。重要项目期间：每天备份一次。重大变动前（比如 chayuan-desktop 升级）：备份一次。

备份验证。备份完成后偶尔做一次 还原验证：找一台测试机，从备份恢复，跑通基本检索。这种验证保证备份真的能用。商业级备份方案都有这一步，单机用户也建议偶尔做。

云端 KB 不在备份范围。src:* 外部源的实际数据在 Milvus、PG、达梦那边，备份是这些系统自己的事。chayuan-desktop 这边只备份连接配置（脱敏后）。

国产化支持下的备份。政企客户的备份策略通常严格，可能要求 异地备份、加密备份、定期演练。chayuan-desktop 的备份能力支持这些要求，但具体执行靠用户的 IT 团队。

WPS AI 插件 chayuan-wps 不需要单独备份，所有数据通过 chayuan-desktop sidecar 访问。备份 CHAYUAN_ROOT 即覆盖 WPS 加载项的数据来源。

KB 备份策略是 chayuan-desktop 单机版的运维责任。免费开源的AI软件 把数据所有权交给用户的同时，备份责任也跟着回来。chayuan-desktop 提供工具，怎么用是用户的选择。
