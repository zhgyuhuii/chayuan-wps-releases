# 引用展示按源类型分类 doc/struct/vec/office/web的UI差异

chayuan-desktop 桌面单机版的引用气泡按知识源类型分类展示。文档库的引用、结构化的引用、向量库的引用、办公库的引用、网页的引用，每种 UI 形态都不一样。这一篇讲清楚每种引用的展示设计。

先看为什么要分类型。早期某个版本所有引用气泡用同一种 UI：一个标题 + 一段预览 + 一个 来源 链接。结果用户分不清哪个引用能下载原文件、哪个能展开 SQL、哪个只是 vector ID 没法跳转。后来改成按 kind 分类渲染。

doc 来源的引用 UI。气泡顶部一行标题：文件名 + 页码（比如 技术规范 v3.2.pdf · 第 7 页）。中间预览：原文段落的 80-150 字摘要。底部一行：信任度分数（5 颗星）+ 跳转按钮（打开原文件到指定页）+ 下载按钮（如果建库时勾了保留原文件）。点击气泡展开抽屉，显示完整 chunk 文本，高亮命中的部分。

struct 来源的引用 UI。气泡顶部一行：表名 + 行数（比如 销售台账 · 12 行）。中间：SQL 摘要（前 100 字符）+ 数据预览（前 3 行）。底部：执行时间 + 数据库名。点击展开抽屉显示完整 SQL、影响行数、执行时间、数据表（最多 100 行）。SQL 的展示用语法高亮。

vec 来源的引用 UI。气泡顶部一行：collection 名 + vector ID。中间：payload 预览（如果有文本字段）+ metadata 摘要。底部：相似度分数 + 距离度量类型（cosine / L2）。点击展开抽屉显示完整 metadata 和 payload。

office 来源的引用 UI。气泡顶部一行：文件路径 + owner（比如 我的笔记/会议纪要.docx · 张三）。中间：原文段落预览。底部：密级标记 + 修改时间。点击展开抽屉跟 doc 类似但带 owner 信息。

web 来源的引用 UI。气泡顶部一行：网页标题 + 域名。中间：网页摘要。底部：URL + 抓取时间。点击在外部浏览器打开 URL。这种 UI 跟 doc 的区别在于 web 是临时检索的不在 KB 里，不能下载原 chunk。

为什么这样分。每种源的可展示信息和操作不同：doc 能下载，struct 能看 SQL，vec 只有 metadata，office 有 owner 隔离，web 是临时。UI 跟着实际能力走。

下载按钮的特别处理。chayuan-desktop 早期某段代码所有引用都给下载按钮，结果 vec 来源的用户点了之后没文件下载。后来改成按 kind 字段控制下载按钮的显示。doc 和 office 显示，struct/vec/web 不显示。

信任度分数的差异。doc 的信任度来自向量召回 + 重排。struct 的信任度是固定值（执行成功就 100%）。vec 的信任度是相似度归一化。office 的信任度跟 doc 一致。web 的信任度依赖搜索引擎的排序。

颜色编码。chayuan-desktop 在引用气泡上用不同的边框颜色区分类型：doc 蓝色、struct 绿色、vec 紫色、office 橙色、web 灰色。用户一眼能看到引用来自哪类。

折叠状态。每个引用气泡默认是 折叠态（一行高度），点击展开成 详情态。多个引用堆叠时按 score 排序。

点击行为。doc 引用点击在右侧抽屉打开原文段落，并提供 跳转到原文件 按钮（用 OS 默认应用打开 PDF 到指定页）。struct 引用点击展开 SQL 详情面板。vec 引用点击展开 metadata。office 引用点击同 doc 但加 owner 标识。web 引用点击外部浏览器打开 URL。

跨 KB 引用的混合展示。一次问答可能命中多种类型的 KB，前端按 kind 分组展示，每组一个折叠面板，组内按 score 排序。这种结构让用户能按类型对照看。

国产化支持下的引用。国产 PDF 阅读器（WPS、福昕）的跳转协议跟 Adobe Reader 略有不同。chayuan-desktop 的跳转用 OS 默认应用，由用户的 PDF 阅读器关联决定。麒麟 UOS 上 WPS Office Linux 版的跳转协议适配到位。

WPS AI 插件 chayuan-wps 的引用展示在 WPS 边栏。点击 doc 引用直接跳到 WPS 文档对应位置（如果当前文档就是该 PDF），或者打开外部 PDF 阅读器。点击 struct 引用展开 SQL 详情面板。点击 office 引用按 owner 检查权限。

引用按源类型分类是 chayuan-desktop UI 的一大特色。免费开源的AI软件 想让用户对 AI 答案有信任感，引用展示的精细化非常重要。一个气泡能不能下载、能不能跳页、能不能看 SQL，这些细节决定用户对答案的可信度判断。
