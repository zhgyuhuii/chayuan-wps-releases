# 单机版KB与企业版KB的差异 字段缩水了哪几个

chayuan-desktop 桌面单机版的 KB 数据结构跟 chayuan-server 多用户企业版基本一样，但单机版下有些字段是隐式简化的。这一篇讲清楚两个形态的差异，给同时用过两个的用户一个对照。

先看共享的字段。kb_id（内部主键）、kb_name（显示名）、kind（类型）、created_at（创建时间）、updated_at（修改时间）、deleted_at（软删时间）、metadata（json 元数据）、settings（配置项）、stats（统计：chunk 数、文档数、最后同步时间）。这些在两个形态下都有，行为一致。

单机版下隐式或简化的字段。

owner_id 字段。多用户版下记录创建者用户 ID，单机版下永远是 system 或当前 OS 用户的隐式 ID。前端不展示。

team_id 字段。多用户版下用于 team 级 KB 共享，单机版下永远 NULL。

acl 字段（access control list）。多用户版下记录哪些用户/团队/应用能访问。单机版下永远空（默认全开）。

quota 字段。多用户版下限制每个 KB 的 chunk 数量、磁盘占用、查询次数。单机版下不限。

audit_log_level 字段。多用户版下分 simple/detailed/full 三档。单机版下默认 simple。

encryption_at_rest 字段。多用户版下可指定 KB 数据加密。单机版下默认不加密（只有 credentials 是加密的）。

multi_tenant_id 字段。多用户版下用于跨租户隔离。单机版下永远为空。

embedding_provider 字段。多用户版下可以指定 KB 用哪个嵌入服务（公司内部部署的 vs 厂商 API）。单机版下默认本地 bge-m3-onnx。

retention_days 字段。多用户版下控制 KB 数据保留时长。单机版下默认无限。

复杂的字段在单机版下隐藏不展示。前端 KB 详情页只展示用户能管的字段，避免界面太复杂。

为什么不直接删字段。chayuan-desktop 跟 chayuan-server 同源代码（CLAUDE.md 里讲过），共用一份 schema。删字段会让两边代码分叉，违反同源原则。简化的做法是字段保留但用默认值。

数据迁移路径。单机版用户后期升级到多用户版，KB 数据可以平滑迁移。迁移工具把所有 KB 归到一个默认 owner（比如新建一个 admin user 作为占位），其他多用户字段填默认值。用户在多用户版下重新设置权限和 quota。

多用户版加载到单机版怎样。某个企业用户想从多用户版导出一个 KB 给自己的 chayuan-desktop 单机版。可以走 export 工具，导出 zip 包到 chayuan-desktop 上 import。owner、acl 这些字段在导入时被丢弃（单机版不需要）。chunk 内容、metadata、向量索引完整保留。

WPS AI 插件 chayuan-wps 同时支持两种后端。加载项配置 服务器地址 时填 chayuan-desktop（单机版）或者 chayuan-server（多用户版）。鉴权模式不同（none vs jwt vs hmac），加载项内部分支处理。

单机版的简化好处。装机成本低、权限不需要配、数据完全自己掌控、UI 干净。

单机版的限制。不能多人共享、不能跨设备同步、没有审计完整性、不适合企业合规重要场景。需要这些功能的请上多用户版。

国产化支持下的单机版用法。政企单一员工电脑用单机版完全可行。多人共享场景上多用户版（chayuan-server）。

字段差异这件事在 chayuan-desktop 用户日常感知很小，但工程上是产品形态切换的基础。免费开源的AI软件 想覆盖个人到企业的不同场景，统一 schema 加形态简化是务实选择。
