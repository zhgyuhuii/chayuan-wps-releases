# 本地离线知识库不是一个东西 察元AI的五类知识源解释

很多人第一次用 chayuan-desktop 桌面单机版的时候会以为 知识库 就是 把文档丢进去然后能问 这一种东西。其实察元AI 内部把 知识库 拆成五种不同的源类型，覆盖了完全不一样的使用场景。这一篇讲清楚五类知识源各自是什么。

第一类是文档库。命名空间 doc:*。形态是 PDF、Word、Excel、PPT、Markdown、HTML 这些办公文档切分后的 chunk，配 bge-m3 嵌入做向量召回，配 bce-reranker 做重排。日常最常用的就是这一类。folder-sync 文件夹同步、单文件上传都是建文档库。

第二类是结构化数据库。命名空间 src:* 的子集，对接 SQL 数据库。形态是数据库的表和列，问答走 text2sql 链路。chayuan-desktop 支持 MySQL、Postgres、Oracle、SQL Server、SQLite、ClickHouse、Hive、达梦 DM、金仓 KingbaseES、Doris 等 17 种方言。问 有几个用户 这种聚合问题应该走这条路径，不应该退化成文档检索。

第三类是向量库。命名空间 src:* 的另一子集，对接外部专业向量库。形态是 Milvus、Chroma、Qdrant、Zilliz、Elasticsearch、PG-vector、Relyt 等的 collection。问答走 ANN 检索 + metadata 过滤。这一类适合数据规模大、需要 HNSW 等高级算法、或者已有外部向量库要复用的场景。

第四类是办公私库。命名空间 office:owner[:group]。形态是个人或团队级别的私有资料，按 owner 和可选的 group 隔离。chayuan-desktop 单机版下主要用 office:zhangsan 这种个人库。多用户场景下 office:dept_finance:team_a 这种细粒度隔离。

第五类是外部连接器。命名空间 src:* 的更广义集，覆盖各种异构数据源。形态包括 MongoDB（半结构化）、Elasticsearch（全文搜索 + 向量）、各种 SaaS 系统（Notion、飞书、钉钉等）。每种连接器有专门 adapter。

为什么要分这么细。每种源的检索逻辑不一样：文档库走向量召回，结构化走 SQL，向量库走 ANN，办公库按命名空间过滤。如果不分类型一锅炒，要么牺牲检索精度，要么需要每个源各自实现一套，重复严重。chayuan-desktop 的五类抽象让每种源专注做自己擅长的事。

ku_ids 与 KnowledgeRef 是合同主字段。前端给后端传 ku_ids 数组，每个 id 是 doc:* / src:* / office:* 这三种命名空间的一种。后端按 id 解析成 KnowledgeRef 对象，再分发给对应的 adapter。这是 chayuan-desktop 的统一接口。

旧字段 kb_names 只作兼容。早期版本有个 kb_names 字段，只承载文档库名。新代码用 ku_ids 表达多类型源，kb_names 只在历史会话里出现作兼容。

不同类型的混选。一次问答可以同时勾上文档库 + 结构化 + 向量库。比如问 我们去年的销售数据怎么样，结合最新的市场分析报告，结构化库提供销售数字，文档库提供报告内容。chayuan-desktop 的 router 会把每个问题路由到合适的 adapter，结果聚合后让模型综合回答。

引用展示按源类型分类。文档来源能下载原文件、能跳页，结构化来源展示 SQL 和表，向量来源展示 collection 和 metadata，办公来源展示 owner 和 group。前端按 kind 字段分流渲染。

国产化支持下的几个特殊源。达梦 DM 和金仓 KingbaseES 在 src:* 命名空间下，跟其他 SQL 数据库走同一个 adapter 接口，方言适配在内部。RT、Relyt 等国产向量库同理。

WPS AI 插件 chayuan-wps 共用同一套五类知识源。在 WPS 文字里挑 KB 时能看到所有类型，每种用法跟桌面客户端一致。引用气泡按 kind 渲染。

本地离线知识库 这件事不是 一种产品功能，是 五种类型的统一抽象。理解了这五类各自是什么，chayuan-desktop 的所有 KB 相关行为都能讲清楚。免费开源的AI软件 在知识管理上的设计深度，从这种分层抽象就能看出。
