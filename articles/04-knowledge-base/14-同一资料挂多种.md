# 同一份资料同时挂成doc和vec 利弊与示例

某些场景下，同一份资料既想用文档 RAG 检索（chayuan-desktop 内嵌的 sqlite-vec），又想用外部专业向量库（Milvus、Chroma）检索。这种 双挂 在 chayuan-desktop 桌面单机版上是允许的，但有取舍。这一篇讲利弊。

先看场景。一份产品手册 PDF。你在 chayuan-desktop 里建了 doc:产品手册 走默认 sqlite-vec。同事另一个项目里在公司 Milvus 集群里也存了同一份资料的向量索引（用了不同嵌入模型，向量维度更高）。两边可以共存。

挂 doc:* 的好处。本地完整体验。引用气泡能展开原文段落、能跳页、能下载原文件。单机离线可用。延迟低。

挂 src:* 外部 vec 的好处。规模大。如果 Milvus 上有大量其他 collection 跟你这份资料关联，混选检索能找到更多 cross-reference。可以走更高级的 ANN 算法（HNSW）和更多 metadata 过滤。

双挂的坏处。

坏处一：维护成本。同一份资料在两边各自有索引。你更新原文件后两边都要重新入库。chayuan-desktop 没有 自动同步两边 的机制。

坏处二：成本翻倍。两边各占存储。如果资料大（GB 级），两份索引可能数 GB。

坏处三：检索结果可能冲突。同一份资料在两边的 chunk 切分可能不同，命中的 chunk 内容会有差异。模型综合时可能报告矛盾的细节。

坏处四：引用展示混乱。一次检索可能既命中 doc:产品手册 又命中 src:milvus_local 的同一份资料。前端按 ku_id 分组，但用户看到 同样内容来自不同源 会困惑。

什么时候值得双挂。

场景一。本地 chayuan-desktop 离线时也要能查。doc:* 在本地，外网断了仍能用。src:milvus_local 需要网络。双挂保 离线兜底。

场景二。本地是子集，外部是全量。比如 chayuan-desktop 只装了部分章节，Milvus 里有完整版。本地查快，外部查全。

场景三。不同检索精度需求。本地 doc:* 用 bge-m3 1024 维，Milvus 用更大模型 4096 维。某些精度敏感场景用外部，普通场景用本地。

什么时候不该双挂。

如果资料更新频繁。每次更新都要在两边重做，麻烦。

如果资料规模小。两边都装没必要，挑一个用就够。

如果用户搞不清两边差别。普通办公场景挂 doc:* 一个就够。

实际操作步骤。

步骤一。chayuan-desktop 里正常建 doc:产品手册，单文件上传或 folder-sync 入库。

步骤二。在外部 Milvus 集群里建 collection（不归 chayuan-desktop 管），用同一份原文件入库。Milvus 那边的工程师做这件事。

步骤三。在 chayuan-desktop 里新建外部连接，src:milvus_local 指向那个 collection。

步骤四。用户在 KB 选择器里勾上 doc:产品手册 + src:milvus_local 一起检索。

步骤五。引用展示时分别按 doc 和 vec 类型 UI 展示。

去重的处理。chayuan-desktop 在 results 模块对相似 chunk 做去重（基于内容相似度阈值），如果两边返回了同一段内容只保留一份。但跨 ku_id 的去重不是百分百可靠，特别是 chunk 切分不同时。

性能。双挂检索时两边并发跑，整体延迟 = max(doc 延迟, milvus 延迟)，不累加。

国产化支持下的双挂。国产 RT、Relyt 等向量库可以作为 src:* 外部源，跟 doc:* 共存。chayuan-desktop 在 multi-source 场景下不区分外部源是国产还是海外，统一处理。

WPS AI 插件 chayuan-wps 同样支持双挂场景。在 WPS 里勾 doc 加 src 检索，引用气泡按类型分类展示。

同一份资料双挂在 chayuan-desktop 上是技术可行的，但日常用很少必要。免费开源的AI软件 给用户灵活度，但不是每种灵活度都该用。挑合适的挂法比同时挂两边更稳。
