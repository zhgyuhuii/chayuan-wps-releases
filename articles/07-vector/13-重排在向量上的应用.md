# 重排在向量结果上的应用 二阶检索的收益

chayuan-desktop 桌面单机版的向量检索默认开启重排。这一步对向量库结果的精度提升明显。这一篇讲清楚为什么向量检索要加重排。

先看 向量召回 + 重排 这个二阶模式。

第一阶：向量召回。query 算 embedding，去向量库找距离最近的 K 个 chunk。这一步是 双塔 模型的双向距离计算，每个 chunk 的向量预先算好。query 跟 chunk 之间的细粒度交互不被建模。

第二阶：重排。把召回的 K 个 chunk 跟 query 一起喂给 cross-encoder 模型，让它实时打分。重排模型考虑 query-chunk 的 token 级别交互，比双塔更精确。

二阶模式的价值。

价值一：召回精度提升。在专业领域 KB（法律、医学、技术）上，重排能把 recall@5 从 0.78 提到 0.91。

价值二：去噪。某些向量召回的 chunk 仅 关键词相似 但语义不相关。重排能识别。

价值三：query 意图理解。同一个关键词在不同 query 下相关 chunk 不同。重排是 query-aware 的。

价值四：跨库归一化。前面 score 归一化文章讲过，重排是消除跨库 score 差异的最有效手段。

代价。

代价一：延迟。重排每个候选 chunk 跑一次模型。chayuan-desktop 用 bce-reranker-base 在 CPU 上每 chunk 30-50ms。重排 30 个候选大约 1 秒。

代价二：成本。如果重排走云端 API（比如 Cohere reranker），按 token 计费。

代价三：模型权重。本地重排需要下载模型权重（300MB）。

什么时候适合用重排。

适合一：专业领域。法律、医学、金融、技术。术语精确度要求高。

适合二：长 query。多条件 query 向量召回容易有偏差，重排能补救。

适合三：多源混合。跨 KB 的结果聚合，重排是好的归一手段。

适合四：精确事实问答。需要精确命中那一段事实。重排能提升 top-1 的精度。

不必用重排的场景。

场景一：极致延迟敏感。需要 1 秒内出答案，重排的 1 秒不能省。

场景二：高度相关的小 KB。所有 chunk 都相关，重排区分度低。

场景三：纯关键词查询。比如全文搜索为主，BM25 加向量召回已经够。

chayuan-desktop 的重排配置。

KB 级别开关。每个 KB 在设置里有 enable_rerank 开关。默认开。

重排模型选择。默认 bce-reranker-base（国产开源）。可选 Cohere reranker（云端 API）。

重排数量。从向量召回的 top-30 中重排选 top-5 给 LLM。这两个数字可在 KB 设置里调。

重排开关切换的代价。重排不影响 KB 索引，开关切换立刻生效。可以跑两次同样 query 对比开关效果。

实测对比。chayuan-desktop 在不同向量库上跑过重排对比。

sqlite-vec + bce-reranker：recall@5 从 0.85 到 0.92。

Milvus + bce-reranker：从 0.83 到 0.91。

Qdrant + bce-reranker：从 0.84 到 0.91。

ES（hybrid search）+ bce-reranker：从 0.86 到 0.93。

不同后端 + 重排都明显提升。

跨语种重排。bce-reranker 是中文重排，对纯中文 query 表现最好。中英混合 query 上仍能用但精度略降。chayuan-desktop 在中英混合场景下推荐用 bge-reranker（智源出品，多语言）。

重排模型升级。chayuan-desktop 跟随 bce-reranker 上游升级。新版本一般精度提升不大但稳定性好。

GPU 加速。如果用户机器有 GPU，安装 ONNX Runtime GPU 版，重排速度从 30ms/chunk 降到 5ms/chunk。整体重排延迟从 1 秒降到几百毫秒。

国产化支持下的重排。bce-reranker 是国产模型。chayuan-desktop 默认选择，符合国产化清单。

WPS AI 插件 chayuan-wps 透明用重排。在 WPS 里检索的精度跟桌面客户端一致。

重排在向量结果上的应用是 chayuan-desktop RAG 的精度核心。免费开源的AI软件 想做出生产级 RAG 体验，二阶检索几乎是必经之路。chayuan-desktop 默认开重排是工程化判断的结果。
