# 向量库的备份与回滚 单机版的常见做法

chayuan-desktop 桌面单机版的 sqlite-vec 数据备份相对简单，外部向量库的备份依赖各自工具。这一篇讲两类向量库的备份策略。

sqlite-vec 备份。每个 KB 一个 sqlite-vec 文件在 CHAYUAN_ROOT/vectors 下。备份就是 cp 这个文件。恢复就是 cp 回来。注意备份前 chayuan-desktop 关闭，避免 SQLite WAL 状态不一致。

整盘备份策略。chayuan-desktop 推荐用户备份整个 CHAYUAN_ROOT。对于 vectors 部分自动包含。

外部向量库的备份。

Milvus。原生 backup 工具（基于 etcd 快照 + 对象存储）。chayuan-desktop 不参与。用户在 Milvus 端做。

Qdrant。snapshot 功能，把 collection 数据导出为快照。

Chroma。export 工具。

ES。snapshot API，依赖共享文件系统或 S3。

PG pgvector。pg_dump 命令导出整个数据库。

回滚场景。

场景一：误删 KB。chayuan-desktop 软删除 30 天。从回收站恢复即可。

场景二：数据损坏。SQLite 文件损坏。chayuan-desktop 检测到时提示用户从备份恢复。

场景三：升级失败。chayuan-desktop 大版本升级偶尔有不兼容问题。回滚到老版本 + 恢复数据。

场景四：嵌入模型升级失败。重建索引出错，原 KB 状态被破坏。从备份恢复。

回滚的具体步骤。chayuan-desktop 的恢复工具在 设置 - 备份与恢复。

第一步：关闭 chayuan-desktop。

第二步：确认要恢复哪个版本的备份。

第三步：把备份文件解压覆盖到 CHAYUAN_ROOT。

第四步：启动 chayuan-desktop。

第五步：跑测试 query 验证数据回来了。

外部向量库的回滚由各自机制。chayuan-desktop 这边只需要重连一次。

备份频率建议。

日用：每周备份一次 CHAYUAN_ROOT。

重要项目：每天备份。

升级前：必备份。

外部向量库：依各自重要性，至少每月一次。

备份介质。建议外置硬盘 + 异地（云端加密）。本地多份备份不算冗余（同一物理位置）。

加密备份。chayuan-desktop 的 export 工具支持密码加密的 zip 包。某些用户怕外置硬盘丢，加密后即使丢也安全。

恢复演练。建议每季度做一次 假设丢了 演练。从备份完整恢复一遍，确认数据可用。这种演练让备份策略真的可靠。

备份的局限。chayuan-desktop 的备份是离线快照，不是实时同步。备份之后到下次备份之间的新对话和新 KB 数据丢失风险。重要场景考虑实时同步（rsync 加日志监控）。

国产化支持下的备份。等保 2.0 三级要求重要数据有 异地备份。chayuan-desktop 的 export 加内部加密让数据传输到异地不泄露。

WPS AI 插件 chayuan-wps 不需要单独备份。所有数据通过 chayuan-desktop sidecar，备份 CHAYUAN_ROOT 即覆盖。

向量库备份与回滚是 chayuan-desktop 单机版的运维必修。免费开源的AI软件 把数据所有权给用户的同时，备份责任也回到用户手里。chayuan-desktop 提供工具，纪律由用户执行。
