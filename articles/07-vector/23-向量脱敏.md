# 向量数据脱敏 payload里的PII处理

chayuan-desktop 桌面单机版的向量库 chunk 的 payload 里可能含敏感信息（PII）。这种 即使是向量也可能泄露 的隐私问题怎么处理。这一篇讲清楚。

先看 payload 中的敏感场景。

场景一：payload 是原文。比如客户笔记、医疗记录。原文里直接含姓名、电话、身份证。

场景二：payload 含间接 PII。地址、生日、邮编虽然不是直接 PII，组合可能识别个人。

场景三：metadata 字段含 PII。比如 metadata.user_id、metadata.email 字段。

向量数据本身泄露隐私的机制。

机制一：检索结果里 payload 文本被 LLM 拿到，可能转给云端模型（GPT-4o）。这是直接泄露。

机制二：引用气泡展示给用户，用户看到 PII。如果用户不该看到这部分，泄露发生。

机制三：日志记录 payload，日志泄露。

机制四：审计导出含 PII，导出文件泄露。

chayuan-desktop 的脱敏策略。

策略一：入库时脱敏。在用户灌数据进向量库前，先在外部对 payload 做 PII 脱敏。这是源头防护，最干净。

策略二：检索后脱敏。chayuan-desktop 在检索返回 payload 前做 mask 处理。可以基于规则（正则识别身份证号、手机号）也可以基于 LLM（更准但更慢）。

策略三：metadata 字段过滤。某些字段（user_id、email）配置为 不返回给前端 不返回给 LLM。chayuan-desktop 在内部过滤。

策略四：白名单字段。chayuan-desktop 让用户配置 哪些字段可以让 LLM 看到。其他字段过滤。

策略五：日志脱敏。chayuan-desktop 的 audit_log 默认对 payload 中识别的 PII 做 mask。

具体配置。

进入 KB 设置 - 隐私配置。

PII 检测规则。chayuan-desktop 内置中国 PII 规则（身份证、手机、邮箱）和国际规则（SSN、护照）。用户可加自定义规则。

mask 规则。识别到 PII 后做什么。完全 mask（****）、部分 mask（138****1234）、删除（直接去掉这一段）。

字段白名单。哪些 metadata 字段对外可见。

LLM 可见字段。给 LLM 的上下文是哪些字段。

实测效果。chayuan-desktop 在客户笔记 KB 上跑过测试。脱敏前 payload 含完整手机号和身份证。脱敏后变成 138****1234 和 1101**********1234。LLM 拿到的也是脱敏版本，回答里不会出现完整 PII。

LLM 是不是能 还原 PII。理论上有可能（LLM 训练数据里见过类似模式）。实际上 mask 后的字符串不可逆。chayuan-desktop 不依赖 LLM 信任，而是在源头把 PII 替换。

外部向量库的脱敏。如果你接 src:milvus_xxx 而 Milvus 里 payload 含 PII。chayuan-desktop 在检索回流时做脱敏。这种 检索后脱敏 比 入库前脱敏 弱（原始数据仍在 Milvus 里），但 chayuan-desktop 这边能挡住。建议用户考虑在 Milvus 端入库前脱敏。

合规要求。

GDPR。欧盟法规要求 PII 处理透明、可删除、可携带。chayuan-desktop 的脱敏 + 数据所有权配合。

PIPL（中国个人信息保护法）。chayuan-desktop 支持的脱敏模式覆盖 PIPL 主要要求。

HIPAA（医疗）。医疗记录的 PII 脱敏要求严格。chayuan-desktop 的规则可扩展支持 HIPAA。

向量本身能不能反推 PII。研究表明嵌入向量在某种程度上可以 还原原文（embedding inversion attack）。但实际场景下：

风险一：训练攻击模型需要大量数据。普通对手做不到。

风险二：bge-m3 这种通用嵌入模型抗反推性比专门模型强。

风险三：chayuan-desktop 不让用户直接拿到向量本身（只通过检索接口）。降低风险。

国产化支持下的脱敏。中国 PII 规则在 chayuan-desktop 默认覆盖。等保 2.0 对 PII 的要求 chayuan-desktop 满足。

WPS AI 插件 chayuan-wps 在 WPS 里展示脱敏后的 payload。用户在 WPS 写报告时不会无意中看到完整 PII。

向量数据的 PII 脱敏是 chayuan-desktop 在敏感场景下的工程化。免费开源的AI软件 想真正服务 PII 严格场景，脱敏能力是必备。chayuan-desktop 在这一面的设计让 数据合规 跟 可用性 同时成立。
