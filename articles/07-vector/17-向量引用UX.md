# 向量结果引用的UX设计 metadata的展示

chayuan-desktop 桌面单机版的 src:* 向量库引用气泡跟 doc:* 文档库不同。这一篇专门讲向量来源的 UX 设计。

先看向量引用气泡的视觉风格。紫色边框、紫色图标。这种颜色编码让用户一眼区分 这是向量库来源。

气泡的折叠态。一行展示。collection 名 + payload 摘要 + 信任度（5 颗星）。比如 `Milvus.products · 跟产品 A 类似的内容... · ★★★★☆`。用户能快速浏览不展开。

气泡的展开态。点击气泡后右侧抽屉打开。展示。

vector ID。原 vector 的 ID。

distance / score。原始距离和归一化 score。

payload。完整 payload 文本。

metadata。所有 metadata 字段，按 key-value 列表展示。

跳转按钮（如可用）。如果 metadata 含 source_file 字段且文件本机可访问，按钮 跳到原文件。

下载按钮（默认无）。向量来源默认不给下载按钮，前面文章解释过。

metadata 字段的展示。chayuan-desktop 按一定规则展示 metadata。

特殊字段。source、title、author、created_at 这些识别出的字段优先展示在前。

业务字段。chayuan-desktop 不预设的字段（用户自定义）按 alphabetical 顺序排在后。

值的格式化。日期类（含 _at 后缀）格式化成可读时间。URL 渲染成超链接。布尔值显示对错图标。空值不显示。

长文本字段。如果 payload 或某个 metadata 字段超过几百字符，默认折叠展示一行，点击 展开全部 看完整。

颜色编码。chayuan-desktop 给不同类型字段用不同颜色 chip。timestamp 用蓝色，tags 用橙色，confidentiality 用红色。视觉上一目了然。

信任度展示。前面文章讲过，归一化 score 转 5 颗星。向量来源的星级比文档来源略保守（向量召回的 score 偏差范围更大）。

跨 KB 的引用排序。如果一段答案引用了 doc + struct + vec 三种来源，前端按 score 全局排序。各类型混合展示在引用区，但每种用各自颜色区分。用户能看到 哪种来源贡献了什么。

引用按 KB 分组（可选）。某些用户偏好按 KB 看引用。chayuan-desktop 设置里有个 引用展示模式 开关：按 score 排序 vs 按 KB 分组。默认按 score。

不要误导用户。CLAUDE.md 里讲过的硬要求。向量来源不能展示成 可下载的文档附件。这条在 UX 上严格执行。

复制 vector ID 功能。开发者用户可能想用 vector ID 去原向量库做更深查询。chayuan-desktop 的引用气泡有 复制 ID 按钮，方便开发者。

原始查询的展示（可选）。某些场景用户想看 chayuan-desktop 实际发给向量库的什么 query。展开抽屉里有 查看原始查询 按钮，展示发出去的 vector + filter。这是开发者工具。

性能。向量引用气泡渲染跟文档引用一致快。React 组件按需 lazy 渲染。多 KB 多引用的页面不卡。

国产化支持下的 UX。中文 metadata 字段名（按部门、按密级）chayuan-desktop 全 utf-8 显示。中文 payload 跟英文一致渲染。

用户自定义。某些用户希望某个特定字段在气泡上 prominent 展示。chayuan-desktop 当前不支持完全自定义，但 KB 设置里能调整 重点字段 排序。

WPS AI 插件 chayuan-wps 在 WPS 边栏展示向量引用气泡。UX 跟桌面客户端一致，但视觉风格适配 WPS 边栏窄空间（每个气泡更紧凑）。

向量结果引用的 UX 设计是 chayuan-desktop 多源 RAG 的 透明可信 体现。免费开源的AI软件 想让用户看清楚 答案来自哪、靠不靠谱、能不能继续追溯，引用气泡的精细设计是关键。chayuan-desktop 在这一面的差别让多源 RAG 真正可用。
