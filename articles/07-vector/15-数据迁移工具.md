# 数据迁移 从Chroma迁到Milvus的工具

chayuan-desktop 桌面单机版用户偶尔需要在不同向量库之间迁移数据。从 Chroma 起步用着用着觉得 Milvus 更适合，怎么搬。这一篇讲迁移流程。

先看迁移的几种触发场景。

场景一：从嵌入式到独立服务。早期用 sqlite-vec 或 Chroma 嵌入式，数据规模长大后迁到 Qdrant 或 Milvus 独立服务。

场景二：从云端到自建。早期用 Zilliz Cloud，后来要求数据本地化，迁到自建 Milvus。

场景三：从一个云端到另一个。从 Pinecone 迁 Zilliz，跨厂商迁移。

场景四：从测试环境到生产。开发用 sqlite-vec，生产用 Milvus 集群。

迁移的核心数据。

核心一：chunk 文本。每个 chunk 的文字内容。

核心二：embedding。每个 chunk 的向量。

核心三：metadata。chunk 的元数据（source、page、tags 等）。

核心四：collection schema。字段定义、维度、距离度量。

迁移流程。

第一步：导出源数据。chayuan-desktop 提供 chayuan-export 命令行工具。从源 KB 导出 chunk + embedding + metadata 到 JSON 或 parquet 文件。

例：chayuan-export --from doc:技术规范 --output ./export.parquet。导出格式 parquet 高效。

第二步：在目标库建好 collection。比如目标是 Milvus，先在 Milvus 集群建对应 schema 的 collection。维度跟源一致。距离度量一致。

第三步：导入到目标。用 Milvus 的 bulk insert 工具或 chayuan-import 命令。

例：chayuan-import --to src:milvus_target --input ./export.parquet。

第四步：在 chayuan-desktop 里建对应 src:* KB 指向新 collection。

第五步：测试。新建对话挑新 KB，跑几个 query 验证。结果合理后正式切换。

第六步：删除旧 KB（可选）。确认新 KB 没问题后删旧的，省存储。

embedding 直接复用。如果目标库用同一 embedding 模型，原 embedding 可以直接复用，不用重新算。这是最快的迁移路径。

embedding 需要重新算。如果目标库要换 embedding 模型，每个 chunk 要用新模型重新生成 embedding。chayuan-desktop 的 import 工具支持 --recompute-embedding 选项。这种迁移比较慢（每 chunk 30-50ms）。

跨格式迁移。

sqlite-vec 到 Milvus。chayuan-export 直接拉 sqlite-vec 数据，chayuan-import 写到 Milvus。

Chroma 到 Qdrant。从 Chroma 拉数据用 chromadb-client，写到 Qdrant 用 qdrant-client。两段操作。

ES 到 Milvus。从 ES scroll API 拉数据，转格式后写入 Milvus。

迁移的几个坑。

坑一：维度不匹配。源跟目标维度不同时迁移失败。要在 chayuan-desktop 用相同 embedding 重新算。

坑二：metadata 字段命名差异。源用 source_file，目标用 source_path。chayuan-import 支持字段映射。

坑三：距离度量差异。cosine 跟 L2 不同。一般做归一化后兼容。

坑四：chunk 文本编码。某些库存的是 UTF-8，某些是 ASCII。一般都是 UTF-8 没问题。

坑五：批量大小。大数据量迁移需要分批，避免单批太大触发限流。

迁移期间的可用性。chayuan-desktop 默认双 KB 并存：旧 KB 仍可用，新 KB 灌好后用户切换。这种 平滑迁移 让业务不中断。

性能。

100 万 chunk 迁移（embedding 复用）。约 10-30 分钟。

100 万 chunk 迁移（重新计算 embedding）。约 1-3 小时。

迁移的回滚。如果新 KB 出问题，旧 KB 还在，立刻切回。chayuan-desktop 不主动删旧 KB。

国产化支持下的迁移。从海外开源（Milvus）迁到国产（RT）的需求在政企信创场景常见。chayuan-desktop 的迁移工具覆盖这种跨国产/海外的场景。

WPS AI 插件 chayuan-wps 在迁移期间不用改配置。新 KB 切换后加载项立刻能用。

数据迁移工具是 chayuan-desktop 数据所有权 承诺的具体落地。免费开源的AI软件 不应该让用户被向量库锁定。chayuan-desktop 的迁移工具让用户随时能换后端。
