# 国产化支持的私有向量库 RT与Relyt接入

国产化场景下用 Milvus、Chroma 这种海外开源软件可能不符合信创要求。chayuan-desktop 桌面单机版支持国产私有向量库 RT（睿驰）、Relyt（实时计算）等。这一篇讲清楚国产向量库接入。

先看几个国产向量库代表。

RT。睿驰科技自研向量数据库。支持 HNSW IVF。MySQL 协议兼容（部分版本）。在金融政企场景里有覆盖。

Relyt。阿里云出品的实时分析云数据库（含向量能力）。基于 Greenplum 二次开发。云端服务为主。

腾讯云 Tencent VectorDB。腾讯云的托管向量库。

阿里云 ANNS（AnalyticDB Neighbors Search）。阿里云分析数据库的向量服务。

百度智能云向量数据库。基于 Apache Cassandra 二次开发。

每家都有自己的特点和适用场景。chayuan-desktop 的 adapter 抽象让接入这些都不难。

接入策略。

策略一：写专用 adapter。每家国产向量库有自己的 SDK 和 API。chayuan-desktop 在 retrieval/query/adapters/vector 下写一份对应 adapter，实现 search、insert、delete 等接口。

策略二：用通用协议。某些国产库支持 OpenAI 兼容协议或 Milvus 兼容协议，可以套现有 adapter。比如 RT 支持 Milvus 协议，chayuan-desktop 直接当 Milvus 接。

策略三：用 SQL 方言。某些国产库 SQL 风格暴露向量查询（比如 pgvector 接到金仓上）。chayuan-desktop 通过 SQL adapter 接。

实操流程。

第一步：评估接入方式。看库支持什么协议。

第二步：在 chayuan-desktop 选对应类型创建外部源。如果库支持 Milvus 协议选 Milvus 类型，等等。

第三步：填连接信息。host、port、user、password、collection 名。

第四步：测试连接和检索。

国产化部署的几个特别注意。

注意一：离线环境。国产部署常常完全离线。chayuan-desktop 跟向量库都在内网。模型钥匙不需要外网。

注意二：合规要求。某些等保 2.0 三级以上环境要求所有组件可审计。RT 等国产库提供源代码或者可审计版本。chayuan-desktop AGPL 开源可审计。整体方案合规。

注意三：性能要求。政企内网常用国产 CPU（飞腾、鲲鹏）。国产向量库对国产 CPU 优化好。chayuan-desktop sidecar 在 aarch64 架构下也跑得顺。

实际案例。某国有银行的 chayuan-desktop 部署。

部署形态。员工电脑装 chayuan-desktop（飞腾 CPU 麒麟 UOS）。后端 sidecar 接 RT 向量库（部署在内网集群）+ 达梦 DM（业务数据）。本地 Ollama 跑 DeepSeek-V3（私有部署）。

用法。员工在 WPS 里写报告调起 chayuan-wps 加载项，混合检索 RT 里的政策文档 + 达梦里的业务数据。

效果。完全离线，数据不出域，国产化清单全覆盖。

跟海外向量库的体验差异。chayuan-desktop 用户感知一致。adapter 抽象隐藏了后端类型。配置和 KB 操作流程跟接 Milvus 一样。

性能对比。chayuan-desktop 在百万 chunk 上跑测试。RT 跟 Milvus 性能接近（毫秒到几十毫秒）。Relyt 因为基于 Greenplum 偏向分析场景，向量查询不是最快。腾讯阿里百度的云端向量库性能稳定。

国产化向量库的局限。

局限一：生态。国际开源（Milvus、Qdrant、Chroma）的社区资源、文档、tutorial 多。国产向量库的资源相对少，遇到问题排查靠原厂支持。

局限二：升级。国产商业产品升级跟开源节奏不同，可能要走商务流程。

局限三：定制。国产产品的私有化定制能力强但开放性弱。

未来发展。国产向量库的能力跟海外开源差距在缩小。chayuan-desktop 的多 adapter 设计让用户可以根据 当前最佳选择 切换，不被产品锁死。

WPS AI 插件 chayuan-wps 透明用国产向量库。在 WPS 里发起检索时不感知后端类型。

国产化向量库的接入是 chayuan-desktop 国产化战略的核心部分。免费开源的AI软件 想真正服务政企客户，国产生态的对接深度是关键。chayuan-desktop 在这一面的多 adapter 投入让 完全国产化部署 真的可达。
