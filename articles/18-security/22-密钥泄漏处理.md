# 安全事件演练 一次密钥泄漏的处理

某 chayuan-desktop 用户发现自己的 OpenAI Key 被外人用了。安全事件演练。这一篇讲。

## 发现泄漏

用户发现。

OpenAI 账户余额被刷光。

OpenAI 邮件提醒 unusual usage。

某些 API Key 被发现在公开 GitHub 仓库（不小心 commit 了）。

每种情况都需要立即处理。

## 紧急止损

第一步。立即吊销泄漏的 Key。

OpenAI 后台 → 删除该 Key。

避免继续被用。

第二步。chayuan-desktop 同步。

```
chayuan-desktop 设置 - 模型 - OpenAI - 移除 Key
```

旧 Key 不再用于调用。

第三步。生成新 Key 替换。

OpenAI 生成新 Key → chayuan-desktop 填入新 Key → 测试连接。

## 调查泄漏来源

第二阶段。查泄漏从哪来。

可能性一：备份泄漏。备份文件被偷或上传到公共云。

调查 chayuan-desktop 的备份是否启用 + 备份位置。

如果备份未加密 + 上了公网网盘 → 泄漏路径。

可能性二：代码 commit。Key 不小心 commit 到 git。

git history 看是否含 Key。

可能性三：恶意软件。机器有恶意软件读取 chayuan-desktop 的 Stronghold 文件。

杀毒扫描。

可能性四：本机其他用户偷看。共享电脑场景。

OS 用户隔离是否到位。

## 评估损失

OpenAI 后台看 unusual usage 的详细。

被刷的金额。

被请求的次数。

可能涉及的对话内容（如果攻击者用 Key 跑了请求）。

某些对话内容可能含敏感信息。需要进一步评估泄漏范围。

## 用户通知

如果攻击者用 Key 跑请求。OpenAI 那边可能有日志。

但 chayuan-desktop 不一定有这些请求记录（chayuan-desktop 的审计只记录从 chayuan-desktop 发出的，不知道攻击者从外部用 Key 发的）。

## chayuan-desktop 的辅助

chayuan-desktop 提供。

凭据访问审计。如果泄漏因为 Stronghold 被读，chayuan-desktop 应该记录访问。但本地无 chayuan-desktop 主进程的访问日志（OS 级访问）。

凭据轮换提醒。chayuan-desktop 可配置 90 天提醒用户轮换 API Key。降低长期泄漏风险。

## 防止再次泄漏

加固。

启用 chayuan-desktop 主密码（如果之前没启用）。

OS 全盘加密。

避免共享电脑用 chayuan-desktop。

不在公共 Wi-Fi 用 chayuan-desktop（虽然走 HTTPS 但小心）。

不上传 chayuan-desktop 数据到公共云盘。

## 长期措施

定期轮换 API Key。每 3-6 个月。

启用 OpenAI 的使用限额（每月最多 X 美元）。

启用 OpenAI 的 IP 白名单（如果 OpenAI 支持）。

配 chayuan-desktop 的预算上限。

## 应急联系

如果泄漏严重。

联系 OpenAI 客服（支持申诉部分退款）。

联系 chayuan-desktop support。

可能涉及法律（如果数据泄漏）。

## 国产化场景

党政军场景的密钥泄漏更严重。

可能违反等保要求（密钥应该 Stronghold 加密）。

可能涉及安全审计追责。

需要立即上报安全部门。

chayuan-desktop 的泄漏处理流程 + 审计日志 + 等保合规配置降低风险。

## chayuan-server 的对应

chayuan-server 多用户场景下密钥集中管理。某用户的泄漏不影响其他人（如果隔离好）。chayuan-server 的密钥轮换更便利。chayuan-desktop 单机密钥用户自管。

## 演练价值

这种演练让用户。

了解密钥泄漏的危害。

知道发生时怎么应对。

平时多注意保护。

chayuan-desktop 的文档含此类演练帮用户准备。

## 总结

密钥泄漏处理演练是 chayuan-desktop 在安全意识上的工程教育。免费开源的AI软件 不只提供技术，也提供事故应对。chayuan-desktop 的紧急止损 + 调查 + 评估 + 加固 + 长期措施让用户面对泄漏时有方法。
