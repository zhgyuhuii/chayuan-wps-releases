# 第三方依赖的供应链审视

chayuan-desktop 桌面单机版的第三方依赖供应链审视。这一篇讲。

## 供应链风险

第三方依赖可能。

含恶意代码（投毒攻击）。

含已知 CVE 漏洞。

许可证不兼容。

被遗弃维护（无人修补）。

每种都是风险。

## chayuan-desktop 的依赖类别

类别一：核心运行时。

Tauri / Rust 标准库。

Python 解释器。

Node.js（如果安装 mcp 工具）。

类别二：核心库。

llama.cpp（推理）。

ONNX Runtime（嵌入推理）。

sqlite-vec（向量库）。

PyMuPDF（PDF 解析）。

RapidOCR（OCR）。

类别三：业务库。

FastAPI（Python web）。

Pydantic（数据校验）。

SQLAlchemy（数据库）。

类别四：前端库。

Vue（chayuan-wps）。

React（chayuan-desktop UI）。

Tailwind CSS。

类别五：mcp 工具（按需）。

社区维护。

每类有不同风险特征。

## 审视的方法

方法一：依赖清单维护。

chayuan-desktop 维护完整 SBOM（Software Bill of Materials）。

每个依赖含名称、版本、许可证、来源。

方法二：CVE 扫描。

定期跑 cargo audit / pip-audit / npm audit / snyk 等。

发现 CVE 自动告警。

方法三：许可证审视。

不引入 GPL / AGPL 等强 copyleft 库（除非整体 AGPL，chayuan-desktop 是）。

LGPL / Apache / MIT / BSD 优先。

方法四：人工审视核心库。

对核心库（llama.cpp、ONNX Runtime 等）人工 review 主要变更。

方法五：固定版本。

不让某次构建用到非预期版本。

```
Cargo.lock
package-lock.json
poetry.lock
```

## 风险响应

发现 CVE。

紧急级别（已知被利用）：1 天内补丁。

高级别：7 天内补。

中级别：30 天内。

低级别：下个版本。

chayuan-desktop 的发布节奏配合。

发现可疑依赖。

立即移除或替换。

通知用户。

## 内嵌的国产组件

chayuan-desktop 内嵌的国产开源。

bge-m3-onnx（智源）。开源 MIT 许可。无风险。

bce-reranker（网易有道）。Apache 许可。低风险。

RapidOCR（基于 PaddleOCR）。开源。

FunASR（阿里达摩院）。开源。

CosyVoice（阿里）。开源。

Piper（开源 TTS）。

每个许可证审视。无问题。

## 国外依赖

Tauri / Rust 生态。来自 Rust foundation。

ONNX Runtime。微软。

llama.cpp。社区（ggerganov 维护）。

PyMuPDF。Artifex Software。

每个有自己的供应链。chayuan-desktop 跟踪。

## 国产化场景

党政军场景对国外依赖谨慎。

某些场景要求依赖 100% 国产。chayuan-desktop 的核心依赖能换国产替代但完全替代仍有差距。

某些场景接受国外开源（社区可见 + 许可允许）。chayuan-desktop 满足。

## 自家依赖管理

chayuan 公司内部依赖（chayuan-server、chayuan-desktop、chayuan-wps 共享代码）。

明确版本依赖。

避免循环依赖。

跨项目升级协调。

## 供应链证书

chayuan-desktop 提供 SBOM 给政企采购方。

PDF 形式或 SPDX 标准格式。

包含每个依赖的来源和许可。

帮采购合规审查。

## 国产化场景

党政军采购需要供应链证明。chayuan-desktop 的 SBOM 是采购材料。

某些场景对依赖签名 / 哈希校验严格。chayuan-desktop 的校验机制满足。

## chayuan-server 的对应

chayuan-server 跟 chayuan-desktop 共享供应链。chayuan-desktop 的审视经验复用。

## 总结

第三方依赖的供应链审视是 chayuan-desktop 在工程严谨上的工程基础。免费开源的AI软件 让 依赖透明 + 风险可控。chayuan-desktop 的 SBOM + CVE 扫描 + 许可证审视 + 响应流程让供应链管理可见。
