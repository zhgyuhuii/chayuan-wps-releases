# 审计日志 单机版默认怎么存

chayuan-desktop 桌面单机版的审计日志记录所有关键操作。这一篇讲存储和管理。

审计的关键操作。

操作一：KB 访问。每次查询哪个 KB、用什么 query、命中多少 chunk。

操作二：模型调用。哪个模型、什么时候、token 数。

操作三：工具调用。哪个工具、参数（脱敏）、结果。

操作四：KB 管理。建库、删库、改 KB 配置。

操作五：模型供应商管理。新加、修改、删除供应商。

操作六：登录登出。多用户版下。单机版没有。

操作七：导入导出。备份、导入。

存储位置。CHAYUAN_ROOT/data 的 audit_log 表。SQLite 表。

字段。

id。自增 ID。

timestamp。操作时间。

user_id。用户标识（单机版下是隐式 OS 用户）。

session_id。会话标识。

action。操作类型（search_kb、call_llm、execute_tool 等）。

resource_id。被操作资源（KB ID、模型名、工具名）。

details。详细信息（JSON）。

ip。IP 地址。

user_agent。客户端标识（web、wps）。

retention。保留期限。chayuan-desktop 默认 365 天。这是大多数等保合规的最低要求。

清理策略。每日定时任务（APScheduler 凌晨跑）扫描超过 retention 的记录，删除。

写入性能。每次操作多写一条记录。SQLite 写入快（毫秒级）。不影响主流程。

查询和导出。chayuan-desktop 设置 - 审计 - 查看日志。提供。

按时间过滤。

按操作类型过滤。

按用户过滤（多用户版）。

按资源过滤。

导出 CSV / JSON。

合规审计常见场景。

场景一：监管检查。监管机构问 上个月 LLM 调了哪些 KB。chayuan-desktop 导出审计日志成报告。

场景二：故障复盘。某次错误对话怎么发生的。审计日志加 trace 还原。

场景三：使用统计。哪些 KB 用得多、哪个用户活跃。审计日志聚合。

场景四：异常检测。某天 query 突增。日志按时间统计能发现。

不可篡改。等保某些场景要求审计日志不可被任何人（包括管理员）修改。chayuan-desktop 当前是 SQLite 普通表，能改。企业版可以集成 WORM 存储。

集成 SIEM。chayuan-desktop 支持配置同步审计日志到 SIEM 系统（splunk、elastic、阿里云日志服务）。每条 audit 实时发出。这种 中央集中审计 是政企标准。

性能。一台 chayuan-desktop 一天日常使用大约产生 1000-10000 条审计记录。年度积累 30 万-300 万条。SQLite 完全扛得住。

国产化支持下的审计。等保 2.0 三级以上要求审计日志完整。chayuan-desktop 默认覆盖。

WPS AI 插件 chayuan-wps 发起的操作同样写入审计。source 字段标记 wps。

审计日志单机版默认存储是 chayuan-desktop 合规底盘。免费开源的AI软件 想在政企落地，审计是基本素质。chayuan-desktop 在这一面的工程化让 真合规 不只是说说。
