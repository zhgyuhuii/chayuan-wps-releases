# 漏洞响应流程 单机版的发布节奏

chayuan-desktop 桌面单机版的漏洞响应流程。这一篇讲。

## 漏洞的来源

来源一：用户报告。某用户发现可疑行为或错误。

来源二：CVE 数据库。chayuan-desktop 用的某依赖被披露 CVE。

来源三：内部审计。chayuan 团队发现。

来源四：外部安全研究员。

来源五：自动扫描。

每种来源的响应不同。

## 响应等级

等级一：紧急。已知被利用 + 影响数据安全。

等级二：高。已知漏洞 + 潜在数据泄露。

等级三：中。未知是否被利用 + 影响有限。

等级四：低。理论漏洞 + 利用条件苛刻。

每等级响应时间不同。

## chayuan-desktop 的响应时间

紧急：1 天内补丁。

高：7 天内。

中：30 天内。

低：下个 minor 版本。

## 响应流程

第一步：接收。chayuan-desktop 的 security@chayuan.com（或类似）接收报告。

第二步：评估。chayuan 团队评估等级。

第三步：通知。如果是用户报告。回复用户确认。

第四步：开发补丁。在 fix 分支开发。

第五步：测试。回归测试 + 安全测试。

第六步：发布。按等级时间发布。

第七步：通知用户。

第八步：CVE 申请（如果适用）。

## 通知用户的方式

紧急：弹窗式 + 强制升级。

高：弹窗式 + 推荐升级。

中：通知中心 + 下次启动提示。

低：release notes 提及。

让用户能按风险决定升级速度。

## 透明披露

chayuan-desktop 维护安全公告页面。

```
chayuan-desktop 安全公告：
  CVE-2026-XXXX: 某严重漏洞
    披露日期：2026-04-01
    影响版本：< 3.0.5
    修复版本：3.0.5
    缓解措施：[临时缓解步骤]
```

公开透明。

## 漏洞奖金（路线图）

chayuan-desktop 路线图含漏洞奖金计划（bug bounty）。

外部安全研究员发现并报告漏洞。chayuan 公司给金钱奖励。

激励社区帮 chayuan-desktop 找漏洞。

## 内部测试

每次发版前。

静态扫描（cargo audit、bandit、semgrep 等）。

依赖漏洞扫描。

模糊测试（少量）。

人工 code review（核心模块）。

避免新版本引入漏洞。

## 修复的回归

修复某漏洞后。

加测试用例确保不回归。

CI 跑过测试。

发版后监控相关代码路径。

## 不修复的情况

某些理论漏洞但不修复。

利用条件极苛刻（用户主动配合攻击者）。

修复成本极高 + 影响极小。

是其他依赖的问题（chayuan-desktop 不引入）。

明确说明不修复理由。

## 国产化场景

党政军场景对漏洞响应严格。chayuan-desktop 的 1 天紧急响应满足等保。

某些场景要求漏洞修复经过审批。chayuan-desktop 的 release 含变更说明便于审批。

## chayuan-server 的对应

chayuan-server 多用户场景下漏洞影响更大。响应时间更紧。chayuan-desktop 单机的流程经验复用。

## 用户的责任

用户也有责任。

及时升级。chayuan-desktop 自动升级建议开。

报告可疑行为。让 chayuan 团队知道。

不忽略安全公告。

## 总结

漏洞响应流程是 chayuan-desktop 在长期安全运营上的工程能力。免费开源的AI软件 不能因为开源就忽视安全响应。chayuan-desktop 的多渠道接收 + 分级响应 + 透明披露 + 持续测试让漏洞响应可信。
