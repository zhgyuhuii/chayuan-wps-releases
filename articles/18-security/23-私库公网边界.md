# 私库与公网知识库的边界 不要混用

chayuan-desktop 桌面单机版的私库 office:* 跟公网知识库 doc:* 边界。不要混用。这一篇讲。

## 混用的风险

风险一：私库内容泄漏。

混用时 LLM 答题可能引用私库 chunk + 公网模型生成。

回答出去（导出聊天 / 截图）。

私库内容意外公开。

风险二：身份混淆。

某员工只对自己 office:zhangsan:* 有权限。

混用时如果检索范围跨多个员工的私库。可能返回别人的私库内容。

风险三：合规审查。

私库属个人 / 部门私有。公网 KB 属企业公开。混用让合规边界模糊。

## chayuan-desktop 的边界标识

每个 KB 的 privacy_level（前面文章讲）。

```
office:zhangsan:notes -> privacy: local
doc:public_policies -> privacy: public
```

混合检索时 chayuan-desktop 用最严格的策略。

如果命中任何 local KB → 不能用云模型。

如果命中任何 enterprise KB → 不能出企业。

最严策略主导。

## 用户警示

混合检索时弹提示。

```
您的检索包含：
  [local] office:zhangsan:notes
  [public] doc:hr_policies

由于含私库，本次回答将使用本地模型（不上云）。
[继续]
```

让用户对边界知情。

## UI 上的明确区分

KbSelectorDialog 里 KB 按 privacy_level 分组显示。

```
[私库 (local)]
  office:zhangsan:notes
  office:zhangsan:meetings
[企业 (enterprise)]
  doc:contracts
  doc:hr_policies
[公开 (public)]
  doc:public_policies
```

不让用户误把私库跟公网混。

## 引用气泡的颜色

颜色编码（前面文章讲）。

橙色：office:* 私库。

蓝色：doc:* 文档。

紫色：src:* 外部向量。

让回答里 哪部分来自私库 一目了然。

## 跨权限边界

某员工对 doc:contracts 有权限。对 doc:hr_personal 无权限。

chayuan-desktop 检索时按身份过滤。无权限的 KB 不参与。

某员工对 office:legal:contracts 有权限（法务部）。对 office:hr:personal 无权限。

完全隔离。

## 同名不同身份

某员工的 office:zhangsan:notes。其他员工看到时会混淆吗。

不会。chayuan-desktop 严格按身份过滤 KB。

zhangsan 看到 office:zhangsan:notes（自己的）。

lisi 看到 office:lisi:notes（自己的）。

互不可见。

## 跨身份引用

某身份A 在 chayuan-desktop 把别人的私库 chunk 复制到自己的对话里。技术上能（如果有权限）。但。

UI 不直接支持（避免误操作）。

如果走 API 直接复制内容粘贴到 chat 框 = 走身份 A 自己的对话。原私库引用关系丢失。

## 国产化场景

党政军对私库 / 公库严格区分。chayuan-desktop 的多级 + 颜色 + 警示满足。

某些等保场景禁止跨级检索（私库不能跟公开数据混合查）。chayuan-desktop 配置可禁用。

## chayuan-server 的对应

chayuan-server 多用户场景下边界更严（多个员工的私库严格隔离）。chayuan-desktop 单机简化但原则一致。

## WPS 加载项

chayuan-wps 在 WPS 里展示同样的颜色编码 + 警示。员工写报告时不会无意中混用。

## 总结

私库与公网 KB 的边界是 chayuan-desktop 在数据隔离上的工程红线。免费开源的AI软件 让 不同隐私级数据 严格隔离。chayuan-desktop 的级别 + 颜色 + 警示 + 严格策略让混用风险降低。
