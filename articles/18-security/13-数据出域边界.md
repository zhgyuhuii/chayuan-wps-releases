# 数据出域的边界 哪些操作可能把数据带走

chayuan-desktop 桌面单机版的数据出域边界。这一篇讲。

## 出域的几种方式

方式一：发给云 LLM。prompt 含数据 → 上传到 OpenAI / Claude / 国产云。

方式二：发给云 embedding / rerank。

方式三：上传到外部向量库（src:milvus 等）。

方式四：导出 KB。导出包带出本机。

方式五：聊天记录导出。含数据片段。

方式六：截图 / 复制。手动出域。

方式七：第三方 mcp 工具。某些工具调用上传数据。

每种都有风险。

## chayuan-desktop 的边界标识

每个 KB 配 privacy_level。

```
local: 完全本地，不出本机。
enterprise: 不出企业（chayuan-server 部署）。
public: 公开数据，能上云。
```

KB 创建时用户选。

## 操作前的检查

用户问问题。chayuan-desktop 检测。

如果命中 local KB 但用云模型 → 弹用户确认。

如果命中 enterprise KB 但出企业 → 拒绝（违反企业策略）。

如果命中 public KB → 自由处理。

## 出域日志

每次数据出域写审计。

```json
{
  "action": "data_export",
  "type": "to_cloud_llm",
  "destination": "OpenAI GPT-4o",
  "data_summary": "5 chunks from doc:contracts (privacy:public)",
  "user_confirmed": true,
  "trace_id": "..."
}
```

完整可追溯。

## 用户警示的设计

弹窗清晰。

```
[隐私警示]
您的请求会把以下内容发送给 OpenAI（位于美国）：
- 当前 prompt 内容
- 命中的 5 个 chunk（来自 doc:contracts）

数据可能被 OpenAI 暂存或用于服务改进（参见 OpenAI 隐私政策）。

是否继续？
[继续] [改用本地模型] [取消]
```

让用户做知情决策。

## 默认严格

chayuan-desktop 默认。

local KB 不能用云模型。强制本地。

enterprise KB 在企业部署外不能用。

public KB 自由。

避免无意中出域。

## 自定义策略

用户能调宽（自己负责）。

```yaml
data_governance:
  allow_local_kb_to_cloud: false  # 默认
  allow_enterprise_kb_to_external: false
  warn_on_pii_export: true
```

## 出域审计的查询

设置 - 审计 - 数据出域查询。

```
查询时间范围：[起] [止]
出域类型：[全部 / 云 LLM / 外部向量 / 导出包]
[查询]
```

帮用户回顾。

## 文件级别

某些文档标记 不能导出。

文档级别。

```yaml
file: confidential_report.docx
exportable: false
```

chayuan-desktop 检测到该文件不能进入云 LLM prompt。强制本地。

## 国产化场景

党政军对数据出域极严。chayuan-desktop 的边界 + 警示 + 审计满足。

某些等保场景禁止任何数据出网。chayuan-desktop 配置 全部本地 模式。所有云 API 都禁用。

## chayuan-server 的对应

chayuan-server 多用户场景下边界由企业级配置。chayuan-desktop 单机用户级。两者一致。

## WPS 加载项

chayuan-wps 在 WPS 里调 chayuan-desktop。出域检查同样生效。WPS 用户看到同样警示。

## 总结

数据出域的边界是 chayuan-desktop 在隐私保护上的工程红线。免费开源的AI软件 让 数据出域 不再是无意识的事。chayuan-desktop 的隐私级别 + 警示 + 审计 + 默认严格让数据流向可控。
