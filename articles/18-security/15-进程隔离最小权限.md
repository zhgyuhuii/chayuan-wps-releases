# 进程隔离与最小权限 单机版的现实约束

chayuan-desktop 桌面单机版的进程隔离与最小权限。这一篇讲。

## 进程构成

chayuan-desktop 启动后涉及的进程。

主进程（Tauri，Rust）。UI + 主控。

Python sidecar。后端业务逻辑。

Ollama（可选）。LLM 推理。

mcp 工具子进程。每个 mcp 工具独立。

各自独立。互不干扰。

## 为什么进程隔离

某子进程崩溃不影响主进程。

某子进程被攻击不能直接攻击主进程。

资源限制能针对子进程独立设置。

## 最小权限

每个子进程只给必要权限。

主进程：完整 OS 用户权限。

Python sidecar：跟主进程一样。需要管 KB 数据。

Ollama：网络（仅 127.0.0.1） + 模型文件读写。

mcp 工具子进程：按工具描述的能力声明限。

## 沙箱实现

Linux 沙箱用 unshare + cgroups。

```
unshare --net --pid --mount mcp_tool
```

子进程在独立网络命名空间（不能访问其他子进程的网络）。

cgroups 限 CPU / 内存。

macOS 沙箱用 sandbox-exec。

```
sandbox-exec -p '(deny default) (allow ...)' mcp_tool
```

明确允许的操作。其他都拒绝。

Windows 沙箱用 Job Object + AppContainer。

## chayuan-desktop 的最小权限

主进程不需要 sudo。

数据目录在 ~/.chayuan/。属当前用户。

不修改系统文件。

不安装系统服务（除非用户主动配 systemd）。

不需要 root 即可使用。

## 网络的最小权限

chayuan-desktop 默认只监听 127.0.0.1:62581。

不监听公网 IP。

mcp 工具按声明放行特定域名。

```
github_mcp 允许：api.github.com, github.com
其他工具默认禁网。
```

## 文件访问

mcp 工具只能访问自己工作目录。

```
~/.chayuan/mcp_data/<tool_name>/
```

某些工具显式申请用户文件访问（filesystem-mcp）。chayuan-desktop 弹用户授权。

## 进程间通信

主进程跟 sidecar：HTTP 127.0.0.1。

主进程跟 mcp：stdio。

主进程跟 Ollama：HTTP 127.0.0.1。

都本机内。无外部暴露。

## 资源限制

每个子进程的限制。

```yaml
mcp_tools:
  default_limits:
    cpu_percent: 50
    memory_mb: 1024
    fd_count: 1024
    network: limited
```

避免某进程吃光系统资源。

## 用户的可见性

chayuan-desktop UI 显示子进程状态（监控面板）。

```
进程状态：
  主进程: ✓ 运行中（PID 12345）
  Python sidecar: ✓（PID 12346）
  Ollama: ✓（PID 12347）
  github_mcp: ✓（PID 12348，CPU 5%）
```

让用户对系统状态有数。

## 国产化场景

党政军场景对系统隔离严格。chayuan-desktop 的进程隔离 + 最小权限符合等保要求。

某些场景禁止运行第三方进程（如未审批的 mcp 工具）。chayuan-desktop 的白名单机制满足。

## chayuan-server 的对应

chayuan-server 多用户场景下进程隔离更复杂（容器化部署）。chayuan-desktop 单机基础。

## WPS 加载项

chayuan-wps 跑在 WPS 进程内。WPS 自己有沙箱（加载项级）。chayuan-wps 受 WPS 沙箱保护。

## 总结

进程隔离与最小权限是 chayuan-desktop 在系统安全上的工程基础。免费开源的AI软件 让 单机也有沙箱。chayuan-desktop 的多进程 + 沙箱 + 最小权限 + 资源限制让单机系统稳健。
