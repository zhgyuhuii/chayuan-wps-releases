# 备份与加密备份 凭据要不要一起带

chayuan-desktop 桌面单机版的备份与加密备份。凭据是否一起备份。这一篇讲。

## 备份的内容

完整备份含。

KB 数据（chunks、embeddings）。

聊天历史。

设置（默认模型、KB 选择等）。

凭据（API Key、模型源、私钥等）。

模型权重（可选，体积大）。

凭据是否一起备份是关键问题。

## 凭据一起备份的好处

恢复时凭据自动恢复。

换电脑或重装时不必重新填 API Key。

便利。

## 凭据一起备份的风险

备份文件如果泄露。凭据被读。

如果备份只是文件夹复制，凭据明文（理论上 Stronghold 加密的本地用，但备份还原后能在新机器解锁吗？）。

加密备份需要专门处理凭据。

## chayuan-desktop 的备份策略

策略一：默认不含凭据。

完整备份 = KB + 历史 + 设置 + 模型。

不含凭据。恢复时用户重新填 API Key。

更安全。

策略二：含凭据（可选）。

用户能选 凭据一起备份。

备份时密码保护。

恢复时密码解锁。

## 加密备份

```
chayuan-desktop 设置 - 备份 - 加密备份
设置备份密码：[输入]
```

备份用 AES-256 加密。

```
chayuan-backup-2026-05-10.zip.enc
```

恢复时密码解锁。

如果忘了密码 → 备份不可恢复（chayuan 公司没法帮）。

## 备份位置

本地。

```
~/.chayuan/backups/
  daily/
    backup-2026-05-10.zip
    backup-2026-05-09.zip
    ...
```

每天自动备份保留 7 天。

远程。

OneDrive、坚果云、NAS 等。

```yaml
remote_backup:
  enabled: true
  type: webdav
  url: https://nas.corp.com/dav
  username: ...
  password: <stronghold encrypted>
  schedule: weekly
```

每周上传到远程。

## 凭据的特殊处理

凭据存在 Tauri Stronghold 文件（独立文件）。

```
~/.chayuan/secrets/keystore.stronghold
```

备份时。

不含凭据：跳过这个文件。

含凭据：复制这个文件到备份。

恢复时凭据需要原 Stronghold 主密码解锁（即使备份了也安全）。

## 备份的完整性

每个备份带哈希。

```
chayuan-backup-2026-05-10.zip
chayuan-backup-2026-05-10.zip.sha256
```

恢复前校验完整性。

## 增量备份

每次全量备份占空间。chayuan-desktop 支持增量。

只备份上次备份后的变化。

复用未变文件。

省空间。

## 备份的保留

保留策略可配。

```yaml
retention:
  daily: 7  # 保留最近 7 天
  weekly: 4  # 4 周
  monthly: 12  # 12 月
```

按周期清理旧备份。

## 恢复流程

```
chayuan-desktop 设置 - 恢复
[选择备份文件]
[输入密码（如果加密）]
[选择恢复内容]
  ✓ KB 数据
  ✓ 聊天历史
  ✓ 设置
  ✗ 凭据（默认不恢复）
[恢复]
```

灵活控制恢复内容。

## 国产化场景

党政军场景对备份合规。chayuan-desktop 的加密备份 + 完整性校验满足。

某些场景禁止凭据出本机（即使加密备份）。chayuan-desktop 的默认不含凭据满足。

## chayuan-server 的对应

chayuan-server 多用户场景下备份集中。chayuan-desktop 单机本地。两者协议一致便于切换。

## 总结

备份与加密备份是 chayuan-desktop 在数据可恢复上的工程能力。免费开源的AI软件 让 备份不丢数据 + 凭据安全 兼顾。chayuan-desktop 的默认不含凭据 + 加密选项 + 增量备份让备份策略既安全又灵活。
