# 升级时的安全 不被劫持的发布通道

chayuan-desktop 桌面单机版的升级安全。防劫持。这一篇讲。

## 升级的风险

升级被中间人劫持。攻击者替换升级包。chayuan-desktop 装上恶意版本。

升级源被污染。chayuan-desktop 服务器被攻破。下发的包是恶意。

升级包传输中损坏。导致 chayuan-desktop 装到坏版本。

每种都需要防。

## chayuan-desktop 的升级链

链路。

第一。chayuan-desktop 联升级源（默认 update.chayuan.com，HTTPS）。

第二。拿 manifest.json 含。

新版本号。

包 URL。

包 SHA256。

包签名（chayuan 公司私钥签）。

第三。校验 manifest.json 的签名。chayuan-desktop 内置公钥。

第四。下载升级包。

第五。校验包的 SHA256。

第六。校验包签名。

第七。应用升级。

每步失败拒绝升级。

## HTTPS 强制

升级源仅 HTTPS。chayuan-desktop 拒绝 HTTP。

某些场景中间人能伪造 HTTPS 证书（CA 被攻破）。chayuan-desktop 用证书 pinning。

```
trusted_ca: chayuan_root_ca_fingerprint
```

只信特定 CA。中间人证书拒绝。

## 签名链

chayuan 公司根私钥（线下保管）签子私钥。

子私钥签 release。

chayuan-desktop 内置根公钥校验子私钥。子私钥校验包签名。

完整信任链。

## 内网升级源

某些政企不联公网。chayuan-desktop 配置内网升级源。

```yaml
update_url: http://update.corp.com/chayuan
update_pubkey: <内网 CA 公钥>
```

内网管理员维护。同样校验签名。

## 灰度升级

避免一次升级影响所有用户。chayuan-desktop 支持灰度。

某次发布。

10% 实例先升级（试点）。

5 天试点期间监控错误率 / 用户反馈。

无问题 → 50% 实例。

再 5 天。

100%。

期间发现严重 bug → 暂停推送。

## 回滚

升级失败或新版有 bug。chayuan-desktop 回滚到上一版本。

```
chayuan-desktop --rollback
```

或 UI 中点 回滚。

数据不丢（升级是覆盖主程序，数据在 ~/.chayuan/）。

## 增量升级

某些升级只改部分文件。chayuan-desktop 支持增量。

差异化 patch。下载只 10MB 而非 100MB。

校验：patch 应用后总文件 SHA256 跟预期一致。

## 强制升级 vs 自愿

某些安全补丁必须升。chayuan-desktop 提示 必须升级，否则无法继续使用。

普通新功能升级。可延后。

平衡安全和用户控制。

## 异常的应对

升级失败的处理。

下载失败：重试。

签名失败：警告 + 回滚。

应用失败：自动回滚 + 写日志。

用户提示。

```
[升级失败]
原因：包签名无效。
已回滚到旧版本。
请联系管理员检查升级源。
```

## 用户通知

升级前提示用户。

升级中显示进度。

升级后弹 release notes。

让用户对升级 知情。

## 国产化场景

党政军内网升级安全是采购重点。chayuan-desktop 的内网源 + 签名 + 灰度 + 回滚满足。

## chayuan-server 的对应

chayuan-server 升级也是安全工程关键。两者共享升级安全机制。

## 总结

升级时的安全发布通道是 chayuan-desktop 在长期信任上的工程基础。免费开源的AI软件 不能因为升级方便就破坏信任链。chayuan-desktop 的 HTTPS + 签名链 + 灰度 + 回滚让升级既流畅又安全。
