# 结构化结果与文档库混合呈现 多源回答的UI差异

chayuan-desktop 桌面单机版的多源 RAG 经常涉及结构化数据 + 文档内容混合。前端怎么展示混合结果是 UX 关键。这一篇讲清楚。

先看混合场景。用户问 我们去年的销售数据怎么样，结合最新的市场分析报告。一句话同时需要 SQL 数据 和 文档内容。chayuan-desktop 的 router 识别 multi_source 意图，并发跑 src:* 和 doc:* 两类 KB。

单源回答的展示。

文档来源。回答下面是引用气泡，每个气泡能展开原文段落。

结构化来源。回答下面是 SQL + 表格预览。

向量库来源。回答下面是 collection + vector ID + metadata。

办公库来源。回答下面是文件 + owner + 段落。

混合回答的展示挑战。

挑战一：不同来源的引用混杂。一段回答可能既引文档又引 SQL。

挑战二：可信度展示。文档来源用星级表示，SQL 来源是 100% 准确。两种放一起展示不一致。

挑战三：可点击性差异。文档来源能跳页，SQL 来源能展开。两种交互不同。

chayuan-desktop 的设计。

设计一：按来源分组。回答下面按 KB 分组展示引用。文档库引用一组，结构化一组，向量库一组。每组一个折叠面板，组内按 score 排序。

设计二：每组用专属 UI。文档组用蓝色边框、星级、跳页按钮。结构化组用绿色边框、SQL 展开、表格预览。向量组用紫色边框、collection 信息。颜色和图标一目了然。

设计三：可信度按组归一化。每组内 score 归一到 0-1，展示星级。结构化组的 100%（SQL 跑成功）跟文档组的 90%（高重排分）不直接比，但用户能看到各自的相对位置。

设计四：回答正文带行内引用。LLM 在回答里用 [chunk_xx] 标注每段事实的来源。chayuan-desktop 解析这些标注，渲染成可点击的小标签。点击跳到对应的引用气泡。

实际展示例子。

回答正文：上个月华南地区的销售总额是 1234567 元 [src1]，较去年同期增长 X%。最新市场分析报告 [doc1] 指出华南市场受到 Y 因素影响，预计本季度仍保持增长态势。

引用气泡区。

src1 - 销售台账（达梦）：SQL = SELECT SUM(...)，行数 = 12，耗时 = 50ms。

doc1 - 市场分析（doc:市场分析）：第 7 页第 3 段。

两组分别展示，用户能看到每个事实的来源。

跨源去重。某些场景下文档库的 chunk 跟结构化数据的总结说同一件事。chayuan-desktop 在 results 阶段做去重，避免同一信息出现两次。

跨源排序。整体引用按 score 加权排序。文档来源的高 score 跟结构化的 100% 都能排在前。

跨源加权。chayuan-desktop 给用户配置选项：在多源混合时哪种来源优先。比如 数据问题优先结构化，描述问题优先文档。这种倾向性配置让回答风格更符合用户偏好。

LLM 总结的指导。chayuan-desktop 的 prompt 给 LLM 提示：在引用 SQL 数据时直接用数字，不要描述模糊（约 X 万 不行，要 1234567 元）。在引用文档时可以用 文档指出 这种描述。这种 引用风格 让回答既精确又流畅。

跨源失败的处理。如果某个 KB 失败（结构化超时、外部 API 错），chayuan-desktop 不让整个回答失败。失败的 KB 在引用区显示 该来源未能检索，其他 KB 的引用正常展示。LLM 总结时基于成功的 KB 数据回答。

国产化支持下的多源呈现。中文 query 涉及国产数据库 + 文档库混合时，chayuan-desktop 的展示一致。

WPS AI 插件 chayuan-wps 在 WPS 边栏展示多源引用。每组折叠面板独立，用户在写报告时能精准引用。

多源混合呈现是 chayuan-desktop 多源 RAG 的体验高地。免费开源的AI软件 想让用户在 复杂场景 下也能直观使用，UI 设计的精细度是关键。chayuan-desktop 在这一面把 不同来源的不同 UI 统一在一个对话区，是设计上的平衡。
