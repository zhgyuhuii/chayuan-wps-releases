# 聚合意图识别 有几个用户该走COUNT而不是RAG

chayuan-desktop 桌面单机版有一条产品上的硬规则：聚合问题不应该走文档 RAG。这一篇讲清楚 router 是怎么识别聚合意图的。

先看错误的做法。早期某些 AI 客户端的处理：用户问 我们公司有多少员工，模型在文档库里搜 包含员工字段的内容，找到几段含数字的 chunk，让 LLM 综合给个数。这种处理常常给出错误数字（有的 chunk 是 2024 年的数据有的是 2025 年的）。

正确的做法。把这种问题路由到结构化 KB 跑 SELECT COUNT(*) FROM employees。返回精确数字。

router 怎么识别聚合意图。chayuan-desktop 的 router 模块有几条启发规则。

规则一：聚合关键词。中文 多少、几个、几位、总数、总和、合计、共有、平均、最高、最低、最大、最小、个数。英文 how many、count、total、sum、average、max、min、average。命中这些词倾向 structured_aggregate。

规则二：实体识别。query 中的实体名词（用户、订单、员工、产品、客户）跟现有结构化 KB 的表名对应。chayuan-desktop 的 schema 提示让 router 知道哪些实体是 SQL 表，哪些只在文档里。

规则三：动词模式。问 列出X 倾向 SELECT。问 多少X 倾向 COUNT。问 总X 倾向 SUM。每种动词对应不同 SQL 结构。

规则四：数据类型暗示。query 涉及数字、金额、百分比等明显数值含义时倾向结构化。

router 的输出。识别为 structured_aggregate 后，router 把 query 转成 plan：调 structured adapter，给定 KB ID 和 query。adapter 跑 text2sql 流程。

边界情况。

边界一：模糊 query。比如 我们公司怎么样。这种 query 没有聚合也没有具体实体。router 走 document_qa 默认。

边界二：跨多源混合。比如 我们去年的销售数据怎么样，结合最新市场报告。router 识别 销售数据 走 structured，市场报告 走 document，混合检索。

边界三：表里没有相关字段。query 想 COUNT 但 KB 没合适的表。chayuan-desktop 让 LLM 先尝试，schema linking 失败时告诉用户 当前 KB 不能回答聚合问题，建议加结构化 KB。

边界四：分类聚合。比如 按部门统计员工数。这是 GROUP BY + COUNT。router 识别 按X 关键词知道要 GROUP BY。

边界五：时间窗口聚合。比如 每月销售额。这是 GROUP BY DATE_TRUNC('month', xxx)。chayuan-desktop 的 LLM prompt 提示这种时间分组语法。

CLAUDE.md 里的硬要求。 有几个用户 这种问题必须命中 structured_aggregate 加 COUNT。chayuan-desktop 的合同测试里专门有这一条。如果某次 PR 改了 router 逻辑导致这个问题不命中聚合，测试失败。

LLM 辅助意图分类。chayuan-desktop 默认走规则启发，但配置开关可以让 LLM 做意图分类（更准但延迟增加 200-500ms）。某些复杂场景下 LLM 分类比规则强。

意图模糊时的兜底。如果 router 不确定（比如关键词匹配多个意图），chayuan-desktop 默认走 多策略并行：同时跑 document_qa 和 structured_aggregate，结果合并交给 LLM 选最相关的。这种 hedge 让边界场景仍能给出合理答案。

可观测性。router 的每次决策记录到 trace 日志：识别的意图、选用的 plan、回退策略。开发者排查 这个问题为什么走错路径 时这些日志关键。

中文意图识别的复杂性。中文表达多样：多少、几个、若干、几位 是同义词。问句结构多样：有多少 vs 总数是多少。chayuan-desktop 的规则覆盖主流表达，但某些极端表达可能漏识别。

国产化支持下的意图识别。中文 query 跟英文 query 的意图识别走同一套 router，关键词列表中英对照。

WPS AI 插件 chayuan-wps 在 WPS 里发起聚合问题同样走 router 判定。比如在 WPS 写销售月报时问 销售数据，加载项调起 chayuan-desktop sidecar，router 识别意图，自动调 src:* 结构化 KB。

聚合意图识别是 chayuan-desktop 多源 RAG 的智能分发层。免费开源的AI软件 想让用户不用懂 这个问题该用哪个 KB，router 必须做对意图判断。chayuan-desktop 在这一面的工程化是结构化 KB 体验的基础。
