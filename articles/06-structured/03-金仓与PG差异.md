# 金仓KingbaseES方言适配点 与PostgreSQL的差异

金仓 KingbaseES 是另一款国产数据库代表（人大金仓），基于 Postgres 二次开发。chayuan-desktop 桌面单机版对金仓的支持是国产化清单的一部分。这一篇讲金仓接入和方言细节。

先看金仓的位置。它是国产化清单里 Postgres 兼容 的代表，跟达梦的 SQL Server/Oracle 风格 互补。许多政企客户因为信创要求把 Postgres 应用迁移到金仓。

跟标准 Postgres 的关系。金仓基于 Postgres 二次开发，大部分语法和功能继承自 PG。SQLAlchemy 接入金仓可以直接用 postgres dialect，绝大多数情况下能跑通。

差异点一：字符集和编码。金仓默认 UTF-8。某些版本支持 GB18030。chayuan-desktop 接入时连接字符串明确指定编码避免乱码。

差异点二：内置函数。金仓增加了一些 PG 没有的函数（兼容 SQL Server 或 Oracle 的语法）。chayuan-desktop 的 text2sql LLM prompt 不专门列金仓特有函数，主要靠标准 PG 语法生成 SQL，覆盖大多数场景。

差异点三：性能优化。金仓针对国产 CPU（飞腾、鲲鹏）做过优化。在国产化部署时性能不输标准 PG。chayuan-desktop 的查询在金仓上的延迟跟标准 PG 接近。

差异点四：扩展支持。金仓支持 PG 的扩展（pg_trgm、postgis 等），但 pgvector 的支持要看金仓版本。如果金仓不带 pgvector，向量检索要走外部专门向量库。

差异点五：身份认证。金仓有自己的认证模型，跟 PG 兼容但增加了一些政企级特性（双因素认证等）。chayuan-desktop 的连接配置主要是用户名密码，复杂认证需求可能要扩展。

接入步骤。

第一步。chayuan-desktop 设置 - 新建知识库 - 结构化数据 - 外部数据库 - PostgreSQL（选这个，因为金仓用 PG 协议）。

第二步。host、port（金仓默认 54321 而不是 PG 的 5432）、user、password、database。

第三步。测试连接。chayuan-desktop 用 psycopg2 这种 PG 驱动连，金仓兼容。

第四步。选表和字段白名单。

第五步。建立 src:kb_xxx 命名空间的 KB。

实际查询例子。问 这个月的订单数量。chayuan-desktop 生成 SELECT COUNT(*) FROM 订单表 WHERE 创建时间 >= DATE_TRUNC('month', CURRENT_DATE)。这是标准 PG 语法，金仓直接执行。

金仓的几个特殊场景。

场景一：迁移。某些客户从原 PG 迁到金仓。chayuan-desktop 接入时只需要改连接信息，业务不变。这种 平滑迁移 是金仓选型的核心理由之一。

场景二：信创合规。某些项目硬性要求用国产数据库。金仓在信创清单里位置高。chayuan-desktop 接金仓让整个技术栈国产化。

场景三：多机房双活。金仓有自己的高可用方案。chayuan-desktop 接的是某个具体实例的连接，HA 切换由金仓自身处理。

性能跟 PG 对比。金仓在大多数 SQL 场景下性能跟 PG 接近。某些国产 CPU 优化场景下性能反而略高。chayuan-desktop 的 text2sql 跑在金仓上跟跑在 PG 上体感一致。

字段编码的处理。金仓某些版本默认字段名小写转换（跟 PG 一样）。chayuan-desktop 在 schema linking 时尊重这种转换，避免大小写不匹配的问题。

时间类型。金仓的 timestamp 跟 PG 一致。time zone 处理跟 PG 一致。日期函数（DATE_TRUNC、INTERVAL、AGE）都标准。chayuan-desktop 的 LLM 用标准 PG 语法生成时间相关 SQL。

事务隔离。金仓默认 READ COMMITTED。chayuan-desktop 的查询都是只读不涉及事务复杂性。

连接池。SQLAlchemy 默认 pool_size 5。金仓在高并发场景下不是瓶颈，单机版的 5 连接够用。

国产化部署的几个常见问题。

问题一：金仓服务起不来。可能原因：licence 文件问题、配置错、端口冲突。这是金仓本身的问题，跟 chayuan-desktop 无关。

问题二：连接超时。可能原因：网络、防火墙、金仓 listener 配置。chayuan-desktop 的诊断会清晰提示是网络层还是认证层失败。

问题三：表查不到。可能原因：schema 名错误、用户没权限、表名大小写不一致。chayuan-desktop 在 schema linking 时检查这些。
