# 数据库连接池在单机版的限制 不要把数据库当推理源

chayuan-desktop 桌面单机版接外部 SQL 数据库时用 SQLAlchemy 连接池。单机版有自己的限制，跟企业级 BI 系统处理大量并发查询不同。这一篇讲清楚。

先看连接池的作用。每次 SQL 查询都建新连接成本高（TCP 握手、认证、初始化）。连接池预先建几个连接复用，每次查询从池里拿一个。chayuan-desktop 默认 pool_size=5、max_overflow=5，意味着同时最多 10 个连接。

单机版的实际场景。一个用户在一个时刻最多发起几个查询（多 Tab 并行最多 5-10）。pool_size 5 + overflow 5 完全够。每个查询用一个连接，跑完归还池。

pool 满的处理。如果用户突然发起几十个查询（不太可能，但理论上），池满后新查询排队等。SQLAlchemy 默认等 30 秒超时。chayuan-desktop 不主动改这个超时。

不要把数据库当 推理源。这是个工程原则。某些用户希望 让 LLM 反复查数据库做复杂推理。这种用法会让数据库连接被占用很久，影响其他用户。chayuan-desktop 限制单 query 30 秒超时，间接限制这种用法。

外部数据库的连接。chayuan-desktop 接的外部 PG、MySQL、达梦、金仓，连接是网络的。如果数据库服务器在远程（比如不同机房），网络延迟会影响每次查询。pool 避免了重复建连接的开销。

连接池的健康检查。SQLAlchemy 默认对每个连接做 pre-ping（每次拿连接前 ping 一下确认还活着）。chayuan-desktop 默认开启 pool_pre_ping，避免死连接的问题。

连接的回收。如果连接长时间不用（比如 1 小时），数据库可能主动断开。SQLAlchemy 的 pool_recycle 配置默认 3600 秒，到期回收连接。chayuan-desktop 用默认值。

连接池的诊断。chayuan-desktop 的诊断里能看到当前连接池状态：当前活跃连接数、空闲连接数、总池大小。开发者排查 数据库连接异常 时这些数据有用。

外部数据库的故障。如果外部 PG 服务挂了，chayuan-desktop 接到的连接失败错误。每个查询独立失败，不影响其他外部源（每个外部源有自己的池）。

跨数据库的连接管理。chayuan-desktop 给每个 src:* KB 维护独立的连接池。比如 src:pg_main 和 src:dm_finance 各有 5 + 5 连接。互不影响。

连接配置的存储。每个 KB 的连接信息（host、port、user、password）加密存到 CHAYUAN_ROOT/data 的 connectors 表。密码加密用 Stronghold + ChaCha20。

连接的安全。chayuan-desktop 推荐用专门的 只读用户 连接外部数据库。这个用户在数据库里只授权 SELECT 权限，没 INSERT/UPDATE/DELETE。这是 在数据库层面的额外防护，跟 chayuan-desktop 的 AST 校验形成双重保险。

读写分离。如果外部数据库有 master/slave 架构，chayuan-desktop 推荐连 slave。slave 是只读副本，避免对生产 master 的影响。

SSL 连接。某些数据库要求 SSL 连接（特别是云数据库）。chayuan-desktop 的连接配置支持 SSL 参数（ssl_ca、ssl_cert、ssl_key）。

国产数据库的连接特殊性。

达梦 DM。除了用户名密码还有 schema 配置。

金仓 KingbaseES。默认端口 54321（不是 PG 的 5432）。

Doris。MySQL 协议但部分行为略有差异，按 MySQL 配置。

跨平台连接。chayuan-desktop 的连接池在 Windows、macOS、Linux、麒麟 UOS 上行为一致。

WPS AI 插件 chayuan-wps 不直接管理连接，所有数据库访问通过 sidecar。加载项的查询跟桌面客户端共用同一份连接池。

连接池在单机版上的限制看起来是工程细节，实际决定单机版能扛多少并发。免费开源的AI软件 给单机用户的合理预期是 自己用顺，不是 多人共享。chayuan-desktop 的连接池配置符合这个定位。
