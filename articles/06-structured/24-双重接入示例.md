# 同一表又作doc又作struct的双重接入示例

chayuan-desktop 桌面单机版支持把同一份数据既作为文档库又作为结构化库。这一篇用一个具体例子讲清楚什么时候双重接入有意义。

先看场景。一个公司的客户管理表 customers。表结构含 id、name、phone、email、address、industry、size、relationship_notes（客户关系备注，每条 200-500 字描述）、created_at。

只接 src:* 结构化的局限。SQL 能查 客户数量、按行业分组、最大客户、注册时间分布 这些结构化问题。但是 跟客户关系如何 这种基于 relationship_notes 的语义搜索，SQL 不擅长（除非用全文检索，但 relationship_notes 这种叙述性内容向量检索更合适）。

只接 doc:* 文档的局限。relationship_notes 作为 chunk 入库后能做语义搜索。但 总共多少客户、按行业统计 这种聚合问题文档库做不了。

双重接入的解决。同一份 customers 表既建 src:customers_db（结构化）又建 doc:customer_notes（文档库）。SQL 问题走 src，语义问题走 doc。

实际配置。

src:customers_db 配置。把整张表作为结构化 KB，所有字段进白名单（除 PII 字段）。LLM 可以走 text2sql 查 customer 表。

doc:customer_notes 配置。从 customers 表导出 relationship_notes 字段（按 id + name + relationship_notes 拼成每条 chunk）。每条 chunk 用 bge-m3 嵌入。把 customer 的 id、name、phone 等结构化字段作为 chunk metadata。这样 chunk 不只有文字还能精确关联到结构化数据。

混合检索。用户问 哪些客户的关系比较紧张。query 涉及 relationship_notes 的语义搜索，走 doc:customer_notes。检索命中几个 chunk，每个 chunk 的 metadata 含 customer_id 和 name。LLM 在回答里直接给出客户名。

进一步混合。用户问 大型企业里关系比较紧张的客户有哪些。这是结构化 + 语义混合。chayuan-desktop 的 router 识别 multi_source 意图。

第一步。src:customers_db 跑 SELECT id FROM customers WHERE size='large' 拿到大型企业 ID 列表。

第二步。doc:customer_notes 检索 关系紧张 语义命中的 chunk。

第三步。两边结果交集（chunk metadata 里的 customer_id 在第一步结果里）。

第四步。LLM 综合给出 大型 + 关系紧张 的客户列表。

这种 SQL 过滤 + 语义检索 + 交集 的混合让查询能回答 结构化 + 语义 复合问题。

双重接入的代价。

代价一：存储两份。customer 表的数据在 src KB 内（连接配置）和 doc KB 内（chunk 数据）两份。如果数据更新，两边要同步。

代价二：维护复杂。schema 变化时两边都要更新。

代价三：检索结果可能冲突。两边检索同一概念可能给出不一致的细节。chayuan-desktop 的去重和归一化处理这种边界。

什么时候用双重接入。

场景一：表里既有结构化字段也有大段叙述字段。客户表的备注、订单表的描述、医疗记录的诊断说明。

场景二：分析需求多元。既要统计又要语义。CRM、医疗记录、案件管理这种场景。

场景三：单源不够。结构化或文档单独都不能完整回答业务问题。

什么时候不该双重接入。

不该一：纯数字数据。销售台账、库存数据，纯 SQL 就够。

不该二：纯叙述数据。会议纪要、博客文章，纯文档就够。

不该三：数据频繁更新。两边同步成本高。

实操注意。

注意一：自动同步。chayuan-desktop 当前不自动从 src 表导出到 doc 库。用户需要手动设置导出脚本。这种手动 ETL 不太顺。

注意二：去重逻辑。两边检索可能命中同一客户。chayuan-desktop 的 results 模块根据 metadata 中的 customer_id 自动去重，避免 LLM 看到重复信息。

国产化支持下的双重接入。在国产数据库（达梦、金仓）上的 customers 表同样可以双重接入。流程一致。

WPS AI 插件 chayuan-wps 用同一份双重 KB。在 WPS 里写客户分析报告时勾上两个 KB，回答的引用气泡按来源类型分别展示。

同一表双重接入是 chayuan-desktop 在 复合数据 场景下的高级用法。免费开源的AI软件 给用户工具的灵活度，双重接入是这种灵活度的体现。
