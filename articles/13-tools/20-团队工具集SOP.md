# 一个团队工具集 自家系统接入的 SOP

某团队接入自家系统到 chayuan-desktop 的标准操作流程。这一篇是 SOP。

## 步骤一 调研

调研一：哪些系统员工天天用。

OA、ERP、CRM、Jira、自家工单系统。

按使用频次排序。优先接最高频的。

调研二：哪些系统有 API。

有 OpenAPI 规范的最方便（chayuan-desktop 一键导入）。

有 REST 接口但没规范的次之（手动写 mcp 工具）。

只有内部 SDK 的。要写 wrapper。

## 步骤二 立项

立项一：选 3-5 个目标系统。

立项二：分配开发资源。每个系统约 2-5 天工作量。

立项三：审批。安全部门、合规部门、IT 部门审。

## 步骤三 接入实施

实施一：环境准备。

申请测试账号 / Token。

申请测试 API 配额。

部署测试环境的 chayuan-desktop。

实施二：写 mcp 工具。

按 chayuan-desktop 的 mcp 模板（前面文章）。

测试用例覆盖核心场景。

实施三：配置鉴权。

OAuth 还是 Token。

Stronghold 加密存储。

## 步骤四 测试

测试一：单元测试。每个工具调用基础场景跑通。

测试二：集成测试。chayuan-desktop + mcp 工具 + 真实系统跑通。

测试三：LLM 行为测试。LLM 在给定场景下能否正确调用工具。

## 步骤五 安全审查

审查一：权限最小化。工具只申请必要权限。

审查二：参数校验。防 injection。

审查三：日志合规。审计日志按规范。

审查四：渗透测试。某些场景做（chayuan-desktop 暴露的端点是否安全）。

## 步骤六 试点

试点一：选 5-10 个用户试用。

试点二：收集反馈。

工具描述好不好用？

LLM 调用准确率？

是否有 边界 BUG？

试点三：修复 + 优化。

## 步骤七 正式发布

发布一：内部 npm 私服 / 工具市场上传 mcp 工具。

发布二：员工 chayuan-desktop 升级配置（自动或手动）。

发布三：发布说明 + 培训。

```
新增工具：corp_oa_mcp v1.0
功能：查询 OA 待办、审批
触发场景：问 AI "我有什么待办" / "帮我审批 X"
不可用场景：发起新审批（v1.0 还不支持）
```

## 步骤八 运维

运维一：监控。

工具调用成功率。

平均延迟。

错误聚合。

运维二：迭代。

按用户反馈持续优化。

按使用数据加新功能（高频但工具不支持的场景）。

运维三：安全更新。

依赖库升级。

CVE 处理。

## SOP 模板

chayuan-desktop 的工具开发文档提供完整 SOP 模板。包含。

立项申请表。

工具开发 checklist。

安全审查清单。

发布说明模板。

运维监控仪表板模板。

让团队照着做不缺步骤。

## 国产化场景

党政军场景的 SOP 还需加上。

涉密审查（如果系统涉密）。

等保备案（系统升级要重新备案）。

供应链审查（mcp 工具的依赖来源）。

## chayuan-server 的对应

chayuan-server 多用户场景下工具集中部署。SOP 重点在服务器侧。chayuan-desktop 单机 SOP 重点在员工电脑侧。

## WPS 加载项

chayuan-wps 在 WPS 里直接能用接入的工具。无需额外接入工作。员工感知就是 WPS 里 AI 工具更全了。

## 总结

团队工具集 SOP 是 chayuan-desktop 在企业级落地上的工程方法论。免费开源的AI软件 不只是 装上就能用，还要 系统接入有章法。chayuan-desktop 的 SOP 模板 + 工具市场 + 监控运维让 AI 接入企业 是工程项目而非冒险尝试。
