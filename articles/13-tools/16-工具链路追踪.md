# 工具的链路追踪 一次请求里所有工具的火焰图

chayuan-desktop 桌面单机版的工具调用链路追踪可视化。火焰图展示一次请求所有工具的耗时和依赖。这一篇讲。

## 链路追踪的价值

复杂请求可能涉及多个工具调用。每个工具又可能内部调多个子操作。

某次请求慢。是哪一步慢。

某次请求失败。是哪一步失败。

火焰图给视觉答案。

## 数据收集

chayuan-desktop 给每次请求生成 trace_id。所有相关操作（LLM 调用、工具调用、嵌入、检索）都打 trace_id 标签。

每个操作记 span。

```json
{
  "trace_id": "abc123",
  "span_id": "span_1",
  "parent_span": null,
  "name": "user_request",
  "start": "...",
  "duration_ms": 5234,
  "children": [
    {"name": "llm.chat (gpt-4o)", "duration_ms": 1200},
    {"name": "tool.kb_search", "duration_ms": 234, "children": [
      {"name": "embedding.bge_m3", "duration_ms": 45},
      {"name": "vec_search", "duration_ms": 12}
    ]},
    {"name": "tool.send_email", "duration_ms": 890},
    {"name": "llm.chat (gpt-4o)", "duration_ms": 2900}
  ]
}
```

完整树状结构。

## 火焰图渲染

chayuan-desktop 的 设置 - 调试 - 链路追踪。

每条 trace 显示火焰图。

```
[user_request          5234ms]
  [llm.chat            1200ms]
  [tool.kb_search       234ms]
    [embedding.bge_m3    45ms]
    [vec_search          12ms]
  [tool.send_email      890ms]
  [llm.chat            2900ms]
```

宽度对应耗时。

## 性能瓶颈识别

看火焰图很容易识别瓶颈。

llm.chat 占了 4100ms，工具加起来 1100ms。说明大头在 LLM。

某个工具耗时 5 秒明显异常，平时 200ms。说明那次工具有问题。

## 失败追踪

失败操作在火焰图标红。

```
[tool.send_email      890ms ✗ rate_limited]
```

点击看详情（错误信息、参数、堆栈）。

## 跨工具的依赖

工具调用之间可能有数据依赖。

kb_search 的输出作为 send_email 的输入。

火焰图能用箭头表示依赖（理论上）。chayuan-desktop 当前简化为时间顺序展示。

## 跟 OpenTelemetry 的关系

链路追踪是 OpenTelemetry 标准能力。chayuan-desktop 的 trace 数据兼容 OpenTelemetry 格式。

```yaml
chayuan-desktop:
  observability:
    otel_export:
      enabled: true
      endpoint: http://otel-collector.corp.com:4317
```

某些政企用 Jaeger 或 Tempo 集中分析。chayuan-desktop 能 export。

## 数据保留

trace 数据每条占几 KB。chayuan-desktop 默认保留最近 1000 条。

设置里能调（保留更多消耗磁盘）。

## 隐私考虑

trace 含用户输入和工具结果。可能含敏感信息。

默认 trace 数据脱敏（参数里的密码、token、长字符串等）。

调试模式下能看完整。

## 国产化场景

党政军场景对运维可观测性重视。chayuan-desktop 的链路追踪满足。集成到企业级监控（Tempo / SkyWalking）。

## chayuan-server 的对应

chayuan-server 多用户场景下 trace 集中。chayuan-desktop 单机本地。

## WPS 加载项

chayuan-wps 在 WPS 里发起的请求也产生 trace。源应用字段 = wps，区分桌面端和 WPS 调用。

## 总结

工具的链路追踪是 chayuan-desktop 在 AI 工作流可观测上的工程支持。免费开源的AI软件 让 复杂请求 不再是黑盒。chayuan-desktop 的 trace 数据 + 火焰图 + OpenTelemetry 兼容让 性能调优 + 故障排查 有数据有工具。
