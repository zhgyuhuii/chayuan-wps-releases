# 工具调用的三层折叠展示 后端是怎么生成那个折叠的

chayuan-desktop 桌面单机版的工具调用 UI 显示用三层折叠。这一篇讲后端实现。

## 三层折叠

层一：工具调用标识。最外层显示 已调用工具 X。简洁。

层二：调用参数和结果摘要。点开看 输入是什么、返回是什么的简短摘要。

层三：完整数据。继续展开看完整 input / output。

## 后端的数据生成

每次工具调用 chayuan-desktop 生成三层数据。

```json
{
  "tool_name": "github_mcp.list_repos",
  "level1": {"label": "已调用 list_repos"},
  "level2": {
    "input_summary": "用户: octocat",
    "output_summary": "找到 5 个仓库"
  },
  "level3": {
    "input_full": {"user": "octocat"},
    "output_full": [{"name": "...", ...}, ...]
  }
}
```

UI 按层级渲染。

## 摘要的生成

input_summary 和 output_summary 不是直接复制。chayuan-desktop 的摘要逻辑。

input：取关键参数。github 工具取 user 字段。slack 取 channel 字段。

output：按数量摘要。返回数组时显示 找到 N 个 X。返回单对象时显示关键字段。

某些场景调本地小 LLM 生成摘要。但日常用规则就够。

## 折叠的好处

好处一：聊天记录干净。用户不需要每次看完整 JSON。

好处二：可探索。需要细节时点开。

好处三：易复制。完整 input/output 能复制（调试用）。

## 多次工具调用的展示

某些回答中 LLM 多次调用工具（不同工具或同工具多次）。chayuan-desktop UI 把多次调用堆叠。

```
[已调用 github_mcp.list_repos]
[已调用 github_mcp.get_repo]
[已调用 web_fetch]
回答内容：...
```

每个独立折叠。用户能逐个查看。

## 失败调用的展示

某次工具调用失败。chayuan-desktop UI 红色显示。

```
[✗ github_mcp.list_repos 失败]
```

点开看错误信息和重试历史。

## 流式中的展示

LLM 边流式生成边调工具。UI 实时更新。

```
LLM 正在思考...
[正在调用 github_mcp.list_repos...]
[已完成]
LLM 整合中...
回答：你的 5 个仓库分别是...
```

让用户看到实时进展。

## 引用的折叠

工具结果有时是引用源。chayuan-desktop 把工具调用的输出 chunk 化，跟 RAG 引用同样展示。

工具返回的某段文本作为引用 chunk，UI 显示引用气泡。

引用气泡跟工具调用折叠并存。

## 折叠的可配置

某些用户喜欢看完整数据。chayuan-desktop 设置里能配。

```
工具调用展示：
  默认：折叠到 level1
  调试用户：默认 level3 展开
```

## 导出的处理

聊天导出（PDF / docx）时折叠展示按某个级别导出。默认 level2（摘要）。设置里可调到 level3（完整）。

## 国产化场景

党政军场景对工具调用透明度有要求。chayuan-desktop 的多层折叠让 用户能选择看多深。审计场景下导出 level3 完整。

## chayuan-server 的对应

chayuan-server 多用户场景下展示一致。chayuan-desktop 共享前端组件。

## WPS 加载项

chayuan-wps 在 WPS 里也支持折叠展示。WPS 侧栏空间小，默认折叠到 level1，需要展开时用户主动操作。

## 总结

工具调用的三层折叠展示是 chayuan-desktop 在 UX 平衡上的工程设计。免费开源的AI软件 让 工具调用透明 不污染聊天。chayuan-desktop 的三层数据 + 摘要生成 + 实时更新让 工具调用 在 UI 上恰到好处。
