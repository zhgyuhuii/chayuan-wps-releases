# 工具的版本与回滚 升级新版本不影响老对话

chayuan-desktop 桌面单机版的工具版本管理保证升级不影响老对话。这一篇讲。

## 工具升级的影响

某 mcp 工具升级。返回字段变了。

旧对话里 LLM 用了旧字段做某些操作（比如说 "我用 created_at 字段排序"）。

如果用户重新打开旧对话点 续写，新版工具返回的 created_at 可能没了（改成 timestamp）。LLM 困惑。

工具版本管理避免这种问题。

## chayuan-desktop 的版本绑定

每个对话记录所用工具版本。

```json
{
  "session_id": "sess_xyz",
  "tool_versions": {
    "github_mcp": "1.2.3",
    "slack_mcp": "0.5.1"
  }
}
```

会话绑定特定工具版本。

## 续写时的版本选择

用户重新打开旧对话续写。

策略一：用绑定版本。chayuan-desktop 启动旧版工具进程处理这个会话。

策略二：用最新版本。可能不兼容。

chayuan-desktop 默认策略一。新对话用最新版。老对话用绑定版。

## 多版本共存

某些场景需要新旧版本同时跑。

chayuan-desktop 同时启动 github-mcp 1.2.3 和 1.3.0。

老对话发到 1.2.3。新对话发到 1.3.0。

资源代价。每个版本一个进程。

某些工具老版本逐步废弃。chayuan-desktop 的清理策略。

```
工具版本超过 30 天未使用 → 提示用户删除。
```

## 升级不破坏

工具开发者的责任。新版本最好向后兼容。

```
v1.3.0 兼容 v1.2.x。新增字段不删旧字段。
```

如果必须 breaking change，发 v2.0.0 而不是 v1.3.0。版本号语义化让用户决策。

## 回滚

新版工具有 bug。chayuan-desktop 让用户回滚。

```
设置 - 工具 - github_mcp
  当前版本：1.3.0
  [回滚到 1.2.3]
```

回滚后所有新对话也用 1.2.3。

## 升级前提示

chayuan-desktop 升级 mcp 工具前。

```
github_mcp 1.2.3 → 1.3.0

变更说明：
  - 新增 fork_count 字段
  - 弃用 forks 字段（仍可用，建议改名）
  - 修复 list_repos 偶发 500 错误

是否升级？
[升级] [稍后] [跳过此版本]
```

让用户知情决策。

## 自动升级开关

某些用户不喜欢手动确认升级。设置里能开自动升级（minor 版本）。

major 版本仍要手动确认（可能 breaking）。

## 老对话的兼容性测试

chayuan-desktop 升级新版工具后能跑兼容性测试。

```
[兼容性测试]
  - 用近 30 天的对话样本测试新旧版工具的输出差异
  - 输出报告：5 处差异，均为新增字段，老对话不受影响
```

让用户对升级安全有信心。

## 国产化场景

党政军场景升级谨慎。chayuan-desktop 的版本绑定 + 回滚 + 兼容性测试满足保守升级风格。

## chayuan-server 的对应

chayuan-server 多用户场景下版本由管理员决定。chayuan-desktop 单机用户级。

## WPS 加载项

chayuan-wps 发起的对话也绑定工具版本。WPS 续写老对话时工具版本一致。

## 总结

工具的版本与回滚是 chayuan-desktop 在长期演进上的工程关键。免费开源的AI软件 让 工具升级 不打断用户。chayuan-desktop 的版本绑定 + 多版本共存 + 兼容性测试让升级既保守又积极。
