# 工具的输入提示工程 描述写得多详细才有效

chayuan-desktop 桌面单机版的工具描述影响 LLM 调用质量。这一篇讲工具描述的提示工程。

## 工具描述的重要性

LLM 看工具描述决定。

是否调这个工具。

什么时候调。

参数怎么填。

描述写得好。LLM 用得对。描述模糊。LLM 乱用。

## 好描述的特点

特点一：明确目的。一句话讲清工具能做啥。

不好：list repos。

好：列出指定 GitHub 用户的所有公开仓库。

特点二：包含使用场景。

```
description: 当用户询问 GitHub 项目、想看代码、需要找 repo 时使用此工具。
```

特点三：明确不能做的。

```
description: 仅返回公开仓库。私库需要 OAuth Token。本工具不能创建 / 删除 repo。
```

让 LLM 不要错调。

## 参数描述

每个参数都该有清晰描述。

```yaml
- name: query
  type: string
  description: |
    搜索关键词。
    支持英文和中文。
    例："machine learning" 或 "深度学习"。
    不要含特殊字符如 # 或 @。
```

含。

类型。

约束。

例子。

注意事项。

## 例子的力量

工具 schema 里加 examples 字段。

```json
"examples": [
  {
    "description": "搜索某用户的 repo",
    "input": {"user": "octocat", "type": "owner"}
  },
  {
    "description": "搜索某主题的 repo",
    "input": {"query": "machine learning", "language": "python"}
  }
]
```

LLM 看例子比看抽象描述更能理解怎么用。

## 错误信息的描述

工具失败时的错误信息也是描述的延伸。

```
{"error": "rate_limited", "message": "GitHub API 调用频率超过 5000 次/小时。请等待或换 Token。"}
```

错误信息让 LLM 知道下一步怎么办。

## 描述的长度权衡

太短：LLM 不清楚怎么用。

太长：占 prompt 上下文（30 个工具，每个 500 字描述就 15000 字了）。

chayuan-desktop 的策略。

简短：基本描述（50-100 字）。

完整：包含 examples 的版本。LLM 第一次询问该工具时 chayuan-desktop 给完整版。

## 多工具的命名一致性

某场景几十个工具。命名不一致 LLM 容易混淆。

约定：动词_对象 模式。

```
list_repos
get_user
create_issue
delete_branch
```

参数命名也一致。

```
所有 list_X 工具都用 limit 参数（不是 count、size、num）。
```

chayuan-desktop 的工具市场推荐统一约定。

## 工具描述的本地化

中文用户希望中文描述（前面文章讲）。chayuan-desktop 翻译。

LLM 看的描述（英文 vs 中文）影响调用。中文 LLM（Qwen）看中文描述更准。英文 LLM（GPT-4）看英文。

chayuan-desktop 按当前模型语言偏好选描述版本。

## 描述的版本管理

工具描述更新可能改变 LLM 行为。

```
v1: 列出 GitHub 仓库
v2: 列出 GitHub 用户的所有公开仓库（不含 fork）
```

v2 更精确。LLM 调用决策可能变化。某些场景退化。

chayuan-desktop 的 A/B 测试能比较新旧描述的实际效果。

## 国产化场景

国产模型（Qwen、文心、智谱）对中文工具描述理解最好。chayuan-desktop 鼓励工具开发者写中文描述。

## chayuan-server 的对应

chayuan-server 多用户场景下工具描述统一管理。chayuan-desktop 单机本地。共享工具市场。

## WPS 加载项

chayuan-wps 调工具看到的描述跟 chayuan-desktop 一致。员工调工具时 LLM 行为一致。

## 总结

工具描述的提示工程是 chayuan-desktop 给工具开发者的核心建议。免费开源的AI软件 让 工具好用 不只是接口好，还要描述好。chayuan-desktop 的命名约定 + 例子 + 多语言 + 长度策略让 LLM 调工具准确可靠。
