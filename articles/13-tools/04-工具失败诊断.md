# 工具调用失败的诊断 给用户看的错误

chayuan-desktop 桌面单机版的工具调用偶尔失败。这一篇讲诊断信息怎么生成。

失败的常见原因。

原因一：参数不对。LLM 传的参数不符合 inputSchema。比如缺必填字段、类型错。

原因二：外部 API 错。HTTP 工具调外部接口时收到 4xx 5xx。

原因三：超时。Python eval 30 秒、HTTP 请求 30 秒超时。

原因四：权限不足。文件操作没权限、API key 过期。

原因五：资源不足。内存 OOM、磁盘满。

原因六：网络不通。外部依赖不可达。

诊断信息分层。

第一层：用户友好。该工具调用失败，原因 X，建议 Y。

第二层：技术错误码。INVALID_PARAMS、HTTP_404、TIMEOUT、PERMISSION_DENIED 等。

第三层：完整 traceback。给开发者排查。

前端展示。工具调用卡片在失败时变红色边框。一行 summary 显示失败概要。展开看 args / output / 完整诊断。

LLM 看到失败后的行为。chayuan-desktop 把失败结果回给 LLM，让 LLM 决定下一步：

option一：换参数重试。LLM 调整参数再试。

option二：换工具。如果某个工具不行，调另一个相似工具。

option三：告诉用户。LLM 解释失败原因给用户，让用户决定。

具体例子。

例子一：LLM 调 web_search 但用户没配搜索引擎 API。错误：CONFIG_MISSING。LLM 告诉用户 该功能需要配置搜索引擎，请到设置中添加。

例子二：LLM 调 execute_sql 但 SQL 含写操作。AST 校验拒绝。错误：AST_VIOLATION。LLM 解释 当前 SQL 包含写操作，仅支持只读查询。

例子三：LLM 调 dingtalk 但 token 过期。错误：AUTH_EXPIRED。LLM 提示 钉钉 token 已过期，请重新授权。

例子四：HTTP 工具调外部 API timeout。错误：TIMEOUT。LLM 重试一次，仍失败告诉用户。

诊断日志。所有工具调用失败写到 CHAYUAN_ROOT/logs/tools.log。包括 tool_name、参数、错误码、完整错误信息、调用时间。

LLM 处理失败的 prompt 指引。chayuan-desktop 给 LLM 的 system prompt 含失败处理指引。让 LLM 不要 装作没失败 编答案，而是诚实告诉用户。

国产化支持下的诊断。中文错误信息按 i18n 设置展示。

WPS AI 插件 chayuan-wps 在加载项里展示工具调用失败提示。点击展开看详情。

工具调用失败的诊断是 chayuan-desktop 在工具透明度上的工作。免费开源的AI软件 不让用户被 黑盒失败 困扰，每次失败都给清晰原因。chayuan-desktop 在这一面的细节让用户能自助排查。
