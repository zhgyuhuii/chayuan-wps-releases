# 工具调用失败的诊断 给用户看的错误

chayuan-desktop 桌面单机版的工具调用失败给用户清晰的错误信息。这一篇讲。

## 失败的常见类型

类型一：参数错误。LLM 给的参数不符合 schema。

类型二：鉴权错误。Token 错或权限不足。

类型三：网络错误。连不上 API。

类型四：业务错误。API 返回错误（资源不存在、操作冲突等）。

类型五：超时。

类型六：工具进程崩溃。

每种类型不同处理。

## 错误的展示分级

层一（用户友好）：简短错误描述 + 推荐操作。

```
✗ 调用 GitHub 工具失败
  Token 已过期，请前往 设置 - 工具 - GitHub 更新。
  [打开设置]
```

层二（中等详细）：错误代码 + 业务上下文。

```
✗ github_mcp.create_issue
  错误：401 Unauthorized
  上下文：调用 POST /repos/octocat/test/issues
```

层三（开发者）：完整堆栈和 raw 响应。

```
[展开看完整堆栈]
TypeError: Cannot read property 'id' of undefined
  at handleResponse (mcp.js:42)
  ...
HTTP Response:
  Status: 401
  Body: {"message": "Bad credentials"}
```

UI 默认显示层一。点 详情 展开层二。再点 完整堆栈 展开层三。

## 错误码翻译

每个错误码有标准翻译。

```
401 → Token 已过期或无效
403 → 您没有权限执行此操作
404 → 请求的资源不存在
429 → 请求过于频繁，请稍后再试
500 → 服务器内部错误
503 → 服务暂时不可用
```

中文用户看友好。

## 推荐操作

不同错误推荐不同操作。

401。打开设置 - Token 配置。

403。联系管理员。

429。等几分钟再试 / 切换 Token。

网络错误。检查网络连接 / 切换工具。

参数错误。LLM 自动重试。

让用户知道下一步该做什么。

## LLM 看到的错误

错误信息也传给 LLM 让它纠正。

```
{"error": "rate_limited", "retry_after": 60}
```

LLM 看到能。

等 60 秒重试。

切换其他工具。

告诉用户暂时无法完成。

## 工具失败的可视化

聊天里失败的工具调用红色显示。点击看详情。

```
[✗ web_fetch] 已重试 3 次，仍失败
```

底下 LLM 给用户的解释。

```
我尝试调用网络获取数据，但服务无响应。
您可以稍后再试，或者用其他方式获取信息。
```

## 失败模式的统计

chayuan-desktop 监控面板。

```
最近 7 天工具失败：
  github_mcp: 5 次（4 次 401、1 次 timeout）
  slack_mcp: 12 次（10 次 429、2 次网络）
```

让用户看到哪些工具频繁出问题。

## 失败的导出

某些故障需要发给开发者排查。chayuan-desktop 支持导出失败诊断包。

```json
{
  "tool": "github_mcp.create_issue",
  "input": {...},
  "error": "401 Unauthorized",
  "stack": "...",
  "environment": {
    "chayuan_desktop_version": "...",
    "os": "...",
    "tool_version": "..."
  }
}
```

发给开发者复现。

## 国产化场景

党政军场景对故障定位有要求。chayuan-desktop 的诊断让用户能 看错误就知道怎么办，减少 IT 工单。

## chayuan-server 的对应

chayuan-server 多用户场景下错误诊断更集中（管理员能聚合查看所有用户的错误）。chayuan-desktop 单机本地。

## WPS 加载项

chayuan-wps 在 WPS 里调工具失败时弹同样诊断。员工知情。

## 总结

工具调用失败的诊断是 chayuan-desktop 在用户体验上的工程细节。免费开源的AI软件 让 工具失败 不只是冷冰冰的错误码，而是 用户能理解 + 能行动 的提示。chayuan-desktop 的多层错误展示 + 推荐操作 + LLM 纠错让失败也是好的体验。
