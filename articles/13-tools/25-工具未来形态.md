# 工具未来形态 自学习自描述的工具

chayuan-desktop 桌面单机版对工具的未来形态有预期。这一篇讲展望。

## 当前工具的局限

局限一：描述静态。开发者写好描述，LLM 看的就是这些。LLM 实际调用过程中遇到边界情况描述里没说。

局限二：参数固定。工具签名定死。LLM 想加新参数得改工具。

局限三：错误信息一次性。失败后给静态错误，LLM 可能不知道怎么解决。

局限四：跨工具协作弱。工具之间不知道彼此存在。

## 自描述工具

未来工具能自我学习并更新描述。

工具运行后看到 LLM 的常见误用模式。自动补充描述。

```
v1.0 description: List GitHub repos
v1.1 description: List GitHub repos. 注意：私库需要 OAuth Token。
v1.2 description: List GitHub repos. 注意：私库需要 OAuth Token。返回字段含 fork_count（v1.3+）。
```

工具自己迭代描述。chayuan-desktop 的工具市场支持这种自更新。

## 自学习参数

工具看到 LLM 经常以特定方式组合参数。工具学习给出推荐参数预设。

```
LLM 常用 list_repos(user="...", type="owner")。
工具学习后给出预设参数：list_repos_owned_by(user="...")。
LLM 看到更具体的工具更容易调对。
```

参数级的自动化便利。

## 跨工具协作

未来工具之间能通信。

```
github_mcp 找到一个 PR 需要审批。
github_mcp 通知 slack_mcp 给作者发消息提醒。
```

不需要 LLM 中间编排。工具之间默契协作。

chayuan-desktop 路线图考虑工具间协作总线。

## 工具的能力发现

LLM 不需要预先知道所有工具。

LLM：我需要查 GitHub 上的某个 repo。

chayuan-desktop 的工具发现引擎：根据这个意图找到 github_mcp.get_repo 工具，给 LLM。

避免 LLM 上下文塞满几十个工具描述。

## 可解释的工具

工具调用过程更透明。

```
工具调用思考链：
  step 1: 解析参数
  step 2: 调用 GitHub API GET /repos/...
  step 3: 解析响应
  step 4: 提取关键字段
  step 5: 返回
```

每步可观测。便于调试和优化。

## 主动推荐

工具看到用户场景能主动推荐。

```
用户在 chayuan-desktop 里频繁手动查 GitHub。
chayuan-desktop 推荐 安装 github_mcp 让 AI 帮你查。
```

让用户发现没用过的工具。

## 工具市场的演化

工具市场不只是工具列表。

工具评分（用户主观）。

工具实测精度（自动评测）。

工具相似性（同类工具比较）。

工具推荐（基于使用场景）。

## 工具的商业化

工具开发者能。

免费开源（社区）。

付费版（更多功能、更好支持）。

订阅模式（接业务系统的）。

chayuan-desktop 的工具市场支持多种商业模式。让工具生态可持续。

## 国产化场景

党政军场景的工具未来形态。

国产工具市场。

行业专用工具（政务、军工、金融、医疗各行业的工具集）。

合规预审。工具发布前过合规审查。

chayuan-desktop 配合国产生态发展。

## chayuan-server 的对应

chayuan-server 多用户场景下工具的自学习更有效（数据更多）。chayuan-desktop 单机能从 chayuan-server 获益。

## WPS 加载项

chayuan-wps 跟工具未来形态共同演进。WPS 内的工具能力越来越强。

## 总结

工具未来形态是 chayuan-desktop 在长期 AI 生态演进上的预期。免费开源的AI软件 不只满足当下，还要为未来准备。chayuan-desktop 的自描述 + 自学习 + 跨工具协作 + 工具市场让工具生态长期可持续。
