# 本地推理与云端推理的混合 智能路由的策略

chayuan-desktop 桌面单机版的智能路由把简单任务给本地，复杂任务给云。这一篇讲混合策略。

## 混合的动机

动机一：成本。本地免费（除电），云模型按 token 计费。能本地解决就别花钱。

动机二：隐私。某些请求含敏感数据。本地处理避免上云。

动机三：响应速度。本地小模型秒级响应。云模型有网络延迟。

动机四：质量。某些复杂任务本地小模型答不好。需要云大模型。

混合是平衡。

## 路由的判断维度

维度一：任务类型。

简单 chat → 本地 1.8B。

代码生成 → 云 GPT-4o 或本地 7B。

长文写作 → 云。

数据分析 → 云。

视觉理解 → 云（多数本地视觉模型不够强）。

维度二：输入复杂度。

输入 < 200 字。本地能搞定。

输入 200-2000 字。本地 7B 或云。

输入 > 2000 字。云。

维度三：用户偏好。

用户配的默认模型。

用户切换的当前模型。

用户对成本的容忍度。

维度四：联网状态。

无网。强制本地。

弱网。倾向本地（避免请求超时）。

强网。按其他维度决策。

## 路由实现

```python
def route(request):
    if not online:
        return "ollama:qwen2.5:1.8b"

    if request.has_image:
        return "gpt-4o"  # 视觉走云

    if request.input_length > 2000:
        return cloud_model

    if request.task_type == "simple_qa":
        return "ollama:qwen2.5:1.8b"

    if request.contains_pii:
        return local_model  # 隐私走本地

    if user.budget_left < 5:
        return local_model  # 预算紧用本地

    return user.preferred_model
```

逻辑简化版。实际更细。

## 用户感知

UI 上不强调用了哪个模型。让用户聚焦内容。

但鼠标 hover 回答看到 此回答由 ollama:qwen2.5:7b 生成（本地）。

如果路由切了，比如本来选云但路由切到本地，UI 弹小提示 因预算原因切换到本地模型。

## 智能路由的开关

某些用户不想路由介入，希望严格按自己选的模型来。chayuan-desktop 设置里有 智能路由 开关，默认开。关掉后用户选什么就用什么。

## 路由的学习

chayuan-desktop 记录用户主观满意度（聊天里的 满意 / 不满意 反馈）。

如果某类问题（比如 代码生成）用本地模型用户经常 不满意，chayuan-desktop 学习后该类问题倾向云模型。

如果某类问题（比如 简单事实查询）用云模型用户没特别满意，学习后倾向本地（省钱）。

不全自动，给用户调整空间。

## 固定路由表

某些场景用户希望特定任务走特定模型。chayuan-desktop 设置里能配。

```yaml
routing:
  - task: code_generation
    model: deepseek-chat
  - task: chinese_writing
    model: qwen-plus
  - task: image_understanding
    model: gpt-4o
  - task: simple_chat
    model: ollama:qwen2.5:1.8b
```

显式优先级最高。

## 多步任务的路由

某些请求需要多步处理。比如 帮我从这堆数据里写一份报告。

第一步：检索（本地 RAG）。

第二步：摘要每个文档（本地 7B）。

第三步：综合写报告（云 GPT-4o）。

chayuan-desktop 的 agent 编排把不同步骤路由到不同模型。混合用最优。

## 国产化场景

党政军用户对成本敏感、对隐私敏感。chayuan-desktop 的本地优先 + 云补充 默认满足国产化需求。

某些场景完全禁止上云。chayuan-desktop 的 强制本地 模式让所有路由都走本地，不走云。

## chayuan-server 的对应

chayuan-server 多用户场景下路由考虑全员配额。chayuan-desktop 单机版只考虑单用户。

## WPS 加载项

chayuan-wps 在 WPS 里发起的请求走 chayuan-desktop 路由。WPS 用户写报告时不感知用了哪个模型。chayuan-desktop 自动选最合适的。

## 总结

本地与云的混合智能路由是 chayuan-desktop 在成本 / 隐私 / 性能上的工程平衡。免费开源的AI软件 不让用户在两者之间手动切换。chayuan-desktop 的多维度路由 + 学习 + 固定路由 让 一个请求自动到最合适模型 这件事在工程上落地。
