# 本地模型的并发控制 单卡的排队机制

chayuan-desktop 桌面单机版的本地推理对 同一张显卡 的并发请求做排队。这一篇讲并发控制。

## 单卡的并发瓶颈

一张 GPU 同时只能跑一个 LLM 推理（除非用 vLLM 的 continuous batching，家用一般不开）。

如果两个请求同时要本地 LLM 推理。GPU 处理第一个时第二个排队。

不排队会 OOM 或显存抖动崩溃。

## chayuan-desktop 的排队设计

每个本地模型一个 queue。

```
ollama:qwen2.5:7b queue: [req_A, req_B, req_C]
ollama:qwen2.5:1.8b queue: [req_D]
bge-m3-onnx queue: [req_E]
```

每个 queue 串行处理。

## 多个 queue 之间的并发

不同模型之间能并发（如果显存够）。Qwen2.5-7B 占 4GB，bge-m3 占 0.3GB，加起来 4.3GB。8GB 显卡能并行跑 chat 和 embed。

chayuan-desktop 启动时检测显卡显存，决定哪些模型组合能并发加载。

## queue 的优先级

某些请求高优先级。

交互式聊天。用户在等。最高优先级。

后台索引。建库时大量嵌入。低优先级。

异步任务。比如定时摘要。最低。

chayuan-desktop 的 queue 支持 priority 标记。高优先级请求插队。

## 用户感知

排队中的请求 UI 显示 排队中... 第 3 位 等。用户看到队列状态。

排队超时（默认 60 秒）chayuan-desktop 弹通知 本地推理繁忙，建议切换到云模型。让用户决策。

## 模型切换的开销

如果显存只够同时加载一个模型。用户先要 Qwen-1.8B 后要 Qwen-7B。chayuan-desktop 要 unload 1.8B 加载 7B，约 2-5 秒。

频繁切换浪费时间。chayuan-desktop 的策略。

策略一：保持当前模型在显存，新请求按原模型排队。

策略二：用户显式切换时才 unload+load。

策略三：智能预测。如果看到用户多次切换，加载更大模型避免来回切。

## 上下文复用

同一会话连续多次请求。chayuan-desktop 复用 KV cache。

第二次请求时如果上下文是第一次的延续，KV cache 不重新计算。响应快很多。

不同会话的 KV cache 不互通。

## 中断和取消

用户在生成过程中点 停止。chayuan-desktop 调底层推理的 abort 接口。GPU 立即释放，处理 queue 里下一个请求。

某些后端不支持中断（必须等完成）。chayuan-desktop 把 已被取消 状态标记，结果丢弃。

## 超长请求的限制

某些请求消耗显存特别大（比如 32k 上下文 + 大量输出）。chayuan-desktop 给 single-request 设上限（默认 16k 上下文 + 4k 输出）。超限分多轮处理。

避免单个请求把 GPU 卡死太久影响后续。

## 多人同时用

多人共用一台电脑（家庭场景）。两人同时用 chayuan-desktop。本地推理排队。

家庭普通显卡不够多人同时本地推理。chayuan-desktop 提示用户 当前推理繁忙，建议切换到云模型。

## chayuan-desktop 的并发可视化

设置 - 模型 - 推理状态。

```
当前推理任务：
  ollama:qwen2.5:7b：处理中（用户 zhangsan，会话 #42）
  ollama:qwen2.5:1.8b：空闲
  bge-m3-onnx：空闲

排队：
  ollama:qwen2.5:7b：2 个请求等待
```

便于用户看负载。

## 国产化场景

党政军单位电脑配置不一。chayuan-desktop 的并发控制让 低配机器 + 单卡 也能稳定运行。不会因为一次复杂请求把整个 chayuan-desktop 卡死。

## chayuan-server 的对应

chayuan-server 部署在带多 GPU 的服务器，支持多用户并发推理。chayuan-desktop 单机串行。两者协议一致便于切换。

## WPS 加载项

chayuan-wps 在 WPS 里发起的请求跟桌面端共享 chayuan-desktop 的推理 queue。WPS 请求和桌面请求合并排队。

## 总结

本地模型的并发控制是 chayuan-desktop 在单机硬件限制下的工程能力。免费开源的AI软件 让单卡也能稳定服务多请求。chayuan-desktop 的 queue + 优先级 + 上下文复用 + 中断 让本地推理在单卡场景下井井有条。
