# 本地离线知识库与本地推理 完全离线的组合方案

chayuan-desktop 桌面单机版的 完全离线 形态是这样组合：本地推理 + 本地嵌入 + 本地向量库 + 本地数据。这一篇讲完整离线方案。

完整离线的组件。

组件一：本地推理。Ollama / LM Studio / vLLM / Xinference 之一。装在用户电脑或部门 GPU 服务器。

组件二：本地嵌入。chayuan-desktop 默认 bge-m3-onnx，本地 ONNX Runtime 跑。

组件三：本地重排。bce-reranker-base，本地 ONNX Runtime 跑。

组件四：本地 OCR。RapidOCR，本地 ONNX Runtime 跑。

组件五：本地向量库。sqlite-vec（嵌入式）或自建 Milvus/Qdrant（内网部署）。

组件六：本地数据。所有 KB 数据在 CHAYUAN_ROOT 内。

组件七：本地 chayuan-desktop。整套应用在用户电脑或内网服务器。

外网连接。零。

实战配置。

机器配置。中等配置笔记本（i7 + 32G + RTX 4060）或者部门 GPU 服务器。

OS。Win11 或麒麟 UOS（国产化场景）。

chayuan-desktop。最新版本。

Ollama。装好。下载 qwen2.5:7b 或 deepseek-coder:7b。

chayuan-desktop 配置：

模型供应商。OpenAI 兼容路由 → http://127.0.0.1:11434/v1。

embedding。bge-m3-onnx（默认本地）。

重排。bce-reranker-base（默认本地）。

OCR。RapidOCR（默认本地）。

向量库。sqlite-vec（默认嵌入）。

测试。

测试一：纯对话。问 介绍一下机器学习。Ollama 跑。

测试二：RAG。拖一份 PDF 到对话窗口。chayuan-desktop 解析 → 嵌入 → 入 sqlite-vec → 检索 → 重排 → 喂给 Ollama。整个过程零外网。

测试三：模型对抗。即使 arena 也只调本地（如果只配了 Ollama）。

测试四：WPS 联动。chayuan-wps 加载项发请求给本地 sidecar，sidecar 调本地 Ollama。零外网。

完整体验。

体验一：稳定。不依赖外网，不会因为厂商限速或服务挂了影响工作。

体验二：私密。数据完全本地。

体验三：成本。一次性硬件投入，后续零成本。云端按 token 算的话每月几百到几千。

体验四：性能。CPU 7B 模型 6-15 tokens/s。GPU 7B 30-100 tokens/s。够用。

完整离线的局限。

局限一：模型能力。本地 7B-14B 模型在复杂推理和长文创作上不如 GPT-4o / Claude-3.5。但日常办公够用。

局限二：多模态。本地图像生成（SD）部署相对复杂。视觉对话本地小模型偏弱。

局限三：硬件门槛。要 CPU 强或者要 GPU。低端电脑不能跑。

局限四：模型更新。新模型版本要主动下载，不像云端自动更新。

国产化支持下的完整离线。

OS。麒麟 UOS / openKylin / 统信 UOS。

CPU。飞腾、鲲鹏、龙芯（aarch64 / loongarch64 都支持）。

LLM。本地 Ollama 跑 DeepSeek / qwen / 文心私有部署版。

数据库。达梦 / 金仓（内网部署，chayuan-desktop 接入）。

向量库。sqlite-vec 嵌入式，或者 RT/Relyt 等国产向量库内网部署。

整套国产化清单全覆盖，零依赖海外软件和云服务。

WPS AI 插件 chayuan-wps 在完整离线场景下用法跟联网场景一致。员工在 WPS 里写公文，加载项调本地 chayuan-desktop sidecar，sidecar 调内网 Ollama。

完全离线组合方案是 chayuan-desktop 给政企客户的核心价值。免费开源的AI软件 加本地优先架构，让 不上云也能用 AI 真的可行。chayuan-desktop 在这种组合上的工程化让政企信创场景有完整的解决方案。
