## 一句话说明

AI 助手跑完一个任务后，结果以哪种方式落进文档，由助手的「文档动作」决定，共九种：替换、插入到光标处、插入到每段后面、插入到文档最前面、添加批注、链接形式批注、批注 + 替换、追加到文末、仅生成结果。所有写回都带三重保护：文档写锁（排队串行 + 改动校验）、样式保护（编号/段落样式尽量不动）、写前备份与一键撤销。

## 适用场景

- 配置助手时看到「文档动作」下拉里有九个选项，不知道选哪个；
- 担心 AI 直接改坏正文，想知道有哪些保险（备份、撤销、修订模式）；
- 明明选了「替换」，结果却变成了批注，想知道为什么。

典型提问（chabot 语料视角）：

- 「AI 结果写回文档的九种方式分别是什么意思？」
- 「为什么选了替换，最后却只加了批注？」
- 「AI 改完文档后悔了，怎么撤销回写之前的状态？」

## 前置条件

- 已安装并启用察元AI加载项（见 W01/W02），已打开一个文档；
- 已配置好对话模型（见 W03），否则任务无法执行；
- 各助手有自己的允许动作范围（如「生成摘要」不允许「插入到每段后面」），下拉里只会列出该助手允许的动作。

## 操作步骤

**1. 在哪配置某个助手的写回动作**

- 在哪：设置窗口 → 助手设置 → 选中某个助手（或自定义助手）→ 右侧配置表单。
- 做什么：找到「**文档动作**」下拉，九个选项（内置助手只显示自己允许的子集）：

| 选项原文 | 行为（以代码为准） |
|---|---|
| 替换文档内容 | 有选中：替换选区（整段替换时保留编号前缀与段落样式，逐段倒序写入）；无选中：按任务输入范围替换（工具栏任务严格按整段/全文替换，个别对话直发场景定位不到范围时退回在光标处插入）；输出段落数对不上、编号前缀变化等不安全场景自动降级为批注 |
| 插入到光标处 | 有选中：插到选区后面；无选中：插在光标位置；Markdown 表格/标题/列表等富内容会渲染成真实格式，而不是插入 `#`、`**` 等记号 |
| 插入到每段后面 | 选区含多段时，把结果按段对齐、逐段插到每一段后面（倒序写入避免位置漂移） |
| 插入到文档最前面 | 有选中：插到选中段落前面；无选中：插到全文最前面 |
| 添加批注 | 在选中/所在段落范围上加一条批注；批注先按原文精确定位（查找 → 复核范围文本一致才落笔，钉不到就不硬挂） |
| 链接形式批注 | 同批注，批注正文末尾多一行「参考：可在任务清单中查看完整结果。」 |
| 批注 + 替换 | 先加批注再替换；替换不安全时自动回退成只加批注，原文不动 |
| 追加到文末 | 在文档末尾追加结果（前后补空行） |
| 仅生成结果，不写回文档 | 只生成，文档一个字不动；结果在任务进度窗/任务清单里查看 |

**2. 发起任务并观察写回**

- 在哪：顶部「文本分析」▾、各功能按钮或 AI 助手窗格发起任务（见 W16/W17）。
- 看到什么：弹出任务进度窗（见 W18）。写回完成后，窗内「文档动作：」一行显示实际发生的动作消息，例如「已替换文档内容」「已添加批注」「已生成结果，未写回文档」。

**3. 认识写保护（不用操作，但要知道）**

- **文档写锁**：同一窗口所有「写文档」动作排队串行执行（先到先写）；写前校验活动文档没被切走、内容没在本回合期间被手动改过。被拦下时任务里会看到错误原文：「写回前校验失败：文档内容在本回合期间已被修改（可能为手动编辑或其它操作）。」或「排队等待期间活动文档已切换，本次写回已取消（避免写到错误文档）。」
- **样式保护**：写回前后对目标范围做字体/字号/对齐/行距等快照对比；发现变化时结果明细里会出现「样式校验：段落对齐发生变化、行距发生变化…」这类条目，变化较多时追加「样式复核：建议人工复核后再继续使用当前写回结果」。
- **写后静置**：每次写完等文档结构稳定后再更新基线，避免连续写被误拦。

**4. 写前备份与一键撤销**

- 在哪：任务执行卡（消息里的长任务卡）上的「**写回前备份源文件**」勾选项（勾上后写回前先把当前文档另存一份快照）。
- 备份存哪：数据目录的 `_document_backups` 文件夹；文档已保存过时也可存在原文档同目录的 `.chayuan_backups`。备份记录上限 120 条，只记录已保存过的文档（未保存过的新文档无法备份源文件）。
- 撤销入口 1（对话内）：智能体改完文档后，消息下方出现「**一键撤销**」卡片——「本轮修改前已创建文档快照，如对结果不满意可整体撤销回写前状态。」点「**撤销本次修改**」（撤销中显示「撤销中...」）即从快照整体恢复。
- 撤销入口 2（批注类任务）：文档批注类任务完成后，任务进度窗标题栏有「**撤销本次改动**」按钮，点击会删除本次新增的批注，提示「已撤销本次新增的 N 处批注」。

**5. 想要修订痕迹：写回前确认卡**

- 看到什么：点「**确认写回**」且文档动作是替换/插入类时，若文档还没开修订模式，窗内弹「**写回前确认**」卡：「检测到即将写回文档，你可以先开启修订模式。」，带 5 秒倒计时（鼠标悬停会暂停）。
- 做什么：点「**开启修订并继续**」→ 自动打开文档修订模式再写回，改动以修订形式留痕；点「**直接继续**」→ 按当前状态直接写；不选则倒计时结束自动直接继续。

**6. 文档智能体链路没有人工确认闸门（重要）**

- 在 AI 对话里让文档智能体改文档时，写操作**直接执行、不会先弹窗问你**（2026-09-17 起移除人工确认闸门，工具的 confirmed 参数由客户端层自动注入）。安全网是上面的备份快照卡与撤销按钮；要事前留痕，可在文档里先开修订模式，或让智能体用 MCP 修订工具（revision_mode 开修订、revision_list 列修订、revision_apply 接受/拒绝修订，接受/拒绝必须 confirmed=true 才执行）。

### 验证

1. 打开 设置 → 助手设置 → 任一助手，能看到「文档动作」下拉且选项与上表原文一致。
2. 把某助手设为「仅生成结果，不写回文档」后跑一次任务：任务完成后文档内容无任何变化，任务窗「文档动作：已生成结果，未写回文档」。
3. 对一篇已保存的文档勾选「写回前备份源文件」再执行替换类任务：`_document_backups`（或文档同目录 `.chayuan_backups`）里多出一个带时间戳的备份文件。

## 常见问题

**Q1：明明选了「替换文档内容」，为什么结果只多了一条批注？**
这是刻意的安全降级：模型输出的段落数量和原文对不上、章节编号前缀发生变化、所选内容不是完整段落等情况下，直接替换会破坏编号和样式，程序自动改为批注建议并在结果里写明降级原因（如「检测到章节编号或条款前缀变化，为保护原编号和样式，未直接替换原文」）。想要强制替换，可让输出严格对齐原文段落数，或先在文档里开修订模式再确认写回。

**Q2：写回时报「写回前校验失败：文档内容在本回合期间已被修改」，怎么办？**
任务发起后你又手动编辑了文档，写锁的基线校验把这次写拦下了（防止把旧结果盖到新内容上）。重新发起一次任务即可；批量任务避免在执行中途手动改动同一文档。

**Q3：报「排队等待期间活动文档已切换，本次写回已取消」？**
多个任务排队时你切到了另一篇文档，写锁为避免写到错误文档而取消。回到原文档重新发起即可。

**Q4：智能体会先给我看结果、经我确认才写进文档吗？**
不会。2026-09-17 起文档智能体的写操作直接执行（无人工确认闸门）。要安全网：一是在任务卡上勾「写回前备份源文件」，改完用「一键撤销」卡的「撤销本次修改」整体回退；二是提前开启文档修订模式，所有改动以修订形式呈现，随时整体拒绝。

**Q5：备份文件存在哪？会无限增多吗？**
存在数据目录的 `_document_backups`（文档已保存过时也可能在原文档同目录 `.chayuan_backups`），文件名带文档名和时间戳。备份记录上限 120 条，超出后旧记录被挤出清单，但已生成的备份文件不会被自动删除。
