## 一句话说明

察元AI文档助手能**自动发现**本机察元OS（察元桌面版）的知识库服务并一键接入：服务端口严格固定 **52582**，走「手动指定 → 上次缓存 → 并行端口梯探测」三级发现，发现后落成一条名为「**察元 Harness 本机知识库**」的稳定连接——本机增删知识库无需在 WPS 侧重配，库列表运行时实时拉取。

## 适用场景

- 本机装了察元桌面版，想让 WPS 里的 AI 直接引用本地知识库（文档全程不出本机）；
- 打开「选择知识库」弹窗看到「未检测到本机『察元桌面版』」引导卡，不知道该怎么办；
- 察元桌面版重启过/换过端口，想知道 WPS 侧要不要重新配置。

典型提问（chabot 语料视角）：

- 「WPS 插件怎么连本机知识库？要填地址吗？」
- 「为什么提示未发现本机知识库服务(默认端口 52582)？」
- 「察元桌面版里新建了知识库，WPS 里要重新配置吗？」

## 前置条件

- 已启用加载项（见 W02），并已配置对话模型（见 W03）——知识库只负责检索注入，回答由所配模型生成；
- **本机察元OS（chatop）在运行**：知识库对外服务固定 `127.0.0.1:52582`（仅回环监听、免密钥），不在运行时连不上；
- 察元OS 侧已有建好的知识库和「就绪」文档（见察元OS 教程《新建知识库》《上传文档与加载索引》）。

## 操作步骤

**1. 打开知识库设置面板**

- 在哪：AI 助手窗格右上角「**设置**」→ 主菜单「**常规设置**」→ 子项「**知识库设置**」。
- 看到什么：面板打开时**静默自动扫描**本机一次。若顶部出现黄色横幅「⚠ 远程知识库集成当前已通过功能开关 `kbRemoteIntegration` 关闭……发送消息时不会触发知识库检索」，点横幅里的「**立即启用**」（默认就是开启的，一般不会遇到）。

**2. 本机自动接入（通常零操作）**

- 发现成功：绿色提示「**已自动接入本机察元 Harness 知识库(127.0.0.1:52582,发现 N 个)**」，左栏「**知识库连接**」列表出现「**察元 Harness 本机知识库**」（模式标「Harness 本机」），右栏「**可访问知识库**」列出各库目录。
- 手动重扫：点连接列表标题行的 ⌖ 按钮（悬停提示「**自动发现本机察元 Harness 知识库**」，扫描中显示「**正在扫描本机服务…**」）；已连接时提示「**本机 Harness 已连接(…,N 个知识库)**」，地址迁移过则提示「**本机 Harness 地址已更新(…,N 个知识库)**」。
- 没发现时：红色提示「**未发现本机察元 Harness 知识库服务(默认端口 52582),请确认 chatop 已启动**」——先启动察元桌面版再回来扫。

**3. 没检测到察元桌面版时的两条出路**

- 在对话输入区点书本按钮（悬停提示「**选择知识库**」），弹窗顶部出现引导卡「**💻 未检测到本机「察元桌面版」**」：
  - 点「**前往官网下载桌面版**」装好后，点「**已安装？重新检测**」；
  - 或点「**或前往设置手动配置远程连接**」改连远程知识库（见 W35）。

**4. 点「测试连通」看三步体检（可选但推荐）**

- 在哪：左栏点选「察元 Harness 本机知识库」连接，点闪电图标按钮（悬停「**测试连通**」）。
- 看到什么：三步逐条打 ✓/✗ 并带耗时——「**服务地址**」（GET /health）→「**本机服务**」（GET /status，校验 chatop-kb 指纹）→「**知识库通路**」（GET /kbs，末尾显示「N 个」）。任一步 ✗ 时下方给对应提示：
  - 第 1 步失败：「**本机 Harness 服务不可达:请确认 chayuan-harness(chatop)已启动(默认端口 52582)**」；
  - 第 2 步失败：「**端口有响应但不是 chatop-kb 服务,请重新自动发现**」；
  - 第 3 步失败：「**服务在线但拿不到库列表,请检查 harness 侧 chatop-kb 插件状态**」。

**5. 发现链是怎么工作的（理解用，无需操作）**

- 三级顺序：**手动指定**（表单里填过地址，命中优先级最高）→ **上次发现缓存** → **并行端口梯探测**（全部并发发出，先命中先用）。端口梯首候选即 52582（严格固定，被占时服务端拒绝启动、不顺延），其后 52582+1..20 顺延段 → dsh 管理面 52584（`/api/chatop-kb` 前缀）→ 会话段 52601..52610 → 旧装机段 3080..3085 兜底；新装机第一个候选必中。
- 每个候选都先取 `/status` 做**指纹校验**：响应必须是 `{ ok:true, kbs:[…] }` 形状才算命中，随机本机服务不会误配。
- 发现成功后落成稳定连接（连接 id `chatop-harness-local`）：**库列表运行时实时从本机服务拉取**——察元OS 里新建/删除知识库，WPS 侧下次打开选择器即同步，**无需重配**；察元桌面版关停后再恢复，连接保留、自动续上（失联时健康快照记「本机 Harness 服务未发现(请确认 chatop 已启动)」）。

### 验证

1. 浏览器或终端访问本机服务（察元桌面版在运行时）：
   - `curl http://127.0.0.1:52582/health` → 返回 `{"ok":true,"service":"chatop-kb",…}`；
   - `curl http://127.0.0.1:52582/kbs` → 返回 `{"ok":true,"kbs":[…]}`，`kbs` 数组即本机库清单。
2. WPS 侧：设置 → 常规设置 → 知识库设置，连接「察元 Harness 本机知识库」在列且标「Harness 本机」，选中后右栏能列出本机各库。
3. 对话输入区点书本按钮，「选择知识库」弹窗左侧出现「**察元 Harness(本机)**」分组并列出各库。

## 常见问题

**Q1：提示「未发现本机察元 Harness 知识库服务(默认端口 52582)」？**
按序排查：① 察元桌面版是否已启动（没装见步骤 3 的下载引导）；② 浏览器开 `http://127.0.0.1:52582/health` 应返回 `{"ok":true,"service":"chatop-kb",…}`——打不开就是服务侧没起或端口被占（chatop-kb 端口被占时拒绝启动，去察元OS 侧看服务状态）；③ 能打开但 WPS 仍报错，点 ⌖ 扫描按钮重扫一次。

**Q2：察元OS 里新建/删除了知识库，WPS 侧要重配吗？**
不用。发现连接的库列表运行时实时拉取，重新打开「选择知识库」弹窗（或知识库设置右栏点「**刷新**」）即可看到最新库清单；服务地址变了也由发现链自动跟随（「本机 Harness 地址已更新」提示）。

**Q3：本机连的是 52582，为什么扫描时还探测 52601、3080 这些端口？**
那是端口梯的兼容尾巴：给「顺延时代」的旧装机和 dsh 会话形态留的兜底候选。新装机 52582 固定必中，后面的候选只是并行扫一遍不命中即弃，不影响使用。

**Q4：知识库设置顶部出现黄色横幅说功能开关已关闭？**
点横幅里的「**立即启用**」，提示「**已启用远程知识库集成**」即可。该开关关闭时连接和绑定仍可配置，但发送消息不会触发知识库检索。

**Q5：删掉这条连接会怎样？**
点垃圾桶图标「**删除连接**」→ 确认卡「确认删除连接「…」？此操作不可恢复。」→「**删除**」。删后再点 ⌖ 扫描按钮，发现链会重新把它建回来。

## 形态差异

- 本篇只覆盖**本机直连**（回环 127.0.0.1:52582、免密钥）；要连部署在服务器上的远程知识库（JWT/APPID 鉴权），见 W35。
- 发现与检索都走本机回环 HTTP，不依赖外网；察元桌面版不运行时仅本机链路不可用，远程连接不受影响。
