## 一句话说明

「脱密复原」是「文档脱密」的逆操作：对已脱密的文档，输入脱密时设置的密码，验证通过后把 `§…§` 占位符就地替换回原文，文档恢复为未脱密状态。按钮只在当前文档处于脱密状态时可用，复原必须凭密码。

## 适用场景

- 文档外发流转结束回到内网，要把占位符还原成真实内容继续编辑；
- 脱密时遮错了词，先复原、调整关键词后重新脱密（脱密操作见 [W21](./W21-文档脱密.md)）。

典型提问（chabot 语料视角）：

- 「脱密之后怎么还原？」
- 「复原密码忘了还能恢复吗？」
- 「脱密后又改过文档，还能复原吗？」

## 前置条件

- 文字端功能：仅 WPS 文字提供「脱密复原」按钮（表格/演示端无此入口）；
- 当前文档处于脱密状态：脱密完成后「脱密复原」亮起（「文档脱密」置灰）；未脱密的文档此按钮置灰，点不了；
- 你记得脱密时设置的密码——复原必须用密码解密随文档保存的恢复载荷，密码错误无法复原；
- 付费能力：属付费专属能力，未购买时点击弹「购买授权」窗（见 [W42](./W42-购买授权与能力门禁.md)）。

打开弹窗后先核对状态卡：脱密状态与「关键词 N 个，替换 M 处。」保存在当前文档里，和任务清单中「占位符脱密」任务记录的数字一致，说明这份文档的脱密记录完整、可以复原。

## 操作步骤

1. 打开已脱密的文档（正文里能看到 `§…§` 占位符），在 Ribbon「察元AI助理」选项卡 →「安全保密」组点「脱密复原」。未购买授权时此处弹「购买授权」窗。
2. 弹出「密码复原」窗口（约 420×320），副标题：「输入执行占位符脱密时设置的密码，验证通过后恢复当前文档原文。」窗口顶部状态卡显示「当前状态：已占位脱密」，及「关键词 N 个，替换 M 处。」；若文档不是脱密状态，状态卡显示「未脱密」并提示「当前文档不是脱密状态，无法执行复原」。
3. 在「复原密码」输入框输入脱密时设置的密码（输入框占位提示「请输入执行占位符脱密时设置的密码」；输入框内直接按回车等同点「确定复原」），点「确定复原」，进行中按钮显示「正在复原...」。密码留空直接提交会提示「请输入复原密码」。
4. 系统用密码解密文档变量中保存的恢复载荷（PBKDF2-SHA-256 派生密钥 + AES-GCM-256 解密），校验通过后按占位符在正文中就地查找替换：每个 `§token§` 换回对应原文，只动占位符所在位置，其余内容与排版格式不动。
5. 完成后窗口显示绿色结果：「已完成复原，共恢复 N 处替换，涉及 M 个关键词。」及提示「当前文档已恢复为未脱密状态。」，点「关闭」收窗。按文档脱密后的实际情况，任务清单的「密码复原」任务会留下三种记录之一：
   - 全部占位符都在：「已完成密码复原，恢复 N 处替换。」；
   - 个别占位符已不在文档中（脱密后被删除或改动）：「已尽力复原:还原 X 处;另有 Y 个占位符未找到(脱密后可能被删除或改动),未还原。」；
   - 文档在脱密后被编辑过：「已复原 X 处(文档脱密后有改动,已按占位符就地还原)。」。
6. 复原完成后脱密状态清除：文档变量中的脱密状态与加密载荷被移除，Ribbon 上「脱密复原」置灰、「文档脱密」恢复可用。

### 验证

- 正文中所有 `§…§` 占位符已换回原关键词，格式不变；
- 「察元AI助理」→「安全保密」组：「脱密复原」按钮置灰、「文档脱密」按钮恢复可用；
- 任务清单（「察元AI编审」→「察元设置」→「任务清单」）新增「密码复原」任务记录；
- 再次点开「脱密复原」弹窗：状态卡应显示「未脱密」并提示「当前文档不是脱密状态，无法执行复原」。

## 常见问题

**Q1：提示「密码错误或脱密数据已损坏」？**
说明输入的密码与脱密时不匹配，载荷解密失败。确认大小写、特殊字符后重新输入；重试没有次数限制，但也没有绕过密码的途径——复原只能靠正确密码。

**Q2：忘记密码还能恢复吗？**
不能。恢复载荷是 AES-GCM 加密密文，复原必须用当初的密码解密，当前代码没有免密码恢复通道。密码遗失时文档只能保持脱密状态，请回 W21 的密码规则处核对自己当时的设置习惯。

**Q3：脱密之后我又编辑过文档，还能复原吗？**
能。复原按占位符 `§token§` 就地查找替换，不依赖脱密时记录的位置——脱密后的增删改不影响，只要占位符还在文档里就能换回原文并保留排版；被删除或改坏的占位符不会伪造还原，会如实计入「未找到」。若所有占位符都找不到了，会报「未找到任何脱密占位符，无法还原（占位符可能已被全部删除或改动）。文档未改动，可撤销编辑后重试。」（注：复原弹窗中「系统会阻止直接复原」为旧版提示文案，当前实际行为以本条为准。）

**Q4：系统怎么知道文档在脱密后被改过？**
脱密执行时会把原文与脱密后文本各算一个 SHA-256 指纹随状态保存；复原时重新计算当前文本的指纹比对，不一致即视为「文档脱密后有改动」。这个判定只影响任务记录里的提示文案，不会阻止按占位符就地还原。

**Q5：把文档拷到另一台电脑还能复原吗？**
能，前提是三样都在：文件本身的脱密状态与加密载荷（随文档保存，拷贝文件即随身携带）、正确的密码、装有本加载项且已授权的 WPS。反之要警惕：任何拿到文件又知道密码的人都能复原——外发前请确认可接受（见 W21 的边界说明）。

**Q6：复原会把我后来加的内容覆盖掉吗？**
不会。复原只替换占位符所在的位置，其余内容原样保留；这也是文档脱密后被编辑仍能安全复原的原因。

**Q7：复原之后想重新脱密怎么办？**
直接再点「文档脱密」即可（复原后该按钮已恢复可用）。当初遮过哪些词，可在任务清单的「涉密关键词提取」任务详情表（原文关键词/占位符/分类/风险/脱密原因）里回看，照着补回关键词即可。

**Q8：外部智能体（如 Claude Code）能做脱密复原吗？**
可以。本机 MCP 文档智能体服务提供同能力的 `declassify_restore` 工具（需 `confirmed` 确认与密码两个参数；工具说明明确无密码必然失败，请勿尝试暴力破解），另有 `declassify_status`/`declassify_preview`/`declassify_apply` 配套，接入方式见 [W39](./W39-MCP工具面总览.md)。
